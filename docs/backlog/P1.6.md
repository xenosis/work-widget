# P1.6 — 트레이 재표시 시 대시보드 데이터 재조회

## 목적

대시보드가 최신 data.json을 항상 반영하도록 개선한다. 현재는 컴포넌트가 mount할 때 1회만 loadData()를 호출하는데, 창이 숨겨졌다가 다시 표시될 때(트레이에서 복귀할 때) 그 사이 변경된 data.json을 반영하지 못하는 문제를 해결한다.

## 쉬운 설명

Dashboard.jsx는 처음 로드될 때만 window.api.loadData()를 호출한다. 하지만 Electron의 X 버튼은 창을 완전히 종료하지 않고 숨기기만 하므로, React 컴포넌트는 살아있는 상태로 유지된다. 따라서 창이 다시 표시되어도 최초 로드 데이터가 그대로 남아있어서 그 사이의 변경 사항(다른 화면에서 추가한 할일 등)을 못 본다. 이를 해결하려면 창이 다시 표시될 때 fresh 데이터를 다시 불러와야 한다.

## 필요한 입력

- P1.5(대시보드 IPC 연동): window.api.loadData() 구현 및 사용 패턴 이해
- electron/main.js의 BrowserWindow show 이벤트 또는 IPC 신호 (창 재표시 감지)
- work-widget-requirements.md의 B5.1(창 닫기=숨김)

## 결과물

대시보드 컴포넌트에 창 재표시 감지 및 재조회 로직 추가. electron/main.js에서 필요시 IPC 신호 전송 (창 show 이벤트 시 렌더러에 신호). Dashboard.jsx가 이 신호를 받으면 loadData() 재호출.

## 선행 작업

- P1.5: 대시보드 IPC 연동 (window.api.loadData 사용 확립)

## 수행 순서에서의 위치

P1(대시보드) 내에서 P1.5 이후의 보완 작업. 초기 기능(P1.1~P1.3)은 완료되었고, 이제는 staleness(오래된 데이터 유지) 문제를 해결하는 단계. P1.6 완료 후 다른 화면(프로젝트/할일전체/메모/일정)들도 같은 문제를 겪을 것으로 예상되므로, 향후 P2~P5 화면에서도 비슷한 패턴 적용 필요.

## done_when을 확인하는 방법

1. npm run dev로 실행
2. Dashboard에서 오늘 마감 할일 1개를 화면에서 확인
3. 다른 화면(예: 프로젝트)으로 이동해 새 할일 1개 추가
4. 다시 대시보드로 이동 또는 창 닫기(X) 후 트레이에서 아이콘 클릭으로 재표시
5. 새로 추가된 할일이 대시보드에 표시되는지 확인 (재조회가 성공하면 표시될 것)
6. lint 통과, 콘솔 에러 없음

## 확인 필요

- electron/main.js의 show 이벤트 또는 대체 신호 방식 (현재 BrowserWindow API로 가능한 정확한 이벤트 네임)
- IPC 신호 방식 (창 show 시 main process → renderer process로 신호 보내는 구체적 구현)
- 다른 화면(Todos, Memos 등)에서도 같은 문제 발생 예상 — 향후 공통 훅이나 로직 추출 필요 여부 검토
