# P10 — 화면 공통 IPC 로딩 훅 추출

## 목적

Dashboard.jsx와 Projects.jsx(그리고 향후 Todos, Memos)에서 반복되는 window.api.loadData() IPC 로딩 보일러플레이트를 공통 React 훅으로 추출해 중복을 제거하고 유지보수성을 개선한다.

## 쉬운 설명

Dashboard와 Projects 화면의 코드를 보면 상태 관리(apiAvailable/data/error) 및 useEffect 로직이 글자 단위로 같다. 이를 src/lib/useAppData.js라는 공통 훅으로 분리하면, 앞으로 Todos/Memos 등을 추가할 때 같은 코드를 3번, 4번 복제하지 않아도 된다.

## 필요한 입력

- P1.5(대시보드 IPC 연동): window.api.loadData() 구현 및 첫 번째 사용 사례
- P2.1(프로젝트 카드 UI): 두 번째 사용 사례 (복제된 로딩 로직)
- React hooks 패턴 이해 (custom hook 작성)

## 결과물

src/lib/useAppData.js 훅 신규 파일. Dashboard.jsx와 Projects.jsx를 이 훅을 사용하도록 리팩터링. 렌더링 JSX와 상태 로직 분리.

## 선행 작업

- P1.5: 대시보드 IPC 연동 (window.api.loadData 사용 확립)

## 수행 순서에서의 위치

P1.5 이후의 코드 품질 개선 작업. 기능 개발(P1~P8)이 진행되면서 중복이 쌓인 뒤에 이를 리팩터링하는 단계. P3(할일전체)과 P4(메모) 화면이 추가될 때 이 훅을 활용해 보일러플레이트 복제를 미리 방지 가능.

## done_when을 확인하는 방법

1. npm run lint 통과
2. npm test 통과 (기존 테스트 35개 전부)
3. npm run build 성공
4. npm run dev로 실행 후 대시보드 화면 렌더링 정상 (이전과 동일)
5. 사이드바에서 프로젝트 탭 클릭 후 프로젝트 목록 정상 렌더링 (이전과 동일)
6. 콘솔 에러 없음

## 확인 필요

- useAppData 훅이 showData 후 재조회(P4.2, P2.5 같은 저장 작업에서 필요한 reload)를 지원하지 않는 구조적 한계 — 지금은 읽기 전용이므로 향후 저장 경로 추가 시 훅 확장 필요
- 3분기 조기반환 JSX가 여전히 Dashboard/Projects 두 화면에서 각각 복제되는 점 — 이번엔 상태 로직만 추출, 렌더링 UI는 화면별로 유지 (향후 추가 리팩터링 기회)
