# P11 — backlog CLI에 필드 수정(set-field) 명령 도입 결정 및 구현

## 목적

backlog.json의 메타데이터 필드(title, summary, where, deps, doc, done_when 등)를 고칠 방법이 없어서, critical-reviewer가 발견한 stale 필드들이 영구히 방치되는 문제를 해결하기 위함. set-status로는 상태 전이만 가능하고 메타데이터는 고칠 수 없으므로, 이를 전담하는 set-field 명령을 추가해 감사 이력을 남기면서 필드를 수정할 수 있게 한다.

## 쉬운 설명

지금까지는 backlog CLI(scripts/backlog/cli.js)에 task를 추가하거나(add), 상태를 바꾸거나(set-status), 순서를 정렬(reorder)할 수만 있었습니다. 하지만 task의 제목(title), 설명(summary), 의존성(deps), 문서 경로(doc) 같은 메타데이터는 고칠 방법이 없었습니다.

그래서 여러 리뷰를 거치면서 critical-reviewer가 "이 필드가 틀렸어요"라고 지적해도(예: P0.6의 summary가 이미 해결된 상황을 현재형으로 계속 서술, P1.1의 deps가 의미상 누락), 임시로 set-status의 --note에 기록만 하고 실제로는 손으로 backlog.json을 수정하거나 영구히 방치할 수밖에 없었습니다.

P11에서는 사람의 결정(2026-09-25: "도입한다")에 따라 `set-field` 명령을 구현했습니다:
- 누구든지 어떤 필드든(status, id, log 제외) 고칠 수 있도록
- 무엇을 왜 고쳤는지(--note)를 의무적으로 남기도록  
- 변경 전후 값(field_edit.before/after)을 task의 log에 기록하도록

합니다.

## 필요한 입력

- backlog CLI 기존 인프라(cli.js, store.js, mutations.js, schema.js) — 이미 존재
- 새로운 모듈 `scripts/backlog/lib/fieldMutations.js` — 이 task에서 작성
- 테스트 파일 `scripts/backlog/lib/fieldMutations.test.js`, `scripts/backlog/lib/schema.test.js` — 기존 또는 신규로 작성
- backlog.json의 현재 상태(valid한 task들의 배열)

## 결과물

다음 파일들이 수정되거나 신규 생성됨:

1. **scripts/backlog/lib/fieldMutations.js** (신규)
   - `setField(filePath, expectedVersion, id, updates, opts)` 함수
   - 11개 필드(title, summary, where, doc, done_when, est_min, gate, priority, category, parent, deps)에 대한 수정 기능
   - 입력값 검증(string 확인, empty 체크, enum 검증, parent 순환 검사, deps 존재성)
   - field_edit 이력 기록(before/after)
   - parent 변경 시 배열 내 위치 자동 이동

2. **scripts/backlog/cli.js** (수정)
   - `set-field <id> --<field>=<value> ... --note=<근거>` 명령 추가(line 168-183)
   - 허용 필드 목록 및 --help 문서화

3. **scripts/backlog/lib/schema.js** (수정)
   - `findParentCycle(tasks)` 함수 추가 — parent 체인의 순환을 감지(deps 순환과는 별개)

4. **테스트 파일들** (신규/확장)
   - `scripts/backlog/lib/fieldMutations.test.js` — setField의 정상/오류 케이스
   - `scripts/backlog/lib/schema.test.js` — findParentCycle 테스트 추가

5. **인프라 문서** (수정)
   - `.claude/rules/backlog-workflow.md` §1(백로그 변경 주체)과 §8(규칙 유형 분류) 갱신 — set-field 명령을 메인 세션의 책임으로 명시

## 선행 작업

없음 (deps: [])

이 task는 결정(set-field를 도입할지 여부)과 그 구현을 모두 포함하므로, 앞선 기능적 작업이 필요하지 않습니다.

## 수행 순서에서의 위치

P11은 backlog 인프라 개선의 일부입니다. Phase 1~10의 개발 과정에서 여러 task의 메타데이터가 실제와 어긋난 것이 반복 지적되자, 사람이 도입 결정을 했고 구현을 완료했습니다.

이제 이 명령이 완료되면:
- P11.1(set-field로 누적된 stale 필드 정정 적용)이 blocking되지 않아 바로 진행 가능해집니다
- 향후 backlog 메타데이터를 다시 수정해야 할 때도 set-field를 사용할 수 있게 됩니다

## done_when을 확인하는 방법

done_when: "사람 결정(2026-09-25, 도입한다)에 따라 scripts/backlog/lib/fieldMutations.js의 setField + cli.js의 set-field 명령이 구현되고, eslint/npm test(scripts/backlog/lib/fieldMutations.test.js·schema.test.js 포함)/npm run build를 통과하며, critical-reviewer가 지적한 Critical 1건/High 4건/Medium 5건이 모두 반영됨."

**P11은 done 상태입니다. 확인 방법:**

1. **명령 존재 확인**
   ```bash
   node scripts/backlog/cli.js set-field --help
   ```
   → 허용 필드 목록(title, summary, where, doc, done_when, est_min, gate, priority, category, parent, deps)과 사용법이 출력

2. **코드 확인**
   - `scripts/backlog/cli.js` line 168-183: set-field 명령 구현
   - `scripts/backlog/lib/fieldMutations.js`: setField 함수 및 검증 로직
   - `scripts/backlog/lib/schema.js`: findParentCycle 함수 추가

3. **테스트 통과 확인**
   ```bash
   npm test
   ```
   → `scripts/backlog/lib/fieldMutations.test.js`와 `scripts/backlog/lib/schema.test.js`의 테스트가 모두 통과

4. **Lint 통과 확인**
   ```bash
   npm run lint
   ```
   → eslint 300줄 제한(fieldMutations.js는 mutations.js에서 분리된 이유) 포함 모든 규칙 통과

5. **Build 통과 확인**
   ```bash
   npm run build
   ```
   → vite build 성공, exit code 0

6. **Critical-reviewer 지적 반영 확인**
   - backlog.json의 P11 로그를 확인하면 다음 지적들이 모두 반영됨:
     - **Critical 1건**: parent 순환 검사 — fieldMutations.js의 assertNoParentCycle 및 schema.js의 findParentCycle 구현
     - **High 4건**:
       1. --field만 넘기는 boolean 값 처리 — assertFieldValueType으로 typeof 검증
       2. est_min의 Number(NaN) 또는 음수 허용 — !Number.isFinite(n) || n < 0으로 거부
       3. --note 누락 시 검증 — typeof opts.note !== 'string' || !opts.note.trim()으로 거부
       4. where/doc/gate/parent 필드의 빈값/리터럴 null 처리 — "null" 문자열도 null로 변환
     - **Medium 5건**:
       1. deps 중복 제거 — new Set(arr)으로 정제
       2. parent만 변경 시 배열 위치 자동 이동 — findInsertionIndex로 새 부모의 형제 옆으로 재배치
       3. title/summary/done_when 절대 빈값 금지 — String.trim() 길이 체크
       4. priority/category enum 검증 — json.enums에서 확인
       5. est_min 빈값 처리 — rawValue === '' → null 변환

7. **실제 사용 검증**(수동, 이미 진행됨)
   - scratch 사본 backlog.json에서 다음을 확인:
     - --note 없이 실행하면 거부
     - 존재하지 않는 deps를 지정하면 거부  
     - parent를 자신의 자식으로 지정하면 순환 오류 발생
     - 정상 반영되면 field_edit 이력(before/after)이 log에 기록
