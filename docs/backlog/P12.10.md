# P12.10 — 일정별 색상(분류) 필드 도입 여부 결정

## 목적

달력의 일정들을 색상으로 분류/구분할 수 있도록, Schedule 데이터 스키마에 색상 또는 분류 필드를 도입할지를 결정한다. 현재는 스키마에 이 필드가 없어, 내용 기반으로만 구분이 가능한 상태이다.

## 쉬운 설명

달력에 여러 일정이 있을 때 (예: 회의, 보고서, 업무시간) 각각을 다른 색으로 표시해서 한눈에 구분하고 싶을 수 있습니다. 이를 위해서는:
- 데이터 스키마에 색/분류 필드를 추가
- 그 필드를 입력하는 UI 추가
- 달력에서 색상을 표시하는 로직 추가

가 필요합니다. 도입하지 않으면 현재대로 색상 구분이 없습니다.

**결정 결과 (2026-09-25)**: 일정에 색상/분류(카테고리) 필드를 도입하기로 결정했습니다. 사용자가 'routine-planner'(참고 앱, 별도 설정창에서 색상/분류 필드를 관리)를 본떠, 이름+색상을 가진 재사용 가능한 카테고리 엔티티를 만들고, 별도 관리 화면(또는 설정 영역)에서 추가/수정/삭제하는 방식으로 진행하기로 했습니다. (단순 자유색 선택이 아니라 고정 팔레트 방식)

구현은 두 개의 별도 task로 분리:
- **P12.16**: 데이터 모델(data.json의 schedule_categories 배열) + 관리 화면
- **P12.17**: 일정 폼(추가/수정)에서 카테고리 선택 + 달력에 카테고리 색 반영

## 필요한 입력

- data.json 스키마 변경 (schedule_categories 배열 추가)
- 고정 팔레트의 색상 목록 (예: 빨강, 주황, 노랑, 초록 등 — P12.1 다크 글래스 팔레트와 조화)
- 카테고리 관리 화면을 어디에 배치할지 (예: 사이드바에 '설정' 메뉴 추가, 또는 기존 화면 내 진입점)

## 결과물

- `work-widget-requirements.md`의 **B3.4** 절에 Schedule 스키마 변경 기록 (새로운 schedule_categories 배열 및 각 schedule의 category_id 필드 추가)
- P12.16 task: 데이터 모델 정규화 + 관리 화면 구현 계획 문서
- P12.17 task: 일정 폼 및 달력 색상 적용 구현 계획 문서
