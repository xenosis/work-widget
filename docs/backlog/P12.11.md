# P12.11 — 편집 폼 저장/취소 버튼 스타일 통일

## 목적

세 개의 편집 폼(프로젝트/할일/일정)에서 저장 버튼과 취소 버튼이 시각적으로 같은 크기와 모양을 가져야 주 액션과 보조 액션으로서의 버튼 쌍으로 인식된다. 현재 취소 버튼이 다른 용도(상세 화면의 뒤로가기)용 스타일을 재사용 중이라 저장 버튼과 매칭되지 않으므로, 저장 버튼과 같은 박스 모델을 가진 새로운 취소 버튼 클래스를 만들고 적용한다.

## 쉬운 설명

세 개의 편집 폼을 열면 맨 아래에 "저장"과 "취소" 버튼이 나란히 있는데, 지금까지 취소 버튼이 상세 화면의 "뒤로가기" 버튼 스타일(텍스트 링크처럼 보이는 작은 텍스트)을 재사용 중이라 저장 버튼(둥근 모양의 크고 진한 pill 버튼)과 전혀 다르게 보였습니다. 이번 작업은 취소 버튼도 저장 버튼과 같은 크기와 모양(패딩, 둥근 모서리, 테두리)을 가지도록 통일하되, 색만 주요 액션(accent 파랑)과 보조 액션(muted 회색)으로 구분하도록 했습니다.

구현 중에 흥미로운 발견이 있었습니다. 처음 작업 설명은 ".back-button은 뒤로가기 용도에만 남는다"고 했지만, 실제로는 삭제 2단계 확인의 취소 버튼에서도 쓰이고 있었던 것입니다(ProjectEditForm, TodoEditForm, ScheduleEditForm, Memos.jsx에서). 

그런데 그 삭제 확인 버튼 쌍을 살펴보니 더 가벼운 텍스트링크 스타일이었습니다 — 폰트 크기도 더 작고(11.5px, 11px 등), 패딩도 없었습니다. 이들을 새 12.5px pill 버튼으로 바꾸면 시각적 균형이 깨집니다. 따라서 이 작업의 범위를 "편집폼의 저장·취소 쌍"으로 좁혔고, 삭제 확인 취소는 기존 `.back-button` 패턴 그대로 두었습니다. 그 대신 발견된 삭제 버튼들의 폰트 불일치는 별도 작업(P12.18)으로 분리했습니다.

또한 구현 중 critical-reviewer의 지적으로 `:hover` 상태에 `:disabled` 가드가 없어서 저장 중에도 마우스 효과가 보이는 문제를 발견해 수정했습니다 (`:hover:not(:disabled)` 선택자 추가).

## 필요한 입력

- `src/index.css`: 기존의 `.project-edit-save` 클래스 (저장 버튼 스타일, 높이 35px, 패딩 8px 12px, font-size 12.5px, border-radius 4px)
- `src/components/ProjectEditForm.jsx`, `src/components/TodoEditForm.jsx`, `src/components/ScheduleEditForm.jsx`: 각 폼의 구조
- 색상 토큰: `--accent`, `--accent-soft-bg` (저장 버튼), `--muted` 계열 색상 (취소 버튼)

## 결과물

1. **CSS**: `src/index.css`에 새 클래스 `.project-edit-cancel` 추가 (347~377줄)
   - `.project-edit-save`와 동일한 박스 모델 (높이 35px, 패딩 8px 12px, font-size 12.5px, border-radius 4px)
   - 배경: 투명
   - 테두리: `--muted` 색 (oklch 40% 0.02 260)
   - 글자색: `--text-muted` (oklch 70% 0.01 260)
   - `:hover:not(:disabled)`: 배경과 글자색 변경 (저장 중엔 효과 없음)
   - `:focus-visible`: outline 2px solid var(--accent)
   - `:disabled`: opacity 0.6

2. **컴포넌트**: 세 편집 폼에서 취소 버튼의 `className`을 `.back-button`에서 `.project-edit-cancel`로 변경
   - `ProjectEditForm.jsx` 91행
   - `TodoEditForm.jsx` 150행
   - `ScheduleEditForm.jsx` 119행

3. **범위 명확화**: 같은 파일의 삭제 2단계 확인 대화창 취소 버튼은 의도적으로 `.back-button`으로 유지 (텍스트링크 스타일, 시각적 스케일 다름)

## done_when을 확인하는 방법

1. 세 편집 폼(프로젝트/할일/일정)을 각각 열어서 저장·취소 버튼 쌍을 확인합니다.
2. Playwright 또는 브라우저 개발자 도구로 실측하거나 스크린샷을 촬영:
   - **높이**: 35px (모두 동일)
   - **너비**: 약 51px (모두 동일)
   - **패딩**: 8px 12px (모두 동일)
   - **border-radius**: 4px (모두 동일)
   - **폰트 크기**: 12.5px (모두 동일)
3. 색상 확인:
   - 저장 버튼: accent 파랑 배경 (oklch 75% 0.15 200)
   - 취소 버튼: 투명 배경 + muted 테두리/글자 (oklch 40% 0.02 260)
4. 취소 버튼의 상태별 동작 확인:
   - `:hover` 상태: 마우스를 올렸을 때 배경/글자색 변경
   - `:disabled` 상태: 저장 중이면 hover 반응 없음 (`:not(:disabled)` 가드 작동)
   - `:focus-visible`: Tab으로 포커스 시 outline 표시
5. `.back-button`이 편집 폼 취소 버튼에서 완전히 제거됨을 확인:
   - 편집 폼 취소: 모두 `.project-edit-cancel`
   - 삭제 2단계 확인 취소: 여전히 `.back-button` (범위 밖)
   - 프로젝트 상세의 뒤로가기: 여전히 `.back-button`
6. `npm run lint` 통과 (eslint 오류 0)
7. `npm run build` 통과 (vite 빌드 성공)
