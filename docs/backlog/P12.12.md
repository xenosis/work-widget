# P12.12 — 프로젝트 상세 할일 카드 안내 문구 간격 보정

## 목적

프로젝트 상세 화면에서 요약 편집 모드일 때 나타나는 안내 문구("요약 수정을 마치거나 취소한 뒤 할일을 추가할 수 있습니다")와 할일 목록 사이의 간격이, 비편집 모드의 입력창과 목록 사이의 간격과 일치하도록 조정합니다. 두 모드 간의 시각적 통일감을 확보합니다.

## 쉬운 설명

프로젝트 상세 화면(ProjectDetail)은 요약 편집 여부에 따라 두 가지 상태가 있습니다:

**비편집 모드 (일반 상태)**:
- 요약 텍스트 + 수정 버튼 표시
- 그 아래 할일 추가 입력창(`.todo-add-form`, margin-bottom: 10px)
- 그 아래 할일 목록

**편집 모드**:
- 요약 편집 폼 표시 (수정 저장/취소 버튼)
- 그 아래 안내 문구(`.empty-text`, margin: 0): "요약 수정을 마치거나 취소한 뒤 할일을 추가할 수 있습니다"
- 그 아래 할일 목록

현재 문제: 편집 모드의 안내 문구는 `margin: 0`이므로 목록이 문구에 붙어있고, 비편집 모드의 입력창은 `margin-bottom: 10px`이므로 목록과 10px의 간격이 있습니다. 두 모드 간에 시각적 일관성이 없습니다.

이 작업은:
1. `.empty-text` 전체를 수정하지 않음 (다른 화면에 영향) 
2. ProjectDetail에서만 안내 문구에 전용 클래스를 추가
3. 그 클래스에 입력창과 같은 `margin-bottom: 10px` 지정

## 필요한 입력

- `src/components/ProjectDetail.jsx` — 146줄의 안내 문구 렌더링 부분
- `src/index.css` — `.todo-add-form`의 margin 값(10px) 확인
- P12.5(할일 추가 폼 마감일 입력) — 비교 기준이 되는 AddTodoForm의 최종 레이아웃

## 결과물

1. **ProjectDetail.jsx**:
   - 146줄의 안내 문구 className을 `"empty-text"` → `"empty-text project-summary-empty-text"`으로 변경

2. **src/index.css**:
   - 새로운 규칙 추가: `.project-summary-empty-text { margin-bottom: 10px; }`

## 선행 작업

**P12.5** (할일 추가 폼 마감일 입력) — 필수 선행 작업

이유: P12.12는 ProjectDetail의 AddTodoForm(비편집 모드)과 안내 문구(편집 모드) 사이의 간격을 비교해야 하는데, P12.5가 AddTodoForm의 레이아웃을 변경합니다. P12.5가 먼저 완료되어야 최종 레이아웃이 확정되고, 그것을 비교 기준으로 삼아 P12.12를 정확하게 수행할 수 있습니다. 만약 P12.5가 먼저 진행되지 않으면 비교 대상이 변경되면서 P12.12의 작업 기준이 흔들릴 수 있습니다.

## 수행 순서에서의 위치

**P12 (UI/UX 보정 및 기능 개선) 내에서 후기 단계 작업**입니다.

- **P12.5** (완료): 할일 추가 폼 마감일 입력 추가, AddTodoForm 최종 레이아웃 확정 → P12.12의 비교 기준 제공
- **P12.12** (대기 중 → 이제 진행 가능): P12.5 완료로 인해 비교 기준이 확정되었으므로 즉시 진행 가능
- **P12.11** (편집 폼 저장/취소 버튼 스타일 통일): 병렬 진행 가능

P12.12가 완료되면 ProjectDetail의 두 모드 간 시각적 일관성이 확보되고, 나머지 스타일 통일 작업(P12.11, P12.13 등)이 더 매끄럽게 진행됩니다.

## done_when을 확인하는 방법

1. **시각적 비교 (편집 모드)**:
   - 프로젝트 상세 화면 열기 → 요약 수정 버튼 클릭
   - 안내 문구("요약 수정을 마치거나 취소한 뒤 할일을 추가할 수 있습니다")와 할일 목록(또는 "할일이 없습니다" 안내 문구) 사이의 간격 확인
   - 스크린샷 캡처 (편집 모드)

2. **시각적 비교 (비편집 모드)**:
   - 요약 수정 취소 또는 저장해 비편집 모드 복귀
   - 할일 입력창(AddTodoForm)과 할일 목록 사이의 간격 확인
   - 스크린샷 캡처 (비편집 모드)
   - 두 스크린샷의 간격이 시각적으로 일치하는지 비교 — 편집 모드의 간격이 비편집 모드의 간격과 동일해야 함

3. **코드 검증**:
   - `src/components/ProjectDetail.jsx` 146줄 확인: `className="empty-text project-summary-empty-text"`으로 클래스 적용
   - `src/index.css`에서 `.project-summary-empty-text { margin-bottom: 10px; }` 정의 확인
   - `.todo-add-form { margin-bottom: 10px; }` 기존 규칙과 동일한 값 사용

4. **다른 화면의 영향 확인**:
   - 할일 전체 화면: "먼저 프로젝트를 만들어야 합니다" 안내 문구 표시 → 간격 변화 없음
   - 메모 화면: `.empty-text` 사용 여부 확인 → 변화 없음
   - 다른 화면에서도 `.empty-text`의 기본 스타일(`margin: 0`)은 유지

5. **린트/빌드 통과**:
   - `npm run lint`: exit code 0 (eslint 규칙 포함)
   - `npm run build`: exit code 0 (vite 빌드 성공)

## 확인 필요

1. **간격 값 확정**: `.todo-add-form`의 margin-bottom이 정확히 10px인지 code 검증 완료 — 실제로 10px임을 확인했으므로 스냅샷 기준으로는 확정값입니다.

2. **전용 클래스명**: 제안된 `.project-summary-empty-text`가 명명 규칙상 적절한지 확인 (ProjectDetail 컴포넌트 내에서만 사용되므로 접두어 추가 고려 — 요구사항 문서에 명시되지 않았으므로 구현 시점에 코드 리뷰로 확정)

대부분의 기술적 결정사항이 이미 반영되었으므로 추가 확인 필요 항목이 최소화되었습니다.
