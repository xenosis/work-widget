# P12.14 — 드롭다운 목록·날짜 선택 팝업 커스텀 컴포넌트 교체 여부 결정

## 목적

HTML의 네이티브 `<select>` 드롭다운과 `<input type="date">` 날짜 선택기를 다크 글래스 테마에 맞춰 렌더링할 수 없는 문제를 해결하기 위해, 커스텀 컴포넌트로 교체할지 또는 네이티브 상태로 유지할지 결정한다. 네이티브 팝업의 스타일링은 Chromium/OS 수준에서 차단되어 CSS로 제어할 수 없다.

## 쉬운 설명

앱의 드롭다운(예: 카테고리 선택) 및 날짜 선택기가 펼쳐졌을 때 OS 기본 모양(Windows 흰색 팝업)이 보여서 다크 테마와 어울리지 않습니다. 이를 해결하는 방법:
- **(1)** 네이티브 유지 (P12.13으로 CSS만 하고 종료) — 팝업은 여전히 밝음
- **(2)** 자체 구현 커스텀 컴포넌트 — 완전히 테마에 맞출 수 있지만 접근성과 유지보수 부담 증가
- **(3)** 외부 라이브러리 도입 (react-select 등) — P5.1의 무의존성 관행과 충돌

**결정 결과 (2026-09-25)**: 외부 라이브러리 없이 자체 구현으로 진행합니다. 기존 다크 글래스 테마(src/index.css의 oklch 커스텀 프로퍼티 토큰: `--bg`, `--sidebar-bg`, `--card-bg`, `--accent` 등, P9에서 확립된 순수 CSS 기반 디자인 시스템)과 동일한 토큰을 그대로 재사용해 커스텀 Select와 DatePicker를 만들기로 결정했습니다.

## 필요한 입력

- P12.6과 P12.8에서 정의된 주말/공휴일 색상 정보 (DatePicker에서 재사용)
- src/index.css의 oklch 커스텀 프로퍼티 토큰 목록 (색상 재사용용)
- 키보드 접근성 요구사항 (ARIA, 포커스 관리, Esc 키 닫기 등)
- 기존 입력 11곳의 목록 (어디까지를 커스텀 Select/DatePicker로 교체할지)

## 결과물

- 커스텀 Select 컴포넌트 (리스트박스 역할, 다크 글래스 스타일)
- 커스텀 DatePicker 컴포넌트 (월간 달력 그리드, 주말/공휴일 색 포함)
- src/components/에 두 컴포넌트 추가
- 기존 select/date 입력 11곳을 새 컴포넌트로 교체
- CSS: 팝업 스타일 (다크 글래스 색상 토큰 재사용)

## 선행 작업

- **P12.6** — 주말 색상 적용 (DatePicker에서 주말 색을 재사용하므로 필요)

- **P12.13** — 네이티브 입력의 CSS 스타일링 (선택된 값 텍스트 색 등 미세 조정)

**주의**: P12.13은 "네이티브 입력" 자체의 스타일인 반면, P12.14/P12.15는 팝업 열림 상태의 스타일입니다.
