# P12.15 — 일정 화면 날짜 입력 2곳 DueDatePicker로 교체(기존 P12.19 컴포넌트 재사용)

## 목적

일정 추가/수정 폼의 네이티브 날짜 입력 필드 2곳을 P12.19에서 만든 커스텀 `DueDatePicker` 컴포넌트로 교체해, 프로젝트/할일 화면과 동일한 다크 글래스 테마와 주말·공휴일 색깔을 보여주는 작업이다. 이를 통해 앱 전체의 날짜 선택 인터페이스를 일관되게 통일한다.

## 쉬운 설명

일정 화면에서 "언제 할일인가"를 고르는 입력 필드가 있다. 지금까지는 OS 기본 날짜 팝업(CSS로 꾸밀 수 없음)을 썼는데, 같은 앱의 프로젝트/할일 화면 마감일 입력은 이미 이쁜 다크 테마 달력(P12.19의 `DueDatePicker`)으로 바뀌었다. 이 작업은 일정 화면도 같은 달력으로 통일하는 것이다.

**왜 간단한가:**

- P12.13에서 "다양한 옵션을 가진 select는 네이티브 유지"라고 결정했다.
- P12.19에서 이미 DueDatePicker를 만들고, "일정 화면 날짜는 나중에"라고 명시했다.
- 원래 "모든 입력을 새 컴포넌트로 바꾼다"는 범위는 일정 화면의 날짜 2곳만 남게 됐다.

따라서 **새 컴포넌트를 만드는 것이 아니라, 이미 있는 DueDatePicker를 가져다 쓰고 약간의 props만 추가하면 된다.**

## 필요한 입력

- **P12.19의 DueDatePicker 컴포넌트**: 프로젝트/할일 마감일 5곳에서 검증된 컴포넌트. 달력 그리드, 주말·공휴일 색, 다크 글래스 스타일, Tab 기반 키보드 네비게이션을 포함.
- **P12.6의 scheduleGrid.js**: `getMonthGrid()` 로직 (DueDatePicker가 재사용).
- **기존 ScheduleAddForm.jsx, ScheduleEditForm.jsx**: 날짜 선택/제출 로직이 이미 있으므로 UI만 교체.
- **dateRange.js의 `isValidDateString()`**: 손상된 날짜 데이터 방어 (ScheduleEditForm 초기값 검증용).
- **src/index.css의 다크 글래스 토큰**: oklch 기반 커스텀 프로퍼티(--bg, --card-bg, --accent 등) — P9에서 확립.

## 결과물

1. **DueDatePicker.jsx에 새 props 추가**:
   - `popoverAlign`: 팝오버 펼침 방향 ('right'=기본값 프로젝트/할일 폼, 'left'=사이드바를 가리지 않도록 일정 폼용 반대 방향)
   - `clearable`: 지우기 버튼 표시 여부 (기본값 true, 일정 폼은 false로 필수 입력 표시)

2. **ScheduleAddForm.jsx, ScheduleEditForm.jsx**: 
   - 네이티브 `<input type="date">` 2곳을 `<DueDatePicker>` 컴포넌트로 교체
   - 일정 폼은 `clearable={false}`, `popoverAlign="left"` 설정 (필수 입력, 사이드바 미침범)
   - onChange 시그니처 정규화 (네이티브 이벤트 객체 대신 문자열 값을 직접 받음)

3. **ScheduleEditForm.jsx의 date 초기화**:
   - `isValidDateString()`으로 schedule.date 초기값 정규화 (ProjectEditForm/TodoEditForm과 동일 패턴)

4. **src/index.css**:
   - `.due-date-popover--left` 규칙 추가 (팝오버 좌측 배치)
   - 더 이상 쓰지 않는 `input[type=date]` 관련 규칙 정리 (hover/focus/disabled/calendar-picker-indicator)

5. **work-widget-requirements.md**:
   - B1.1에 P12.15 최종 결정 문단 추가 (일정 화면 날짜는 DueDatePicker 사용, 소속 프로젝트 select는 네이티브 유지)
