# P12.16 — 일정 카테고리(분류) 데이터 모델 + 관리 화면

## 목적

일정(Schedule) 데이터에 색상 기반 분류 기능을 추가하기 위한 기초 계층이다. P12.10에서 사람이 결정한 "고정 팔레트 색상 기반 카테고리" 설계를 구현하여, 사용자가 반복되는 일정(예: 업무, 회의, 휴식)을 이름과 색상으로 정의하고 이를 관리할 수 있게 한다. 이 작업은 데이터 모델과 관리 UI까지만 담당하며, 실제로 일정을 추가/수정할 때 카테고리를 고르는 UI와 달력에 색상을 반영하는 부분은 P12.17에서 별도로 처리한다.

## 쉬운 설명

**이 작업이 만드는 것:**

1. **새로운 데이터 구조** (`data.json`에 추가)
   - `schedule_categories` 배열: 각 카테고리는 고유 id, 이름, 색상(key) 세 가지를 가진다.
   - Schedule 엔티티에 `category_id` 필드 추가: 어느 카테고리에 속할지 나타낸다 (미지정도 허용).

2. **고정된 7가지 색상 팔레트**
   - 빨강, 주황, 노랑, 초록, 파랑, 보라, 회색
   - 사용자가 자유롭게 색을 정하는 게 아니라, 이 7가지 중에서만 선택한다.
   - 색은 실제 RGB값이 아니라 색깔 이름(key)만 저장되므로, 나중에 스타일을 바꿔도 기존 데이터는 자동으로 새 색을 받는다.

3. **카테고리 관리 화면** (일정 화면 안의 진입점)
   - 일정 화면 내 "카테고리 관리" 토글 버튼으로 접이식 패널을 열 수 있다.
   - **추가**: 이름 입력 + 7색 팔레트에서 색 선택 → 저장
   - **수정**: 각 카테고리의 이름과 색을 따로 고칠 수 있다 (인라인 편집).
   - **삭제**: 카테고리를 지울 때, 그 카테고리를 사용 중이던 일정들은 자동으로 "미분류"(category_id = null)로 돌아간다 (2단계 확인).

**⚠️ 이 작업이 하지 않는 것:**
- 일정 추가/수정 폼에서 카테고리 선택 드롭다운 또는 라디오 버튼 → P12.17에서 수행
- 달력 화면(월간/주간 뷰, 날짜 상세)에 카테고리 색상 표시 → P12.17에서 수행

이 작업 자체를 완료해도 아직 달력에서 색깔이 보이지 않을 것이다. P12.17에서 "일정을 추가할 때 카테고리 선택" UI와 "달력에 색상 반영" 기능이 추가될 때 비로소 전체가 완성된다.

## 결과물

### 데이터 모델 확장

**새 엔티티: ScheduleCategory**
- `id` (string): 고유 식별자 (category-{uuid} 형태)
- `name` (string): 카테고리 이름
- `color` (string): 고정 팔레트 7색 중 하나의 키 (red/orange/yellow/green/blue/purple/gray)
- `created_at` (datetime): 생성일
- `updated_at` (datetime): 수정일

**Schedule 엔티티 필드 추가**
- `category_id` (string, nullable): ScheduleCategory의 id 참조. null이면 미분류(분류되지 않음)

## done_when을 확인하는 방법

### 1. 카테고리 관리 화면 작동 (UI 상호작용)

일정 화면을 열고 "카테고리 관리" 토글을 클릭:
- 패널이 펼쳐져 추가 폼과 기존 카테고리 목록을 본다
- 이름을 입력하고 7색 팔레트에서 색을 선택한 뒤 저장한다
  - 새 카테고리가 목록에 나타난다
- 카테고리 행의 수정 버튼을 클릭해 이름을 바꾸고 저장한다
  - 변경사항이 즉시 반영된다

### 2. 카테고리 삭제 및 정합성 처리 (cascade)

**중요: 이것이 done_when의 핵심 항목**

- 카테고리를 삭제할 때, 그 카테고리를 사용 중이던 일정(schedules)들이 정합성 있게 처리되는지 확인:
  - 삭제 버튼 → 2단계 확인 대화 → 확인
  - `data.json`을 열어보면:
    - `schedule_categories` 배열에서 그 카테고리가 사라진다
    - 그 카테고리를 쓰던 일정들의 `category_id`가 `null`로 되돌아간다
  - 예: 카테고리 id = "category-abc", 일정 A가 category_id = "category-abc" → 카테고리 삭제 후 일정 A의 category_id = null
- 앱을 재시작해도 일정이 여전히 `category_id: null` 상태로 유지된다 (Playwright로 cascade cascade 확인함)

### 3. 데이터 저장/로드 확인 (파일 시스템)

- `npm run dev`로 앱을 실행하고 카테고리를 여러 개 추가한 뒤 닫는다
- `data.json`을 열어 확인:
  - `schedule_categories` 배열이 추가되어 있다
  - 각 레코드가 정확한 스키마로 저장되어 있다: `{ id, name, color, created_at, updated_at }`
  - color 값이 팔레트 key 중 하나다 (red/orange/yellow/green/blue/purple/gray)
- 앱을 다시 열고 카테고리 목록이 이전과 동일하게 로드되는지 확인한다

### 4. 기존 데이터 하위 호환성 (마이그레이션 안전성)

- `data.json`의 schedules 배열에서 일부 레코드의 category_id 필드를 의도적으로 제거한다
- 앱을 다시 시작 (`npm run dev`)하면:
  - electron/dataStore.js의 정규화가 자동으로 `category_id: null`을 채운다
  - 앱이 크래시하지 않는다
  - 일정이 "미분류"(category_id: null) 상태로 정상 표시된다
