# P12.16 — 일정 카테고리(분류) 데이터 모델 + 관리 화면

## 목적

P12.10 결정에 따라, 일정에 재사용 가능한 카테고리(이름+고정 팔레트 색상) 개념을 도입하고, 사용자가 이러한 카테고리를 추가/수정/삭제할 수 있는 별도 관리 화면을 구현한다.

## 쉬운 설명

달력의 일정들을 "회의", "보고서", "업무시간" 같은 카테고리로 분류하고 각각을 다른 색으로 표시하고 싶습니다. 이를 위해:
1. **데이터 모델**: data.json에 카테고리 목록(schedule_categories 배열)을 추가하고, 각 일정은 카테고리 ID를 참조
2. **관리 화면**: 사이드바나 설정 영역에서 카테고리를 추가(이름+색 선택), 수정(이름/색 변경), 삭제(기존 일정을 미분류로 처리)할 수 있는 UI

## 필요한 입력

- 고정 팔레트 색상 목록 (예: 빨강, 주황, 노랑, 초록, 파랑, 보라 — src/index.css 또는 P12.1에서 정의된 색상과 조화)
- 카테고리 ID 생성 방식 (UUID, 숫자 증분 등)
- 카테고리 관리 화면의 배치 위치:
  - 사이드바에 새 메뉴 추가 (예: '설정')
  - 기존 화면 내 진입점 (예: 일정 추가 폼에서 "카테고리 관리" 버튼)
  - 별도 팝업/모달

## 결과물

### 데이터 구조
- `data.json`에 새 배열 추가:
  ```
  schedule_categories: [
    { id: "cat_1", name: "회의", color: "oklch(60% 0.15 240)" },
    ...
  ]
  ```
- 각 schedule 항목에 선택사항 필드:
  - `category_id: "cat_1"` (또는 null/undefined = 미분류)

### 코드 변경
- `electron/dataStore.js`: 
  - 새 배열 초기화 로직 (기본값: 빈 배열 또는 샘플 카테고리 포함)
  - 정규화(P6.4 기본값 패턴) 적용
- `src/lib/scheduleStore.js` 또는 유사: 카테고리 CRUD 로직
- 단위 테스트: 정규화, 마이그레이션(기존 일정 데이터 유지) 확인

### UI 컴포넌트
- 카테고리 관리 화면/모달 (ScheduleCategoryManager.jsx 또는 SettingsPanel.jsx 등):
  - 카테고리 목록 표시
  - 카테고리 추가 입력 (이름 텍스트 필드 + 색상 팔레트 선택)
  - 각 항목에 수정/삭제 버튼
  - 삭제 시 경고 및 처리 로직 (기존 일정을 미분류로 되돌림)

### CSS
- 카테고리 색상 미리보기 UI
- 팔레트 색상 선택기 스타일 (다크 글래스 테마 일치)

## 선행 작업

- **P12.10** — 일정별 색상 필드 도입 여부 결정 (카테고리 방식, 고정 팔레트로 결정됨)

**참고**: P12.6, P12.8의 색상 정보를 재사용할 수 있으므로, 이들이 먼저 구현되면 도움이 됨. 하지만 필수는 아님 (색상 토큰은 src/index.css에서 직접 정의 가능).

**선행**: P12.10(카테고리 도입 결정)
**후속**: P12.17(일정 폼에서 카테고리 선택 + 달력에 색 반영) — P12.16이 먼저 완료되어야 P12.17이 카테고리를 참조할 수 있음

## done_when을 확인하는 방법

다음 절차로 확인합니다:

1. **카테고리 CRUD 동작 확인** (수동 또는 자동 테스트):
   - 카테고리 추가: 새 이름+색 입력 후 목록에 나타나는지, data.json에 저장되는지
   - 카테고리 수정: 이름/색 변경 후 즉시 반영되는지
   - 카테고리 삭제: 삭제 시 기존 일정들이 정합성 있게 처리되는지 (예: 미분류로 되돌림, null 또는 빈 문자열로 설정)

2. **데이터 저장/로드 확인**:
   - 앱 실행 후 카테고리 추가/수정/삭제 → 앱 재시작 후 변경사항 유지되는지
   - data.json 파일 확인: schedule_categories 배열이 정상 저장되는지

3. **마이그레이션/하위호환성 확인**:
   - 기존 데이터(카테고리 필드 없음)를 로드했을 때 에러 없이 작동하는지
   - 다른 필드(일정명, 시간 등)는 정상 로드되는지

4. **정규화 테스트**:
   - `npm test` 또는 `vitest run`으로 dataStore 정규화 테스트 통과
   - 기본값(빈 배열) 생성 및 로드 확인

5. **스크린샷**:
   - 카테고리 관리 화면이 보이고, 색상 팔레트 선택이 다크 글래스 테마와 일치하는지

6. **Lint/테스트/빌드 통과**:
   - `npm run lint` 통과
   - `npm test` 통과 (관련 테스트)
   - `npm run build` 통과

## 확인 필요

- **카테고리 관리 화면의 정확한 위치/UX**: 현재 "별도 관리 화면/영역"이라고만 명시되어 있는데, 실제로 사이드바 메뉴를 추가할지, 기존 설정 화면을 만들지, 모달 형태로 할지 구체적으로 결정 필요. 'routine-planner' 앱의 UI를 참고하면 더 구체적인 방향을 잡을 수 있음.
- **팔레트 색상 목록**: 고정 팔레트에 정확히 몇 개의 색상을 포함할지, 그 색상값이 무엇인지 (P12.1 다크 글래스 팔레트와 조화하는 색상 정의 필요).
- **삭제 시 처리 방식**: 카테고리를 삭제할 때, 그 카테고리를 사용 중인 일정들을 어떻게 처리할지 (예: null로 설정, 기본 카테고리로 돌림, 삭제 불가 안내 등).
