# P12.19 — 프로젝트/할일 마감일 선택에 주말·공휴일 색 반영(커스텀 날짜 선택기)

## 목적

프로젝트와 할일 항목의 마감일을 입력할 때 일정 화면(P12.6, P12.8)처럼 주말과 공휴일의 색 구분이 보이도록 하기. 이를 통해 사용자가 마감일을 설정할 때 주말을 피하거나 공휴일을 고려한 계획을 세울 수 있게 함.

## 쉬운 설명

프로젝트/할일을 추가하거나 수정할 때 마감일을 입력하는 부분이 있습니다. 원래는 `<input type="date">`(브라우저 기본 달력)를 사용했는데, Windows의 네이티브 달력 팝업은 브라우저가 OS에 일임해서 그려서 CSS로 색을 바꿀 수 없습니다(P12.13에서 select 선택박스도 같은 문제를 겪었습니다).

이 작업은 새로운 `DueDatePicker` 컴포넌트를 만들어서, 일정 화면(B2.4)에서 이미 만들어둔 월간 그리드 렌더링(scheduleGrid.js의 getMonthGrid/getWeekdayKind/getHolidayInfo 함수)과 CSS(토요일/일요일/공휴일 색 규칙)를 그대로 재사용합니다. 트리거 버튼을 누르면 팝오버로 월간 그리드가 나타나고, 날짜를 클릭하면 값이 입력되고 팝오버가 닫히는 방식입니다.

프로젝트/할일 관련 마감일 입력 5곳에 모두 적용됨:
1. 새 프로젝트 추가 폼 (Projects.jsx)
2. 프로젝트 수정 폼 (ProjectEditForm.jsx)
3. 프로젝트 상세 화면의 인라인 할일 추가 (ProjectDetail.jsx)
4. 할일전체 화면의 할일 추가 폼 (TodoAddForm.jsx)
5. 할일 수정 폼 (TodoEditForm.jsx)

일정 화면 자체의 날짜 입력(ScheduleAddForm/ScheduleEditForm)은 사용자 요청 범위 밖이라 그대로 둠.

## 필요한 입력

- 일정 화면의 기존 구현 — 월간 그리드 렌더링 함수(scheduleGrid.js: getMonthGrid/getWeekdayKind/getHolidayInfo)와 CSS 클래스 체계(.schedule-month-grid, .schedule-day-cell, .is-saturday, .is-sunday, .is-holiday, .is-outside, .is-today, .is-selected)가 이미 완성돼 있어야 함 (P12.6/P12.8 완료 필수)
- 마감일 입력 폼들의 기존 코드 — Projects.jsx, ProjectEditForm.jsx, ProjectDetail.jsx, TodoAddForm.jsx, TodoEditForm.jsx

## 결과물

- CSS 신규 규칙: `src/index.css`에 `.due-date-picker`, `.due-date-trigger`, `.due-date-popover`, `.due-date-placeholder`, `.due-date-clear` 클래스 추가

- 검증 함수 추출: `src/lib/dateRange.js`에 `isValidDateString(str)` 수출 — 형식 검사(YYYY-MM-DD) + 왕복 검증(존재하지 않는 날짜 필터링)

  - src/components/ProjectEditForm.jsx (프로젝트 수정 폼에 적용, 초기 state 정규화)
  - src/components/ProjectDetail.jsx (상세 화면 인라인 추가에 적용)
  - src/components/TodoAddForm.jsx (할일전체 추가 폼에 적용)
  - src/components/TodoEditForm.jsx (할일 수정 폼에 적용, DATE_STRING_RE 정의 통일)
- 테스트 추가: vitest 230개 통과(신규 3개: getDayCellClassNames 2개 + isValidDateString 1개)
- 불필요한 CSS 정리: `.todo-add-form .project-edit-row input[type=date]` 규칙 삭제(사용 중단)

## 수행 순서에서의 위치

P12(UI/스타일 개선) 안의 후반부 작업. P12.13(select/date 입력 테마 통일)에서 네이티브 date input의 플랫폼 제약을 확인한 뒤, 사용자 피드백으로 P12.19가 새로 생김. 

이 작업이 끝나면 프로젝트/할일 마감일 입력 UX가 P12로 완성됨. 모든 P12.1~P12.19 하위 작업이 done 또는 cancelled 상태가 되면 부모 P12도 완료됨.
