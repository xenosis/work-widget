# P12.20 — 프로젝트 삭제 확인 버튼 hover 반응 없음(할일/일정/메모와 비대칭)

## 목적

P12.18 재검증 과정(critical-reviewer 지적)에서 발견된 UI 일관성 문제를 해결한다. 프로젝트 삭제 확인 버튼(`.project-delete-button`)은 마우스 hover 시 시각적 피드백이 전혀 없어서, 같은 역할을 하는 할일/일정/메모 삭제 버튼(`.todo-delete-toggle`)과 상호작용 경험이 불일치한다. 이를 통일하여 네 화면의 삭제 버튼에서 일관된 hover 반응을 경험하도록 한다.

## 쉬운 설명

위젯에서 위험한 작업(삭제)을 하려면 보통 두 단계를 거친다:
1. "삭제" 버튼을 누르면 정말 할 건지 다시 묻는 확인 대화가 뜬다.
2. 최종적으로 "삭제 확인" 또는 "취소"를 선택한다.

**문제**: 프로젝트의 빨간 "삭제 확인" 버튼만 마우스를 올려도 아무 변화가 없다. 반면 할일, 일정, 메모의 같은 버튼들은 마우스를 올리면 밑줄이 생기거나 시각적 피드백을 준다.

**해결**: 프로젝트 버튼에도 마우스를 올렸을 때 텍스트에 밑줄이 생기도록 CSS 규칙을 추가해서 네 화면 모두 일관된 방식으로 반응하게 한다. 버튼의 빨간 색(danger)은 그대로 유지하고 밑줄만 추가한다.

## 필요한 입력

- P12.18(삭제 2단계 확인 취소 버튼 스타일 정리)이 완료돼 있는 상태. P12.20은 그 리뷰 재검증 과정에서 발견된 추가 개선사항이므로, P12.18의 변경 사항(`.delete-cancel-button` 클래스 분리, `:hover:not(:disabled)` 가드 패턴 확립)이 적용돼 있어야 한다.
- `src/index.css`에 현재 `.project-delete-button` 선언이 있고, 초기 상태에서 hover 규칙이 없는 상태여야 한다.
- 개발 환경에서 lint(`npm run lint`) 및 build(`npm run build`) 도구가 정상 작동해야 한다.

## 결과물

`src/index.css`의 `.project-delete-button` 선택자에 다음 CSS 규칙이 추가된다:

```css
.project-delete-button:hover:not(:disabled) {
  text-decoration: underline;
}
```

**변경 내용**:
- 사용자가 프로젝트 삭제 확인 버튼 위에 마우스를 올리면 텍스트에 밑줄이 생긴다.
- 버튼이 비활성화된 상태(`:disabled`)에서는 hover 피드백이 나타나지 않는다.
- 버튼의 danger 색상(oklch 0.75 0.17 25 — 빨강)은 변하지 않는다.
- 할일, 일정, 메모의 삭제 확인 버튼과 동일한 hover 시각적 피드백이 적용된다.

## 선행 작업

- **P12.18** — 삭제 2단계 확인 취소 버튼 스타일 정리(폰트 크기 불일치)

P12.18이 먼저 완료돼야 하는 이유: P12.20은 P12.18 리뷰 재검증 중에 발견된 별도 문제다. P12.18에서 `.delete-cancel-button` 클래스를 분리하고 `:hover:not(:disabled)` 가드 패턴을 정립했으므로, P12.20은 그 동일한 패턴을 프로젝트의 "삭제 확인" 버튼에도 적용하는 작업이다.

## 수행 순서에서의 위치

P12 배치 내에서 P12.18의 리뷰 과정에서 분리된 후속 개선 작업이다.

- P12.18이 삭제 버튼 쌍의 크기 통일과 취소 버튼의 `:hover:not(:disabled)` 가드를 수정했다면,
- P12.20은 확인 버튼(프로젝트만) 쪽에도 동일한 hover 가드 패턴을 보완하는 작업이다.

이 작업이 완료되면 프로젝트/할일/일정/메모 4곳의 삭제 확인 버튼들이 모두 동일하게:
- hover 시 밑줄로 시각적 피드백을 제공한다.
- disabled 상태에서는 hover 반응이 없다.
- 모든 버튼이 danger 색 위계를 유지한다.

## done_when을 확인하는 방법

### 1. 코드 검증
`src/index.css`에서 `.project-delete-button` 규칙을 찾고 다음을 확인한다:

```css
.project-delete-button:hover:not(:disabled) {
  text-decoration: underline;
}
```

- `:hover:not(:disabled)` 선택자가 추가되어 있는가?
- `text-decoration: underline;` 규칙이 있는가?
- danger 색(`color: var(--danger)`)은 원래대로 유지되고 있는가?

### 2. 실제 동작 확인 (수동 테스트)
- `npm run dev`로 앱을 띄운다.
- 프로젝트 카드를 하나 선택해 상세 화면을 열고 "삭제" 버튼을 누른다.
- 삭제 2단계 확인 대화가 나타나고, 빨간 "삭제 확인" 버튼이 보인다.
- 마우스를 그 버튼 위에 올린다 → 텍스트에 **밑줄이 생기는지 확인**한다. 색은 변하지 않는다.
- 마우스를 치운다 → 밑줄이 사라진다.

### 3. 비교 검증 (네 화면의 hover 동등성)
같은 방식으로 다음 화면의 삭제 확인 버튼들을 확인한다:
- 프로젝트 상세 화면 (`.project-delete-button`)
- 할일 편집 폼 (`.todo-delete-toggle`)
- 일정 편집 폼 (`.todo-delete-toggle`)
- 메모 화면 (`.todo-delete-toggle`)

네 곳 모두 hover 시 **밑줄이 생기고**, disabled 상태에서는 hover 반응이 없으며, **danger 색이 일관되게 유지**되는지 확인한다.

### 4. Lint 및 빌드 검증
```bash
npm run lint    # 0 errors 확인
npm run build   # 성공 확인(exit code 0)
```

### 5. 테스트 통과 확인
```bash
npm test
```
vitest가 통과하는지 확인한다. 이 작업은 CSS 추가만 하므로 기존 테스트 수(240개)와 동일해야 한다.

### 6. 스크린샷 또는 실측 기록
Playwright를 통한 실측: hover 전 `text-decoration: none` → hover 후 `text-decoration: underline`, `color`는 danger 불변 확인.
