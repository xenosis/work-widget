# P12.3 — 타이틀바/창 컨트롤 다크 글래스 테마 구현

## 목적

Electron의 기본 네이티브 타이틀바(최소화/최대화/닫기 버튼)는 OS가 그리기 때문에, 앱의 다크 글래스 테마(CSS의 `--sidebar-bg` 톤) 색깔이 적용되지 않는다. P12.2에서 결정한 "frame:false 완전 커스텀" 방식을 구현해 타이틀바와 4개 버튼(최소화/최대화/닫기/상태 조회)을 직접 렌더러에서 만들고, 클릭 시 IPC로 메인 프로세스의 실제 창 제어 기능을 호출하도록 연결한다. 이를 통해 앱 전체의 시각적 일관성을 확보하면서도 Windows 창 관리 기능은 그대로 유지할 수 있다.

## 쉬운 설명

Electron 앱은 보통 Windows가 자동으로 파란색 타이틀바를 제공합니다. 하지만 이 위젯의 웹 화면은 어두운 회색 테마를 쓰고 있어서, 아래는 어두워도 위의 타이틀바만 밝게 떠있는 어색한 상황이었습니다.

이 작업에서는 다음을 구현했습니다:

1. **창 틀을 없앤다** — electron/main.js에서 `frame:false`를 설정하면 Windows 기본 타이틀바가 나타나지 않습니다.

2. **어두운 타이틀바를 직접 만든다** — React 컴포넌트 TitleBar.jsx를 만들어 36px 높이의 영역에 어두운 배경, 앱 이름("업무 위젯"), 최소화/최대화/닫기 버튼을 그립니다.

3. **버튼을 창 제어와 연결한다** — 버튼을 클릭하면 IPC(프로세스 간 통신)를 통해 메인 프로세스에 "최소화해줘", "최대화해줘", "닫아줘" 같은 명령을 보냅니다. 메인 프로세스의 Electron API는 실제 창 제어를 처리합니다.

4. **상태를 렌더러와 동기화한다** — 메인 프로세스에서 창이 최대화/복원되면 렌더러에 알려줘서, 최대화 버튼의 아이콘이 "복원(작아지는 화살표)" 모양으로 실시간 바뀝니다.

## done_when을 확인하는 방법

1. **시각적 일치 확인**
   - `npm run dev`로 실행 후 타이틀바와 버튼의 배경색이 사이드바와 같은 어두운 톤(--sidebar-bg)인지 스크린샷 촬영해 육안 확인

2. **창 이동 확인 (수동, Playwright 불가능)**
   - 타이틀바 영역을 마우스로 실제 드래그해서 창이 화면 내에서 이동되는지 확인
   - Playwright(Chromium DevTools Protocol)은 OS 레벨의 실제 마우스 드래그를 시뮬레이션할 수 없으므로 사람이 직접 해야 함

3. **최소화 버튼**
   - 최소화 버튼 클릭 후 창이 작업 표시줄로 내려가는지 확인
   - Playwright로 `mainWindow.isMinimized() === true` 상태 검증

4. **최대화/복원 버튼**
   - 최대화 버튼 클릭 후 창이 화면을 채우고 아이콘이 "복원" 모양으로 전환되는지 확인
   - Playwright로 `mainWindow.isMaximized() === true` 상태 검증 및 아이콘 전환 확인
   - 복원 버튼 클릭 시 원래 크기로 돌아오고 아이콘이 최대화 모양으로 다시 전환되는지 확인

5. **닫기 버튼**
   - 닫기 버튼 클릭 시 창이 숨겨지고(`mainWindow.isVisible() === false`), 프로세스는 실행 중(`mainWindow.isDestroyed() === false`)인지 확인
   - B5.1 규칙("X는 트레이로 숨김, 프로세스 유지") 정상 동작 확인

6. **Alt+Space 확인 (수동)**
   - Windows 기본 창 제어 메뉴(Alt+Space)가 여전히 동작하는지 확인

7. **더블클릭 최대화 토글 (수동, 미검증 구간)**
   - 타이틀바를 더블클릭했을 때 최대화/복원이 한 번만 토글되는지 확인
   - 주의: Windows의 드래그 영역(HTCAPTION)이 OS가 자동으로 처리할 수도 있고, DOM dblclick과 겹칠 수 있어 완벽히 검증하기 어려움. 이는 알려진 한계이며 requirements.md에 명시됨.

8. **최소 창 높이와 사이드바 오버플로우**
   - 창의 최소 높이(minHeight=420px)에서 사이드바의 마지막 메뉴("일정")이 창 아래로 잘리지 않고 57px 여유로 들어오는지 실측 확인
   - 콘텐츠 영역이 실제로 363px(타이틀바 36px + 여유)인지 Playwright로 boundingBox 확인

9. **린트/테스트/빌드 통과**
   - `npm run lint` → 0 errors (300줄 제한 포함)
   - `npm test` → vitest 240개 테스트 통과 (이 작업에서 변경 없음)
   - `npm run build` → Vite 프로덕션 빌드 성공
