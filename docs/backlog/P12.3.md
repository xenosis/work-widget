# P12.3 — 타이틀바/창 컨트롤 다크 글래스 테마 구현

## 목적

P12.2에서 결정된 방식에 따라 네이티브 타이틀바와 창 컨트롤 버튼을 앱의 다크 글래스 테마와 일치하게 구현하고, 창 이동/숨김 등 기존 동작을 유지합니다.

## 쉬운 설명

P12.2에서 3가지 방식 중 하나가 선택되면, 그 방식에 맞춰 코드를 수정합니다. 예를 들어:

- **(방식 a 선택 시)**: `electron/main.js`에서 `nativeTheme.themeSource = 'dark'`를 추가하고 테스트
- **(방식 b 선택 시)**: `titleBarOverlay` 옵션을 활성화하고, 렌더러 상단에 드래그 영역과 앱 제목을 CSS로 구현
- **(방식 c 선택 시)**: 타이틀바를 완전히 숨기고, React 컴포넌트에서 최소화/최대화/닫기 버튼을 직접 만든 뒤 preload.js를 통해 Electron과 통신

어느 방식이든 끝나면:
- 타이틀바와 버튼이 앱 배경 색과 어울림
- 드래그로 창을 이동할 수 있음
- X(닫기) 버튼을 누르면 트레이로 숨어짐(B5.1 동작 유지)
- 최소화/최대화가 정상 작동

## 필요한 입력

- `electron/main.js` — BrowserWindow 옵션 설정
- `electron/preload.js` — (방식 c인 경우) 창 제어 IPC 함수
- `electron/windowState.js` — (방식 b/c인 경우) 새 minHeight 측정 및 업데이트
- `src/index.css` — 테마 색 토큰, (방식 b/c인 경우) 드래그 영역/버튼 스타일
- `src/App.jsx` 또는 레이아웃 컴포넌트 — (방식 b/c인 경우) 타이틀바 렌더링

## 결과물

- `electron/main.js`: 선택된 방식에 맞게 BrowserWindow 옵션 수정
- `src/index.css`: 필요한 경우 타이틀바/버튼 스타일 추가
- `electron/windowState.js`: 새 minHeight 값 반영 (방식 b/c인 경우)
- `electron/preload.js`: 창 제어 IPC 추가 (방식 c인 경우)
- 실행 시 타이틀바/버튼이 다크 톤으로 표시되는 스크린샷
- 새 프레임에 맞춘 최소 높이 측정값을 주석으로 기록

## 선행 작업

1. **P12.1** — 메뉴 제거(이미 하단이 타이틀바와 연결되므로 먼저 수행)
2. **P12.2** — 타이틀바 방식 결정(이 task는 그 결정에 따라 달라짐)

## 수행 순서에서의 위치

P12의 핵심 첫 번째 구현 task입니다. P12.1(메뉴)이 완료되고 P12.2(결정)가 끝난 후에 착수합니다. 타이틀바 개선이 끝나면 사이드바와 콘텐츠 영역이 깔끔해져, P12.4~P12.15의 나머지 기능 개선이 훨씬 쉬워집니다.

## done_when을 확인하는 방법

1. **시각적 확인**:
   - 앱 실행 후 타이틀바(제목 표시줄과 최소화/최대화/닫기 버튼)가 대시보드 배경 톤(다크 글래스)과 같은 색으로 표시되는지 확인
   - 스크린샷 1장 캡처 — 밝은 기본 배경이 아니라 앱의 다크 톤이어야 함

2. **기능 확인**:
   - 드래그로 창을 이동할 수 있는지 확인
   - X(닫기) 버튼을 누르면 창이 완전히 닫히지 않고 트레이로 숨어드는지 확인(B5.1)
   - 최소화 버튼을 누르면 최소화되는지 확인
   - 최대화 버튼을 누르면 최대화되는지 확인(방식 a에서는 없을 수 있음)

3. **레이아웃 확인**:
   - 새 프레임 기준 최소 높이(P7.4의 420px 재측정)에서 사이드바의 마지막 메뉴 항목이 잘리지 않는지 확인
   - 스크린샷으로 측정값 기록(예: "새 드래그 영역 높이 48px 추가되어 콘텐츠 영역 줄어듦, 사이드바 마지막 메뉴 시작점 327px 기준으로 최소 높이 조정 필요" 등)

4. **코드 검증**:
   - `npm run lint` — eslint 통과
   - `npm run build` — Vite 빌드 성공
   - (있으면) `npm test` — 단위테스트 통과(ScheduleGrid 같은 순수 함수만 다룸)

5. **문서**:
   - `work-widget-requirements.md`의 B1.1 절에 구현 세부사항 기록(예: "방식 b 선택, titleBarOverlay 적용, 드래그 영역 CSS-webkit-app-region 사용, preload 변경 없음")

## 확인 필요

- **새 창 높이**: 새 타이틀바 구현 후 실제 필요한 minHeight 값 — P7.4의 기준값(420/327px)을 초과할 가능성이 있으므로 실측 후 기록 필요
- **(방식 c인 경우) preload.js IPC**: P12.2에서 "최소화/최대화/닫기 IPC 추가"를 기술했는데, 구현 시 IPC 이름과 시그니처를 확인하고 security context 검토 필요
