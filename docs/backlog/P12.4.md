# P12.4 — 프로젝트 추가 폼 마감일 입력

## 목적

프로젝트를 만들 때 마감일을 바로 설정할 수 있게 함으로써 사용성을 개선한다. 기존에는 프로젝트를 만든 후 상세 화면으로 들어가 별도의 수정 폼을 열어야만 마감일을 설정할 수 있었다. 이를 추가 폼 안에서 한 번에 처리할 수 있도록 개선하는 것이 이 작업의 목표다. 앱 전반의 "별도 팝업 없이 폼 안에서 바로 처리(B2.1)" 기조와도 일치한다.

## 쉬운 설명

프로젝트를 추가할 때 쓰는 입력 폼에 마감일 선택 필드를 추가하는 작업이다. 지금까지는 프로젝트명과 유형(장기/단기) 두 가지만 입력했지만, 이제 마감일까지 함께 입력하고 한 번에 저장할 수 있다.

다만 창의 폭이 정해져 있어서(최소 420px) 모든 필드가 한 줄에 들어가지 않으므로, AddProjectForm만을 위한 새로운 CSS 레이아웃을 적용했다:
- 첫 번째 줄: 프로젝트명 입력
- 두 번째 줄: 유형 선택 + 마감일 선택 + 추가 버튼

이때 같은 `.project-add-form` CSS 클래스를 쓰는 다른 폼(할일전체 화면의 할일 추가 폼, P3.3)이 깨지지 않도록 새로운 modifier 클래스 `.project-add-form--stacked`를 만들어 AddProjectForm에만 적용했다. 할일 추가 폼은 여전히 한 줄 레이아웃이다.

## 필요한 입력

1. **AddProjectForm 컴포넌트** (src/screens/Projects.jsx):
   - 이미 있던 입력: 프로젝트명(텍스트 input), 유형(select, 장기/단기)
   - 추가할 입력: 마감일(HTML date input)
   - state로 dueDate 변수 추가, date input의 value와 onChange 연결

2. **createProject 함수** (src/lib/projectFactory.js):
   - 기존 시그니처: `createProject(name, type, now = ...)`
   - 새 시그니처: `createProject(name, type, dueDate = null, now = ...)`
   - dueDate를 now보다 앞에 배치해 기존 2-인자 호출부가 깨지지 않도록 하위호환성 유지

3. **CSS 클래스 설계** (src/index.css):
   - `.project-add-form` 기본값: row(가로) 레이아웃 유지 — TodoAddForm이 이 레이아웃 필요
   - 새로운 `.project-add-form--stacked`: column(세로) 레이아웃 — AddProjectForm에만 적용
   - `.project-edit-row`: AddProjectForm의 두 번째 줄에서 유형/마감일/버튼을 flex로 배열

4. **요구사항 문서** (work-widget-requirements.md):
   - B2.1 섹션에 "(2026-09-25 결정, P12.4)" 항목 추가
   - 마감일 필드 추가, 레이아웃 변경(이름 1줄 + 유형/마감일/버튼 2줄), TodoAddForm 레이아웃 보존 명시
   - v2.7 변경 이력 추가

## done_when을 확인하는 방법

1. **프로젝트 추가 폼에서 마감일 입력 동작 확인**:
   ```bash
   npm run dev
   ```
   - 프로젝트 화면에서 프로젝트명(예: "테스트 프로젝트")과 유형을 입력
   - 마감일 필드에서 날짜 선택(예: 2026-12-25)
   - "추가" 버튼 클릭
   - data.json 파일을 열어 새로 생성된 프로젝트에 `"due_date": "2026-12-25"` 저장 확인

2. **마감일 없이 추가하는 경우 확인**:
   - 프로젝트명과 유형만 입력하고 마감일 필드는 비운 채로 추가
   - data.json에서 해당 프로젝트의 `"due_date": null` 저장 확인

3. **레이아웃 오버플로 확인**:
   - 개발자 도구의 기기 에뮬레이션으로 창 너비를 420px로 제한
   - 프로젝트 추가 폼 영역에서 모든 요소(이름 입력, 유형/마감일/버튼 행)가 보이고 찌그러지지 않는지 확인
   - 스크린샷 촬영으로 기록

4. **할일 추가 폼 레이아웃 회귀 확인** (critical-reviewer 지적 반영):
   - 할일전체 화면으로 이동
   - 할일 추가 폼이 여전히 한 줄 레이아웃(제목 input + 프로젝트 select + 버튼)으로 배치되는지 확인
   - 새 modifier 클래스 때문에 이 폼의 높이가 늘어나지 않는지 Playwright 또는 개발자 도구로 검증
   - 스크린샷 촬영으로 기록

5. **테스트 실행**:
   ```bash
   npm test
   ```
   - projectFactory.test.js의 모든 테스트 통과
   - dueDate 저장/기본값 테스트 통과
   - 3-인자 호출(now 생략) 하위호환 테스트 통과

6. **린트 및 빌드**:
   ```bash
   npm run lint
   npm run build
   ```
   - eslint 규칙 준수(max-lines 300줄 이내, src/electron 분리 등)
   - Vite 빌드 성공

7. **요구사항 문서 갱신 확인**:
   - work-widget-requirements.md의 B2.1 섹션에 "(2026-09-25 결정, P12.4)" 항목이 추가됨
   - 마감일 필드 추가, 레이아웃 변경(두 줄), TodoAddForm 레이아웃 보존이 명시됨
   - 변경 이력에 v2.7 항목 추가 확인
