# P12.5 — 할일 추가 폼 마감일 입력(할일전체/프로젝트 상세)

## 목적

할일을 추가하는 시점에 마감일을 함께 지정할 수 있도록 해서, 수정 폼을 거치지 않고도 새 할일을 올바른 날짜 그룹(오늘/이번주/나중)에 바로 배치할 수 있게 합니다. 두 추가 폼(할일전체 화면, 프로젝트 상세 화면)에서 일관된 마감일 선택 경험을 제공합니다.

## 쉬운 설명

현재까지 할일을 추가할 때는 제목만 입력할 수 있었습니다. 마감일을 설정하려면 생성 후 따로 수정 폼을 열어야 했고, 그 사이 새 할일은 항상 '나중' 그룹에 나타났습니다.

이 작업은 할일을 만드는 두 곳에 마감일 선택 입력을 추가합니다:
1. **할일 전체 화면** — 새 할일 추가 폼에 date 입력 필드 추가
2. **프로젝트 상세 화면** — 인라인 추가 폼에 date 입력 필드 추가

날짜를 선택하면 할일이 즉시 올바른 그룹(오늘/이번주/나중)에 나타나고, 비워두면 '나중' 그룹에 들어갑니다. 프로젝트 상세 화면에서는 제목만 입력해서 Enter로 추가하는 기존 동작도 그대로 유지됩니다.

## 필요한 입력

- `src/components/TodoAddForm.jsx` — 할일 전체 화면의 추가 폼
- `src/components/ProjectDetail.jsx` — 프로젝트 상세 화면의 AddTodoForm 컴포넌트
- `src/lib/todoFactory.js` — createTodo() 함수
- `src/lib/todoFactory.test.js` — 함수 테스트 케이스
- `src/index.css` — 폼 레이아웃 스타일
- `work-widget-requirements.md` B2.1·B2.2 섹션 — 마감일 입력 결정 문단 기록

## 결과물

1. **TodoAddForm.jsx**: 마감일 선택 입력(`<input type="date">`) 추가, `dueDate` 상태 관리, `onAdd` 콜백에 `dueDate` 전달
2. **ProjectDetail.jsx의 AddTodoForm**: 
   - 제목과 마감일 입력을 `.project-edit-row`로 한 행에 배치
   - HTML 표준상 date 입력은 암묵적 제출(implicit submission)을 막으므로, 화면에 안 보이는 submit 버튼 추가 — 날짜 입력에서도 Enter로 제출 가능
   - 기존 "제목만 입력 후 Enter로 즉시 추가" 흐름 유지
3. **todoFactory.js**: `createTodo(projectId, title, dueDate=null, now=...)` 함수 서명 확장
4. **todoFactory.test.js**: `dueDate` 값(지정/미지정)에 따른 생성 테스트 케이스 추가, 그룹 경계 검증을 서로 다른 날짜 3개로 수행
5. **index.css**:
   - `.todo-add-form .todo-add-input`: flex 범위 좁혀 date 입력과 함께 한 행 배치
   - `.todo-add-form .project-edit-row input[type='date']`: 고정 폭(100px) 지정으로 제목 입력이 남은 공간 전부 사용
   - `.visually-hidden`: 스크린리더용 숨겨진 submit 버튼 스타일
6. **work-widget-requirements.md**: B2.1, B2.2의 마감일 입력 추가 결정 문단 기록

## done_when을 확인하는 방법

1. **두 추가 폼에서 마감일 지정 후 저장 확인**:
   - 할일 전체 화면: 제목 + 프로젝트 선택 + 마감일(예: 2026-09-27) → 추가
   - data.json 확인: 생성된 할일의 `due_date` 필드가 "2026-09-27"로 저장됨
   - 프로젝트 상세 화면: 제목 + 마감일(예: 2026-09-28) → 추가
   - data.json 확인: 생성된 할일의 `due_date` 필드가 "2026-09-28"로 저장됨

2. **마감일 미지정 시 null 저장 확인**:
   - 두 폼 모두에서 마감일 입력을 건드리지 않고 추가
   - data.json 확인: 할일의 `due_date`가 `null`임

3. **올바른 그룹에 즉시 반영 확인** (critical-reviewer 재검증에서 경계값 테스트로 강화됨):
   - 오늘 날짜로 설정: 할일이 "오늘" 그룹에 즉시 나타남
   - 이번주 미래 날짜(예: 3일 뒤, 월~금 범위)로 설정: "이번주" 그룹에 즉시 나타남
   - 다음주 이후 또는 빈 채로 설정: "나중" 그룹에 즉시 나타남
   - 테스트에서는 서로 다른 날짜 3개(각 그룹 하나씩)로 경계 검증

4. **프로젝트 상세 화면 Enter 흐름 유지**:
   - 프로젝트 상세에서 제목 입력 → Enter: 할일이 '나중' 그룹에 생성됨 (마감일 미지정이므로)
   - 날짜 입력 필드에 포커스 중 Enter: 같은 제출 동작 (숨겨진 submit 버튼으로 보정)

5. **createTodo 함수 서명 확인**:
   - `createTodo(projectId, title, dueDate=null, now=...)` 형태
   - TodoAddForm/ProjectDetail → Projects.jsx → useAppData → createTodo로 이어지는 콜백 체인에서 모두 `dueDate` 인자 관통

6. **테스트 통과**:
   - `npm test` 실행: todoFactory.test.js의 신규 테스트 전부 통과
   - `dueDate` 지정/미지정, 그룹 경계(오늘/이번주/나중) 모두 커버

7. **린트/빌드 통과**:
   - `npm run lint`: exit code 0 (eslint 규칙 포함 300줄 제한)
   - `npm run build`: exit code 0 (vite 빌드 성공)

8. **요구사항 문서 갱신**:
   - `work-widget-requirements.md` B2.1, B2.2 섹션에 P12.5 결정 문단 기록됨

## 확인 필요

1. **critical-reviewer 재검증에서 발견된 2가지 버그 (모두 반영 완료)**:
   - (1) 그룹 배치 검증이 같은 날짜만 써서 실제로는 경계를 검증하지 못하던 문제: 서로 다른 날짜 3개(오늘/이번주/나중)로 재검증하여 해결
   - (2) ProjectDetail의 AddTodoForm에서 date 입력에 포커스 중 Enter를 누르면 제출되지 않던 HTML 표준 동작: 화면에 안 보이는 submit 버튼(`.visually-hidden`)을 추가하여 모든 입력에서 Enter로 항상 제출되도록 보정

해당 버그 지적 항목이 모두 반영되었으므로 추가 확인 필요 사항 없음.
