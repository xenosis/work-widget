# P12.7 — 공휴일 데이터 출처 결정

## 목적

달력에 한국 공휴일을 표시하기 위해, 공휴일 정보를 어떻게 제공할지 결정한다. 한국 공휴일은 음력 기반(설날, 추석, 부처님오신날) + 대체공휴일 + 임시공휴일을 포함하고 있어 순수 계산만으로는 불가능하므로, 외부 데이터나 라이브러리를 활용해야 한다.

## 쉬운 설명

달력을 표시할 때 특정 날짜가 공휴일인지 판정해야 합니다. 한국 공휴일은 복잡해서(음력 기반, 대체공휴일 등) 순수 계산만으로는 불가능합니다. 이 task는 복합한 결정 과정을 거쳤습니다:

**1단계: 초기 필요성 인식 (2026-09-25 05:13)**
스크린에서 공휴일 데이터를 다루려면, 선택지(a) 연도별 정적 테이블 수동 관리, (b) 양력+테이블 혼합, (c) 공공 API 호출, (d) npm 라이브러리, (e) 사용자 직접 입력 중 하나를 결정해야 합니다. 현재로서는 명확한 결정이 없으므로 사람의 판단을 기다립니다.

**2단계: 빠른 결정 (2026-09-25 05:22)**
사람이 npm 패키지 **'korean-holidays'**(MIT 라이선스, 의존성 korean-lunar-calendar 하나뿐)를 선택했습니다. 대체공휴일 지원이 필요했고, 런타임 네트워크 호출 없이 오프라인 동작하므로 Part A 3 '로컬전용' 원칙과 충돌하지 않습니다. P5.1의 "무의존성 관행"을 이 건에 한해 예외로 두기로 결정했습니다.

**3단계: 미충족 done_when 발견 (2026-09-25 10:14)**
P12.8 리뷰 중에 critical-reviewer가 중대한 문제를 지적했습니다. 이 task의 done_when이 요구한 **"지원 연도 범위"와 "갱신 책임"이 실제로는 결정되지 않은 채 done으로 처리돼 있었다**는 것입니다. 사람이 비로소 이를 명시했습니다: 지원 연도는 라이브러리가 계산하는 범위 그대로 받아들이고, 갱신 책임은 npm 패키지 버전 업데이트에 맡긴다고 확정.

**4단계: 사실 오류 발견 및 정정 (2026-09-25 10:23)**
critical-reviewer가 코드와 라이브러리 README를 직접 확인한 결과, 3단계의 기록이 **사실과 다르다**는 것을 발견했습니다. 최초 설명에는 "연도별 **계산 로직**이라 정적 테이블처럼 만료되지 않는다"고 했지만, 실제로는 음력 공휴일(설날/석가탄신일/추석)이 **음력 1000~2050년(양력 ~2050-12-31) 범위의 정적 변환 테이블**에만 의존하며, 2051년부터는 조용히 null을 반환한다는 것을 `getHolidayInfo` 함수로 직접 확인했습니다. 또한 공휴일끼리 겹칠 때 생기는 대체공휴일(예: 어린이날과 석가탄신일이 같은 평일에 겹치는 경우)은 계산되지 않는다는 한계도 발견했습니다. 사람이 이 정정된 사실을 반영해도 여전히 "범위 그대로 수용"하기로 재확인했습니다(24년 이상 남은 시점이라 개인용 위젯 용도로 충분하다고 판단).

**5단계: 제헌절 판정 수용 확정 (2026-09-25 11:29)**
P12.8의 3차 재검증에서 critical-reviewer가 "제헌절 2026 공휘일 복원 판정을 라이브러리 값 그대로 신뢰하는 항목이 실제 사람 결정 기록(이 log)에는 없고 구현자 note에만 있었다"고 지적했습니다. 사람이 명시적으로 "라이브러리(korean-holidays)가 하드코딩한 '2026년부터 제헌절 공휴일 복원' 판정을 법령 검증 없이 그대로 신뢰하기로 확정"했습니다.

**결론**: 처음 선택(npm 패키지)은 빨리 결정되었지만, 완전성을 위해 (1) 미충족 done_when 명시, (2) 사실 오류 발견과 정정, (3) 제헌절 판정의 명시적 승인이라는 세 라운드의 재확인을 거쳤습니다. 이 과정 자체가 정확한 결정을 위해 필수였습니다.

## 필요한 입력

- 공휴일 데이터 소스로 사용할 npm 라이브러리 선택 (최종: korean-holidays)
- 지원 연도 범위와 그 근거 (최종: 라이브러리 범위 그대로 수용, 음력 공휴일은 2050년까지)
- 대체공휴일 미비 시 갱신 책임자 지정 (최종: npm 패키지 버전 업데이트에 맡김)

## 결과물

- `package.json`에 `korean-holidays` 의존성 추가
- work-widget-requirements.md의 B2.4 절에 결정 문단 기록:
  - 공휴일 데이터 출처: npm 패키지 `korean-holidays`
  - 지원 연도 범위: 고정 공휴일(신정/3·1절/어린이날/현충일/제헌절/광복절/개천절/한글날/성탄절) 무제한, 음력 공휴일(설날/석가탄신일/추석) 및 대체공휴일은 2050년까지만 정확함 (2051년부터 null 반환)
  - 갱신 책임: npm 패키지 버전 업데이트에 맡김
  - 알려진 한계: 선거일/정부 임시공휴일 미지원, 공휴일 겹침 시 이름 하나만 반환, 공휴일끼리 겹칠 때의 대체공휴일 미계산
- P12.8(달력 공휴일 표시)이 이 라이브러리로 판정 함수를 구현하는 기초

## done_when을 확인하는 방법

### 1단계: 요구사항 문서 확인
`work-widget-requirements.md`의 B2.4 절 "일정 화면(루틴 포함)" 섹션을 엽니다.

### 2단계: 지원 연도 범위 확인
"P12.7 한국 공휴일 표시..." 문단과 그 아래 "지원 연도 범위·갱신 책임(2026-09-25 사람 결정, ...)" 문단을 찾아, 다음이 모두 구체적으로 기록되어 있는지 확인합니다:
- 고정 공휴일(신정 등 9개)의 연도 제한이 없음
- 음력 공휴일(설날/석가탄신일/추석)과 대체공휴일이 **2050년(양력 기준 2050-12-31)**까지만 정확함
- 2051년부터 음력 공휴일이 "조용히 null을 반환"한다는 내용

### 3단계: 갱신 책임 확인
문단에 "매년 갱신 책임자도 별도로 지정하지 않고 npm 패키지 버전 업데이트에 맡긴다"고 명시되어 있는지 확인합니다.

### 4단계: 한계 명시 확인
"알려진 한계(critical-reviewer 지적, 2026-09-25 사람 결정으로 수용)" 문단에서:
- 선거일과 정부 임시공휴일 미지원
- 대체공휴일 판정이 **주말과 겹칠 때만** 계산되며, 공휴일끼리 겹칠 때의 대체공휴일은 미계산
- 두 공휴일이 같은 날 겹치면 첫 번째 이름 하나만 반환
- 2026년 제헌절 복원 판정을 라이브러리 값 그대로 신뢰

이 네 가지가 정확히 기록되어 있는지 확인합니다.

### 5단계: 패키지 확인
`package.json`을 열어 `dependencies` 또는 `devDependencies` 중 `korean-holidays` 항목이 있고 버전이 명시되어 있는지 확인합니다.

모든 단계가 확인되면 done_when 충족입니다.
