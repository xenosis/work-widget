# P12 — UI/UX 개선 — 실사용 피드백 1차

## 목적

사용자가 실제로 앱을 설치하고 써본 뒤 지적한 7가지 UI/UX 문제를 분석하고 개선해서, 위젯의 사용성과 시각적 일관성을 높인다.

## 쉬운 설명

MVP 개발(P0~P11)이 끝난 뒤 실제 사용자가 앱을 써보니 여러 문제가 발견됐습니다:
1. Electron 기본 메뉴가 불필요하게 떠있음
2. 타이틀바와 앱 테마가 어울리지 않음
3. 프로젝트/할일을 추가할 때 날짜를 입력할 수 없음(수정에서만 가능)
4. 달력에 주말/공휴일 구분이 없음
5. 달력 셀이 '있다'는 점만 보여주고 내용이 보이지 않음
6. 편집 폼 버튼들이 스타일이 다름
7. select와 date 입력이 OS 기본 모양이라 앱 테마와 안 어울림

이 부모 작업은 이 7가지 문제를 15개의 구체적 하위 작업으로 분해해서 관리하고, 모두 끝나면 이 작업도 종료됩니다.

## 필요한 입력

- 사용자 피드백(7가지 항목) — 이미 수집됨
- 기존 코드(electron/main.js, src/components, src/index.css 등) — 프로젝트에 존재
- 요구사항 문서(B1~B5) — 이미 작성됨

## 결과물

다음 15개 하위 task(P12.1~P12.15)가 모두 `done` 또는 `cancelled` 상태가 됨:
- 메뉴 제거(P12.1)
- 타이틀바 테마 처리(P12.2 spike, P12.3 구현)
- 추가 폼 날짜 입력(P12.4, P12.5)
- 달력 개선(P12.6~P12.9)
- 폼 UI 통일(P12.11~P12.15)
- 공휴일 처리(P12.7 spike, P12.8 구현) — 결정 필요

## 선행 작업

없음. MVP(P0~P11)가 완료된 상태에서 실사용 피드백을 반영하는 독립 phase입니다.

## 수행 순서에서의 위치

P12는 부모 task로, 전체 위젯 개선 phase를 표현합니다. 실제 구현 순서는:
- **1단계**: P12.1(메뉴 제거), P12.4(프로젝트 날짜), P12.5(할일 날짜) — 독립적, 빠름
- **2단계**: P12.2 spike(타이틀바 방식 결정), P12.7 spike(공휴일 출처 결정) — 사람 결정 필요
- **3단계**: 2단계 결정 후 P12.3(타이틀바 구현), P12.8(공휴일 표시)
- **4단계**: P12.6(달력 주말), P12.9(달력 셀 정보), P12.10 spike(색상 필드)
- **5단계**: P12.11(버튼 스타일), P12.12(간격 보정), P12.13(select/date 테마)
- **6단계**: P12.14 spike(커스텀 컴포넌트), P12.15(구현)

각 task가 모두 done되거나 의도적으로 cancelled(예: 공휴일 스킬 미배정)되면 이 부모가 종료됩니다.

## done_when을 확인하는 방법

하위 P12.1~P12.15 15개 task의 상태를 확인합니다:
```
node scripts/backlog/cli.js list | grep -E '"id": "P12\.(1[0-5]|[1-9])"' | grep -E '"status": "(done|cancelled)"'
```
그 결과가 정확히 15줄이면 이 task의 done_when을 충족합니다(부모 P12는 모두 done이어야 함). 또는 `backlog.json`을 읽어서 P12.1~P12.15의 status가 모두 done 또는 cancelled임을 직접 확인합니다.

## 확인 필요

없음. 부모 task는 하위 task들의 상태에만 의존합니다.
