# P14.1 — 외부 backlog(.json) 소스 등록 및 읽기 (관리 UI/IPC/파서)

## 목적

다른 프로젝트의 backlog(.json) 파일(이 프로젝트의 `scripts/backlog/cli.js`와 같은 작업 추적 방식)을 이 위젯에 등록해서 관리할 수 있도록 준비합니다. 이 작업은 데이터 모델(`backlog_sources` 배열), 네이티브 파일 선택 다이얼로그, 안전한 읽기 전용 IPC, 유연한 파서, 그리고 일정 화면의 관리 UI를 포함합니다. **실제 등록된 파일의 task 목록을 화면에 나열하는 것은 P14.2의 몫입니다.**

## 쉬운 설명

업무 위젯은 원래 이 프로젝트 자신의 프로젝트/할일/메모/일정만 관리하는 도구입니다. 하지만 회사의 다른 프로젝트들도 자기만의 backlog.json 파일로 작업을 추적할 수 있습니다. P14.1은 그런 다른 프로젝트들의 backlog.json 파일을 여러 개 "등록"할 수 있는 기능을 만듭니다.

**구체적으로:**

1. **등록하기**: 일정 화면에 "외부 backlog(.json) 소스 관리" 접이식 패널이 생깁니다. 사용자는 "+ backlog(.json) 파일 선택해서 등록" 버튼을 눌러 Windows 파일 선택 다이얼로그를 열고, 다른 프로젝트의 backlog.json을 골라 등록합니다. 같은 파일을 두 번 고르면 자동으로 무시됩니다(중복 방지).

2. **등록된 정보 보기**: 등록된 각 파일마다:
   - 파일이 든 폴더 이름(보통 프로젝트 이름) 표시
   - 전체 경로 표시(마우스 올리면 tooltip으로 전체 확인)
   - 그 자리에서 파일을 읽어본 상태 표시: "정상 (task 3개)" 또는 "파일을 찾을 수 없습니다" 같은 오류 메시지

3. **안전하게 읽기만 하기**: 이 위젯은 등록된 파일을 **절대 쓰지 않습니다**. 다른 프로젝트의 backlog.json은 그 프로젝트 자신의 CLI/훅(validation rules 등)을 이미 갖고 있을 수 있기 때문입니다. 읽기(`fs.readFileSync`)만 합니다.

4. **유연하게 파싱하기**: 다른 프로젝트의 backlog.json 구조가 이 프로젝트와 정확히 같을 리 없습니다(배열 이름, 필드가 다를 수 있음). 그래서 파서는 여러 형태를 받아들입니다:
   - 최상위가 배열 → 그걸 task 목록으로 봄
   - `{ tasks: [...] }` 형태 → tasks 배열을 task 목록으로 봄
   - `{ items: [...] }` 또는 `{ backlog: [...] }` 형태도 지원
   - 각 task는 `id`(문자열)만 필수 → 없으면 건너뜀
   - `title`/`status`/`owner` 필드는 있으면 쓰고 없으면 "(제목 없음)" 같은 자리표시자로 채움

5. **독립적 오류 처리**: 파일이 없어지거나 JSON이 깨져도 그 소스 하나만 오류로 표시됩니다. 다른 등록된 소스나 위젯 전체에는 영향이 없습니다.

## 결과물

### 1. 데이터 모델 (`electron/dataStore.js`)
- `data.json`에 새 최상위 배열 `backlog_sources` 추가
- 각 항목 스키마(B3.5):
  - `id` (string): `backlog-source-<uuid>` 형태
  - `path` (string): 등록된 backlog.json 파일의 절대 경로
  - `label` (string|null): 사용자 지정 이름(현재 항상 null, 나중에 UI 추가 예정)
  - `created_at`, `updated_at` (datetime)

### 2. Electron 메인 프로세스 - IPC 핸들러 (`electron/backlogSources.js`)
```javascript
ipcMain.handle('backlog-source:pick-file', async () => { ... })
  // 반환: 파일 경로 문자열 또는 null(취소)
  
ipcMain.handle('backlog-source:read-tasks', (_event, filePath) => { ... })
  // 반환: { ok: true, tasks: [...] } 또는 { ok: false, error: "..." }
  // 파일 없음/JSON 파싱 실패 등을 각 소스별로 처리
```

### 3. Electron 메인 프로세스 - 파서 (`electron/backlogSourceReader.js`)
- `parseBacklogSourceTasks(jsonText)` 함수
- 입력: JSON 문자열
- 출력: 정규화된 task 객체 배열 (최소 4개 필드: id, title, status, owner)
- 특징: 다양한 배열 위치/필드 조합을 관대하게 파싱

### 4. 렌더러 - Preload 브리지 (`electron/preload.js`)
```javascript
window.api.pickBacklogSourceFile()      // → path|null
window.api.readBacklogSourceTasks(path) // → { ok, tasks|error }
```

### 5. 렌더러 - 비즈니스 로직 (`src/lib/`)
- **backlogSourceFactory.js**: `createBacklogSource({ path })` — 새 소스 레코드 생성
- **backlogSourceMutations.js**:
  - `getUsableBacklogSources(sources)` — id/path 없는 레코드 필터
  - `removeBacklogSource(sources, sourceId)` — 소스 삭제
  - `deriveLabelFromPath(filePath)` — 경로에서 폴더명 추출
  - `getSourceDisplayLabel(source)` — label 또는 파생된 이름 반환
- **backlogSourceActions.js**: `createBacklogSourceActions(...)` — 추가/삭제 액션 팩토리

### 6. 렌더러 - UI 컴포넌트 (`src/components/`)
- **BacklogSourceManager.jsx**: 소스 목록/추가/삭제 관리 인터페이스
  - SourceStatus 서브컴포넌트: 각 소스 읽기 상태 표시
  - SourceRow 서브컴포넌트: 각 소스의 행(이름, 경로, 상태, 삭제 버튼)
- **BacklogSourcesSection.jsx**: 일정 화면 내 접이식 패널(카테고리 관리와 같은 스타일)

### 7. 렌더러 - 통합 (`src/screens/Schedule.jsx`)
- BacklogSourcesSection 컴포넌트 마운트
- handleAddSource/handleDeleteSource 액션 연결
- data.backlog_sources 배열을 상태로 관리
