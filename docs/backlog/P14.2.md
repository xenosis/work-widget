# P14.2 — 외부 백로그 task 목록 대시보드 (상태/담당별 분류)

## 목적

P14.1에서 등록한 다른 프로젝트의 backlog(.json) 파일들의 실제 task 목록을 일정 화면에 보여줍니다. 각 등록 소스별로 그 소스의 모든 task를 상태(`status`)별로 묶어 표시하고, 각 task의 담당자(`owner`)를 한 줄에 함께 표시합니다. P14.1의 "관리" 패널이 소스 하나당 개수/오류 요약만 보여줬다면, P14.2는 전체 task 목록의 대시보드입니다.

## 쉬운 설명

P14.1을 통해 다른 프로젝트의 backlog.json 파일을 여러 개 등록했습니다. P14.2는 **그 파일들에 들어있는 실제 작업 목록을 보여주는** 기능입니다.

**구체적으로:**

1. **새로운 패널**: 일정 화면에 "외부 백로그 현황" 이라는 새로운 접이식 패널이 생깁니다(P14.1의 "외부 backlog(.json) 소스 관리" 패널 바로 아래).

2. **등록된 소스 없으면**: 패널을 열었을 때 "등록된 외부 backlog(.json) 소스가 없습니다(위 소스 관리에서 먼저 등록하세요)" 메시지가 나타납니다.

3. **각 소스별 task 목록**:
   - 패널 안에서 등록된 각 파일마다 하나씩 섹션이 만들어집니다(파일이 든 폴더명으로 제목).
   - 그 섹션 안에서 모든 task를 **상태별로 묶어서** 보여줍니다:
     ```
     진행중 (3개)
       [task 1] — 담당자 이름
       [task 2] — (담당자 없음)
       [task 3] — 담당자 이름
     
     완료됨 (2개)
       [task 4] — 담당자 이름
       [task 5]
     ```

4. **유연한 상태 인식**: 다른 프로젝트의 backlog.json은 상태 값을 자유롭게 쓸 수 있습니다(예: "진행중", "blocked", "검토중" 등 프로젝트마다 다름). P14.2는 "이 프로젝트가 사용하는 상태 목록"을 미리 정해두지 않고, **등록된 파일의 task들에 실제로 등장하는 상태 값들을 그대로 인식해서 그룹을 만듭니다.** 그래서 이 프로젝트가 모르는 상태값도 조용히 나타납니다.

5. **오류 처리**: 파일이 없어지거나 JSON이 깨지거나 형식을 인식할 수 없으면, 그 소스 섹션에 오류 메시지만 표시되고 다른 소스에는 영향이 없습니다.

## 필요한 입력

**기술적 의존성:**
- P14.1이 이미 완료돼서 데이터 모델(`data.backlog_sources`)과 IPC 핸들러(`readBacklogSourceTasks`)가 존재해야 합니다.
- P14.1과 동일한 `backlogSourceMutations.js`, `backlogSourceReader.js` 기반 task 형식(id, title, status, owner)

**React 컴포넌트 시스템:**

**스타일시트:**

## 결과물

### 1. 컴포넌트 - 접이식 패널 틀 (`src/components/BacklogStatusSection.jsx`)
- 토글 버튼: "외부 백로그 현황 ▼" (닫혀있음) / "외부 백로그 현황 닫기 ▲" (열려있음)
- 열려있으면 카드 형태의 패널 표시
- `BacklogStatusPanel.jsx` 컴포넌트에 `sources` prop 전달

### 2. 컴포넌트 - 패널 본체 (`src/components/BacklogStatusPanel.jsx`)
- 등록된 소스 없음 → 안내 메시지
- 등록된 소스 있음 → 각 소스별로 `SourceTaskGroups` 서브컴포넌트 렌더링

#### 2-1. 서브컴포넌트 - `SourceTaskGroups`
- `useBacklogSourceRead` 훅으로 해당 소스의 파일 읽기(로딩/성공/실패 상태 추적)
- 로딩 중: "확인 중..." 텍스트
- 읽기 실패: 오류 메시지 표시
- 형식 미인식: "인식 가능한 task 배열을 찾지 못했습니다." 경고 메시지
- 성공 & 빈 목록: "등록된 task가 없습니다."
- 성공 & task 있음: `groupTasksByStatus`로 상태별 묶음 생성 후 렌더링
  - 각 상태별 섹션: 제목 (상태 문자열 + task 개수 배지)
  - 각 task 행: 제목 + (owner 있으면) 담당자 이름

### 3. 순수 함수 - 상태별 그룹화 (`src/lib/backlogTaskGrouping.js`)
- `groupTasksByStatus(tasks)` 함수
- 입력: task 배열 (각 항목 최소 필드: id, title, status, owner)
- 출력: `[{ status: string, tasks: [...] }, ...]` 형태 배열
- 특징:
  - 같은 status끼리 하나의 그룹으로 묶음
  - 그룹 순서는 task 배열에 **처음 등장한** status 순서를 따름 (정렬하지 않음)
  - 이 프로젝트가 모르는 임의의 status 문자열도 그대로 그룹 키가 됨

### 4. 훅 - 소스 파일 읽기 (`src/lib/useBacklogSourceRead.js`)
- `useBacklogSourceRead(path)` 커스텀 훅
- 입력: 등록된 소스의 파일 경로
- 출력: `{ loading, ok, tasks, recognized, skippedCount, error }`
- P14.1의 `BacklogSourceManager.jsx`와 이 P14.2의 `BacklogStatusPanel.jsx` 둘 다에서 사용
- 특징:
  - 마운트/언마운트 시 IPC 호출 자동 관리
  - 경합 방지: 이전 요청이 도중이면 취소 (cancelled 플래그)
  - IPC 자체 거부(전송 실패) 포함 예외 처리

### 5. 통합 (`src/screens/Schedule.jsx`)
- `BacklogStatusSection` 컴포넌트 마운트
- `sources={data.backlog_sources}` prop 전달

### 6. 테스트 스위트
- `src/lib/backlogTaskGrouping.test.js`: vitest 5개 케이스
  - 빈 목록
  - 같은 status 묶음
  - 그룹 순서(처음 등장 순서)
  - 미지 status 값 인식
  - owner 보존
