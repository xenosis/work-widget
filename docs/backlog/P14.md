# P14 — 외부 백로그 소스 대시보드

## 목적

회사의 다른 프로젝트들도 각자의 backlog.json 파일로 작업을 추적합니다. 이 위젯에 그런 다른 프로젝트의 backlog.json 파일들을 등록할 수 있도록 하고, 각 프로젝트의 task 현황을 한눈에 볼 수 있는 대시보드를 일정 화면에 추가합니다. 읽기 전용이며 이 위젯은 다른 프로젝트의 작업 파일을 절대 쓰지 않습니다.

## 쉬운 설명

이 위젯이 개인의 프로젝트/할일/메모/일정을 관리하는 도구라면, P14는 **다른 팀 프로젝트들의 진행 상황도 함께 추적할 수 있도록** 확장하는 작업입니다.

예를 들어:
- 팀 A의 backlog.json: task 50개, 진행 중 30개, 완료 20개
- 팀 B의 backlog.json: task 15개, 진행 중 10개, 완료 5개
- 팀 C의 backlog.json: task 8개, 모두 진행 중

이 모든 것을 이 위젯의 일정 화면에 등록하면, 각 팀의 상태를 한눈에 볼 수 있습니다.

**P14의 두 부분:**
1. **P14.1** (완료됨): 파일을 등록/관리하기 - 다이얼로그로 backlog.json을 고르고, 등록된 목록을 보고, 삭제할 수 있습니다.
2. **P14.2** (이 작업): 등록된 파일들의 실제 task 목록을 보기 - 각 등록 파일별로 task들을 상태(진행, 완료, 보류 등)별로 분류해서 대시보드처럼 표시합니다.

## 필요한 입력

- 사용자 요청: 다른 프로젝트 task 현황을 위젯에서도 보고 싶음
- 기존 코드: 일정 화면(src/screens/Schedule.jsx), 데이터 모델(electron/dataStore.js), 컴포넌트 패턴 (BacklogSourcesSection 등)
- 요구사항 문서(work-widget-requirements.md)의 P14 섹션(B2.4, B3.5 등)

## 결과물

다음 2개 하위 task(P14.1, P14.2)가 모두 `done` 상태가 됨:

- **P14.1** (완료됨): 데이터 모델(`backlog_sources`), IPC 핸들러, 파서, 관리 UI
  - 파일 선택 다이얼로그로 경로 등록
  - 등록된 소스들의 개수/상태 한 줄 요약 표시
  - 읽기 전용 정책 강제

- **P14.2** (이 작업): 대시보드 패널
  - 등록된 모든 소스의 task 목록을 상태별로 분류해서 표시
  - 각 task의 담당자 정보 포함
  - 로딩/오류 처리

## 선행 작업

없음. P14는 이전 작업들(P0~P13, MVP)과 독립적으로 진행 가능합니다. 다만 일정 화면(P5 등)과 데이터 저장 체계(P6 등)가 이미 구현돼 있어야 합니다.

## 수행 순서에서의 위치

P14는 부모 task로, MVP 개선/확장 단계의 일부입니다. 실제 구현 순서는:

1. **P14.1** (완료됨): 파일 등록/관리 기능
2. **P14.2** (이 작업): task 목록 대시보드

P14.2가 완료되면 P14 전체가 종료됩니다. 그 다음 필요한 작업(예: P15, P16 등)은 별도로 결정됩니다.

## done_when을 확인하는 방법

하위 P14.1, P14.2 task의 상태를 확인합니다:

```bash
node scripts/backlog/cli.js list | grep -E '"id": "P14\.[12]"' | grep -E '"status": "(done|cancelled)"'
```

그 결과가 정확히 2줄이면 이 task의 done_when을 충족합니다. 또는 `backlog.json`을 읽어서 P14.1과 P14.2의 status가 모두 done 또는 cancelled임을 직접 확인합니다.

## 확인 필요

없음. 부모 task는 하위 task들의 상태에만 의존합니다.
