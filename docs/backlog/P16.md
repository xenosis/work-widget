# P16 — 일정 화면 캘린더 아래 순서 재배치

## 목적

사용자 피드백(2026-09-26)에 따르면 일정 화면에서 캘린더 바로 아래에 "새 일정 추가" 입력 폼이 있으면 선택한 날짜에 이미 있는 일정을 보기 전에 추가 폼부터 마주치게 되어 가독성이 떨어진다고 합니다. P16은 이를 해결하기 위해 `ScheduleDateDetail` 컴포넌트(선택한 날짜의 일정 목록)를 캘린더/범례 바로 다음으로 올리고, "새 일정 추가" 카드를 그 아래로 내립니다. 로직이나 상태 변화는 없고 순수하게 JSX 배치만 재구성하는 작업입니다.

## 쉬운 설명

일정 화면의 레이아웃을 다시 생각해 봅시다. 원래는:
1. 월간/주간 탭 버튼
2. 캘린더 그리드 (또는 주간 뷰)
3. 범례 (점=카테고리, 테두리=반복 표시)
4. **새 일정 추가 폼** ← 사용자가 먼저 보는 것
5. 선택 날짜의 일정 목록 ← 사용자가 나중에 스크롤해서 봄
6. 외부 백로그 현황 패널

사용자 피드백: "캘린더를 선택했을 때, 먼저 그 날짜에 이미 있는 일정이 뭔지 보고 싶습니다. 지금은 추가 폼이 먼저 보여서 불편해요."

**P16이 하는 일:**

순서를 다음과 같이 바꿉니다:
1. 월간/주간 탭 버튼
2. 캘린더 그리드 (또는 주간 뷰)
3. 범례
4. **선택 날짜의 일정 목록** ← 이제 먼저 보임
5. 새 일정 추가 폼 ← 이제 나중에 보임
6. 외부 백로그 현황 패널 (변경 없음)

다른 화면(프로젝트/할일/메모)처럼 "별도 팝업이나 토글 없이 입력창이 항상 보인다"는 원칙을 유지하되, 순서만 조정합니다.

## 필요한 입력

- **기존 구현**: P5.2(월간/주간 캘린더 뷰), P5.3(뷰 전환), P5.4(일정 추가/수정 폼), P5.6(일정 삭제)이 이미 완료돼 있어야 합니다.
- **컴포넌트들**: `ScheduleDateDetail.jsx`, `ScheduleAddForm.jsx`, `BacklogStatusSection.jsx`가 이미 구현돼 있어야 합니다.
- **작업 순서 지시**: P15(설정 탭 이동)가 이미 완료되어 있어야 일정 화면이 정리된 상태입니다.

## 결과물

- `<ScheduleDateDetail ... />` 블록을 `<p className="schedule-dot-legend">` 범례 아래로 이동
- `<div className="card"> ... <h2>새 일정 추가</h2> ... </div>` 카드를 `<ScheduleDateDetail />` 아래로 이동
- `<BacklogStatusSection ... />`는 변경 없이 맨 아래 유지
- 컴포넌트 임포트, 함수 핸들러(handleAddSchedule, handleEditSchedule, handleDeleteSchedule), 상태 변수 — 모두 그대로

**변경 없는 것들:**
- 로직 (일정 추가/수정/삭제 함수는 동일)
- 상태 (selectedDate, saving 등)
- 이벤트 핸들러 연결
- props 전달
- CSS 스타일

- P15가 먼저 완료되어야 일정 화면이 정리된 상태에서(관리 토글 없이) 이 작업을 진행할 수 있습니다.

## 수행 순서에서의 위치

**작업 분류**: UI 미세 조정 / 사용자 피드백 반영 (2026-09-26 사람 결정)

**타임라인에서의 위치**:
- P15 (설정 탭 추가로 일정 화면 정리) → 완료
- **P16** (일정 화면 내 컴포넌트 순서 재배치) ← 이 작업
- P17 이상 (향후 작업, 아직 미정)

**왜 P15 다음인가:**
- P15에서 일정 화면에서 관리 토글(카테고리, 백로그 소스)을 제거했으므로, 이제 일정 화면이 "캘린더 우선"으로 구성될 수 있습니다.
- P16은 그 정리된 상태에서 최종 순서를 사용자 피드백에 맞춰 조정합니다.

**내부 의존 구조:**
```
P15 (설정 탭 + 일정 화면 정리) ──> P16 (일정 화면 순서 재배치) ──> (다음 작업)
```
