# P2.1 — 프로젝트 목록 카드 UI

## 목적

프로젝트들을 장기/단기로 구분해서 카드 형식으로 표시하여, 사용자가 진행 중인 프로젝트들을 한눈에 볼 수 있도록 한다.

## 쉬운 설명

프로젝트 화면(Projects.jsx)에서 projects 배열의 type 필드("장기"/"단기")로 필터링해서 장기 섹션과 단기 섹션을 별도로 표시한다. 각 프로젝트는 카드로 렌더되며, 프로젝트명, 진행률 바, 마감일, 상태 배지를 포함한다. type이 장기도 단기도 아닌 프로젝트(미분류)는 빨간 경고 문구와 함께 별도로 표시되어 데이터 정합성 문제를 알린다.

## 필요한 입력

- projects 데이터 구조 (work-widget-requirements.md B3.1)
- **P6.1**: calculateProjectProgress 함수 — 각 프로젝트의 진행률(0~100%)을 계산
- **P6.2**: getProjectsByType 또는 groupProjectsByType 함수 — 프로젝트를 type별로 분류
- IPC 데이터 연동 (window.api.loadData)

## 결과물

- Projects.jsx의 목록 보기 화면: 장기/단기 섹션 분리
- ProjectCard.jsx: 각 프로젝트를 나타내는 카드 컴포넌트
- .project-card, .project-card-button 등 CSS 스타일 (src/index.css)
- src/lib/projectGrouping.js: groupProjectsByType 함수와 테스트

## 선행 작업

- **P6.1** (프로젝트 진행률 계산): calculateProjectProgress 함수로 progress(0~100% 정수)를 계산해서 진행률 바에 표시
- **P6.2** (프로젝트 타입 분류): 장기/단기/미분류 그룹핑 로직 필요

## 수행 순서에서의 위치

P2(프로젝트 화면) 내에서 가장 첫 번째 UI 레이아웃 작업이다. P2.1이 완료되면 P2.2(상세 화면 라우팅), P2.3(인라인 추가), P2.4(메모/진행률 요약), P2.5(CRUD IPC)를 순차적으로 진행할 수 있다.

## done_when을 확인하는 방법

1. npm run dev로 앱 실행 후 프로젝트 탭 진입
2. data.json에 장기 프로젝트 2개 + 단기 프로젝트 2개를 다양한 진행률로 시딩
3. 프로젝트 목록 화면에 "장기" 섹션과 "단기" 섹션이 분리되어 나타나는지 확인
4. 각 카드에 프로젝트명, 진행률 바(progress-fill의 width가 진행률과 일치), 마감일, 상태 배지가 표시되는지 확인
5. 진행률이 정확한지 확인 (50% 진행 프로젝트는 progress-fill이 절반 채워짐)
6. type이 '장기 ' (트레일링 스페이스 등) 오타인 미분류 프로젝트는 "미분류 프로젝트" 경고 문구와 함께 별도 섹션에 표시되는지 확인
7. npm test 실행 시 projectGrouping 관련 테스트 35건이 통과하는지 확인
