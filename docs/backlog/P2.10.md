# P2.10 — 프로젝트 삭제 확인 화면 — 소속 todo/memo cascade 삭제 미리보기

## 목적

P2.8에서 결정된 cascade 삭제 정책을 구현한다. 프로젝트 삭제 시 소속 todo와 memo가 함께 자동으로 삭제되는데, 삭제 전에 무엇이 지워질지 사용자에게 미리 보여주는 2단계 확인 화면을 제공한다.

## 쉬운 설명

사용자가 프로젝트를 삭제하려 할 때, 먼저 "이 프로젝트를 삭제하면 할일 3개, 메모 2개가 함께 삭제됩니다"라는 확인 화면이 나타난다. 삭제될 할일의 제목 목록과 메모 개수를 구체적으로 보여줘서 사용자가 정말로 의도한 것인지 확인하게 한다. 사용자가 "삭제" 버튼을 클릭하면 프로젝트 + 소속 할일 + 소속 메모가 모두 data.json에서 제거되며, 재시작 후에도 삭제된 상태로 유지된다.

## 필요한 입력

- P2.5 완료: 프로젝트 CRUD UI (수정/삭제 폼 구조)
- P2.8 완료: cascade 삭제 정책 결정 (프로젝트 삭제 시 소속 항목들을 자동으로 함께 제거)
- projects/todos/memos 배열: 프로젝트 ID로 소속 항목들을 조회하기 위해 필요

## 결과물

- DeleteProjectButton: 2단계 삭제 확인 UI (ProjectEditForm.jsx에 포함)
- 첫 단계: "프로젝트 삭제" 버튼 클릭 시 확인 여부 묻기
- 두 번째 단계: 삭제될 할일 제목 목록 + 메모 개수 표시 후 최종 확인
- src/lib/projectMutations.js: removeProjectCascade 함수 (프로젝트+소속 todo/memo 동시 제거)
- src/lib/projectMutations.test.js: removeProjectCascade 테스트 (9개)
- src/index.css: 삭제 확인 UI 관련 스타일

## 선행 작업

- **P2.5** (프로젝트 CRUD IPC): 프로젝트 삭제 폼과 handleDeleteProject 함수가 필요
- **P2.8** (고아 todo/memo 처리 정책 결정): cascade 삭제 정책 결정 후 구현

## 수행 순서에서의 위치

P2.5/P2.8 완료 직후에 진행되는 마무리 작업이다. P2.10 완료 후 P2.6(단기 프로젝트 전용 뷰)을 진행할 수 있다.

## done_when을 확인하는 방법

1. npm run dev로 앱 실행 후 프로젝트 화면에서 프로젝트 추가 및 할일 2개, 메모 1개 추가
2. 그 프로젝트의 상세 화면에서 삭제 버튼 클릭
3. 첫 번째 확인 화면 표시 ("정말 삭제하시겠습니까?")
4. "확인" 또는 "계속" 클릭하면 두 번째 화면 표시 ("할일 2개, 메모 1개가 함께 삭제됩니다")
5. 두 번째 화면에서 삭제될 할일의 제목이 구체적으로 목록으로 표시되는지 확인
6. "삭제" 버튼 클릭 후 프로젝트가 목록에서 사라지는지 확인
7. 같은 프로젝트의 할일전체 화면(Todos.jsx)에서도 해당 할일들이 사라지는지 확인
8. 앱을 종료했다가 재시작한 후에도 프로젝트/할일/메모가 사라진 상태로 유지되는지 확인
9. npm test 실행 시 projectMutations 관련 테스트(removeProjectCascade 등)가 통과하는지 확인
