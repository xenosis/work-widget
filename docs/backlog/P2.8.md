# P2.8 — 프로젝트 삭제 시 고아 todo/memo 처리 정책 결정

## 목적

프로젝트를 삭제할 때 그 프로젝트에 속한 todo와 memo의 고아 레코드 문제를 어떻게 처리할지 정책을 정한다.

## 쉬운 설명

프로젝트를 삭제하면 현재 그 프로젝트에 소속된 할일과 메모는 data.json에 그대로 남겨져 고아 레코드가 된다. 이를 어떻게 처리할지 결정해야 한다: (1) cascade 삭제, (2) project_id를 null로 변경, (3) 경고만 강화.

## 필요한 입력

- work-widget-requirements.md B3.2 (todo/memo의 project_id 규정)
- P2.5의 handleDeleteProject 코드
- 사용자의 정책 선택

## 결과물

정책 선택에 따른 구현 방향 결정

## 선행 작업

- P2.5: 프로젝트 삭제 기능

## 수행 순서에서의 위치

P2의 마지막 정책 결정 작업

## done_when을 확인하는 방법

사용자(제품 관리자)가 세 가지 옵션 중 하나를 선택하고, 그에 따른 구현 계획이 기록됨

## 확인 필요

1. 프로젝트 삭제 시 실제로 고아 레코드가 발생하는가?
2. 사용자의 선호 정책이 무엇인가?
