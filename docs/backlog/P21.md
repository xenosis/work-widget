# P21 — 일정 탭: 새 일정 추가 폼을 버튼 클릭 시에만 표시

## 목적

사용자가 일정 화면에서 새 일정 추가 폼이 항상 펼쳐져 있어 지나치게 많은 수직 공간을 차지한다고 지적했습니다. 이 폼을 기본적으로 숨기고, 사용자가 "새 일정 추가" 버튼을 클릭했을 때만 펼치도록 변경합니다. 이는 P16의 초기 결정(항상 보이는 입력 방식)을 의도적으로 뒤집는 결정이지만, 사용자가 그 트레이드오프를 알고도 다시 요청했고, 일정 화면이 다른 화면들보다 항목 밀도가 높아 공간 부족이 실제 문제이기 때문입니다.

## 쉬운 설명

지금까지 일정 화면을 열면 맨 아래 "새 일정 추가" 입력 폼이 항상 펼쳐져 있었습니다:
- 소제목, 날짜, 시간, 내용, 반복 설정 등 여러 필드를 한눈에 볼 수 있어 편리했지만
- 그 폼이 차지하는 공간(약 250~300px) 때문에 위의 캘린더나 일정 목록을 보기 위해 자주 스크롤해야 했습니다.

**P21이 하는 일**:
1. **폼을 기본으로 숨김**: 일정 화면에 진입하면 "새 일정 추가" 폼이 안 보임
2. **버튼으로 토글**: 화면 위쪽에 "새 일정 추가" 버튼 추가
3. **버튼 클릭 시 펼침**: 버튼을 누르면 폼이 나타나고, 사용자가 일정을 추가하거나 다시 버튼을 누르면 접힘
4. **다른 요소는 변화 없음**: 캘린더, 날짜별 상세 보기, 일정 목록 등 모든 것은 원래대로 동작

## 필요한 입력

- **기존 구성 요소**: `ScheduleAddForm.jsx` 컴포넌트가 이미 작성되어 있어야 함
- **상태 관리 기초**: `src/screens/Schedule.jsx`에서 폼의 표시/숨김을 제어하는 state(예: `showAddForm`)를 추가할 수 있는 구조
- **스타일 재사용 가능성**: 버튼 토글 스타일은 프로젝트 내 이미 존재하는 토글 버튼 패턴(예: `.schedule-category-manager-toggle`)을 재사용 가능해야 함

## 결과물

### 1. Schedule.jsx의 상태 추가
- `showAddForm` state 추가 (기본값: `false`)
- `setShowAddForm` 토글 함수 추가

### 2. 토글 버튼 렌더링
- "새 일정 추가" 버튼을 화면 내 적절한 위치(예: 캘린더 아래, 폼이 있던 위치)에 표시
- 버튼을 클릭하면 `showAddForm` 상태를 반전
- 버튼의 스타일은 기존 프로젝트의 토글 버튼 클래스(예: `.schedule-category-manager-toggle`)를 재사용하거나 유사한 패턴 적용

### 3. ScheduleAddForm의 조건부 렌더링
- `showAddForm`이 `true`일 때만 `<ScheduleAddForm />` 컴포넌트 렌더
- `showAddForm`이 `false`일 때는 버튼만 표시

### 4. 폼 닫힘 로직
- 일정을 성공적으로 추가한 후 폼 자동 접힘 (기존 동작이면 충분)
- 또는 "취소" 버튼이나 폼의 X 버튼을 누르면 접힘

### 5. CSS (필요 시에만)
- 버튼 스타일이 기존 토글 패턴과 일치하려면 추가 CSS는 최소화
- `.schedule-add-form-button` 또는 유사 클래스로 버튼의 시각적 상태(기본/hover/활성) 정의

## 선행 작업

### deps 배열
- **deps 없음** — 이미 ScheduleAddForm, Schedule.jsx 등 모든 필요한 컴포넌트가 구현되어 있으며, 단순히 상태 추가와 조건부 렌더링만 필요

### 왜 선행 작업이 없는가
- 일정 화면의 핵심 기능(캘린더, 일정 추가/수정/삭제, 반복 설정)은 모두 P5~P12 단계에서 완성됨
- P21은 그 기능을 변경하지 않고, UI 공간 활용만 개선하는 작업
