# P22 — 스크롤바 전체 앱 다크 테마 적용

## 목적

사용자가 창을 작게 했을 때나 목록이 길어서 스크롤이 필요한 경우, 스크롤바가 Windows의 기본 밝은 색상 그대로 나타나 앱의 다크 글래스 테마와 시각적으로 어울리지 않는다고 지적했습니다. P19에서 사이드바(`.sidebar`)에만 한정해 적용한 웹킷 기반 커스텀 스크롤바를 앱 전체로 확장하여, 메인 콘텐츠 영역, 팝오버(DueDatePicker 달력), 목록 오버플로우 등 스크롤이 발생하는 모든 곳에 일관된 다크 테마 스크롤바를 적용합니다.

## 쉬운 설명

앱의 사이드바와 메인 콘텐츠 영역은 어두운 색상(다크 글래스 테마)으로 디자인되어 있지만:
- 창이 작아지거나 목록이 길어서 스크롤바가 나타날 때
- Windows 기본 밝은 회색 스크롤바가 뜨는 바람에
- 테마의 일관성이 깨집니다.

**P22가 하는 일**:
1. **전역 웹킷 스크롤바 적용**: CSS의 `::-webkit-scrollbar` 의사 요소를 `index.css`에 추가
2. **스크롤바 색상 통일**: 스크롤바 트랙(배경)과 썸(움직이는 부분)을 앱의 기존 다크 토큰으로 칠함
3. **기존 색 토큰 재사용**: 새 색을 정의하지 않고 `--track-bg`, `--card-border`, `--text-faint` 같은 이미 정의된 토큰 활용
4. **사이드바는 별도 유지**: 사이드바는 폭이 더 좁은 자체 규칙(4px)을 그대로 두고, 색은 전역 규칙을 물려받음

## 필요한 입력

- **기존 CSS 토큰**: `src/index.css`에 이미 정의된 CSS 커스텀 프로퍼티
  - `--track-bg`: 진행률 막대 트랙 색상 (스크롤바 트랙으로 재사용)
  - `--card-border`: 카드 테두리 색상 (스크롤바 썸으로 재사용)
  - `--text-faint`: 비활성 텍스트 색상 (스크롤바 썸 hover 상태로 재사용 가능)
- **스타일 적용 대상 확인**: `.content` 메인 영역, DueDatePicker 팝오버, 할일 태그 목록 등 `overflow-y: auto` 또는 `overflow-y: scroll`이 있는 모든 컨테이너

## 결과물

### 1. 전역 스크롤바 스타일 추가 (`src/index.css`)

#### 웹킷 기반 (Chromium/Electron 지원)
```css
::-webkit-scrollbar {
  width: 8px;  /* 스크롤바 전체 폭 */
}

::-webkit-scrollbar-track {
  background: var(--track-bg);  /* 트랙(배경) 색상 */
}

::-webkit-scrollbar-thumb {
  background: var(--card-border);  /* 썸(움직이는 부분) 기본 색상 */
  border-radius: 4px;
}

::-webkit-scrollbar-thumb:hover {
  background: var(--text-faint);  /* 썸 hover 상태 */
}

::-webkit-scrollbar-corner {
  background: var(--track-bg);  /* 모서리 배경 */
}

::-webkit-resizer {
  background: var(--track-bg);  /* textarea 리사이저 배경 */
}
```

#### 표준 CSS (향후 호환성)
```css
* {
  scrollbar-width: thin;
  scrollbar-color: var(--card-border) var(--track-bg);
}
```

### 2. 사이드바 예외 규칙 유지
```css
.sidebar::-webkit-scrollbar {
  width: 4px;  /* 사이드바는 더 좁게 유지 */
}
/* 색상은 전역 규칙 물려받음 */
```

### 3. 적용 범위
- **메인 콘텐츠 영역** (`.content`)
- **프로젝트 카드 내부 목록** (오버플로우 있는 경우)
- **할일 태그 입력 목록** (오버플로우 있는 경우)
- **DueDatePicker 팝오버** (달력 그리드)
- **메모 목록** (overflow 있는 경우)
- **사이드바** (기존 4px 폭 유지, 색상만 전역 규칙 적용)

### 4. 스타일의 브라우저 호환성 고려
- **Electron 내장 Chromium**: `::-webkit-scrollbar` 완전 지원 ✓
- **표준 CSS** (`scrollbar-width`, `scrollbar-color`): Electron에서도 일부 지원되지만, 주요 구현은 웹킷 기반으로 진행
- **Firefox/Safari**: 프로젝트가 Electron 전용이므로 호환성 우려 없음

## 선행 작업

### deps 배열
- **deps 없음** — CSS 토큰이 이미 `src/index.css`에 정의되어 있으며, 새로운 기능이나 API 추가가 필요 없음

### 왜 선행 작업이 없는가
- P22는 순수 CSS 스타일링 작업
- 기존 토큰(`--track-bg`, `--card-border` 등)을 재사용하므로 새로운 데이터/기능 준비 불필요
- 사이드바와 메인 콘텐츠 구조는 이미 안정적으로 작동 중
