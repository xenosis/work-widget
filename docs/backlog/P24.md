# P24 — 백로그 상태별 전체 목록: 이번 주 변경 항목 색상 구분 + 50개 cap 예외

## 목적

사용자가 백로그 탭의 상태별 전체 목록을 볼 때, "이번 주 상태가 바뀐 항목"을 다른 글자색으로 표시해서 전체 목록 안에서 어떤 항목이 변경됐는지 한눈에 알아볼 수 있게 하려는 요청입니다. 동시에, 이 프로젝트의 백로그(105개)처럼 상태 그룹당 50개를 넘는 외부 백로그를 쓸 때 문제가 발견됐습니다 — 변경된 항목이 51번째 이후에 있으면 글자색으로 구분해도 보이지 않아 의미가 없다는 것이었습니다. 이를 해결하기 위해 변경 항목은 50개 제한(cap)에서 예외로 두고 항상 표시하는 방식으로 개선합니다.

## 쉬운 설명

백로그 화면(다른 프로젝트의 작업 추적 파일을 읽어서 보는 탭)에서 상태별로 항목들을 나열할 때:

**이전 상황**:
- 각 상태 그룹마다 최대 50개까지만 표시했음
- 51번째 이후 항목은 "외 N개" 로 감춰짐
- 이번 주 상태가 바뀐 항목이 51번째 이후에 있으면 화면에 안 보였음

**P24가 하는 일**:
1. **색상 표시**: 이번 주에 상태가 바뀐 항목들을 다른 글자색(주의색, `--priority-mid-text`)으로 표시
2. **cap 예외 처리**: 바뀐 항목(added/statusChanged)은 50개 제한을 받지 않고 항상 표시
3. **안 바뀐 항목에만 제한 적용**: 상태가 안 바뀐 나머지 항목들만 처음 50개까지만 표시

**중요한 구분**:
- 색상 표시는 **상태가 바뀐 항목(statusChanged)에만** 적용
- 새로 추가된 항목(added)은 이미 위에 "이번 주 변경 사항" 섹션에서 따로 표시되므로, 추가로 색 구분을 하지 않음(사용자가 명시적으로 이렇게 요청)

## 결과물

### 1. 새 순수 함수 추가: `selectGroupDisplayTasks()` (`src/lib/backlogTaskGrouping.js`)

```javascript
export function selectGroupDisplayTasks(tasks, changedIds, cap) {
  const unchanged = tasks.filter((t) => !changedIds.has(t.id));
  const cappedUnchangedIds = new Set(unchanged.slice(0, cap).map((t) => t.id));
  const displayed = tasks.filter((t) => changedIds.has(t.id) || cappedUnchangedIds.has(t.id));
  return { displayed, hiddenCount: unchanged.length - cappedUnchangedIds.size };
}
```

**역할**:
- `tasks`: 같은 상태 그룹의 모든 항목 배열
- `changedIds`: 이번 주에 변경된 항목의 id 집합(Set)
- `cap`: 안 바뀐 항목의 최대 표시 개수(50)
- **반환**: `{ displayed, hiddenCount }`
  - `displayed`: 실제로 화면에 보일 항목 배열 (바뀐 항목 전부 + 안 바뀐 항목 처음 cap개)
  - `hiddenCount`: 감춘 안 바뀐 항목의 개수

**중요한 설계**:
- 원래 배열의 순서 유지 (바뀐 항목을 앞으로 끌어올리지 않음)
- 바뀐 항목 개수는 제한 없음 (대량 변경이 한 번에 일어나지 않는다는 가정에 기반)
- Vitest로 3가지 케이스 테스트 (무언가 바뀐 경우, cap 초과, 전부 바뀐 경우 등)

### 2. BacklogSourceCard.jsx 렌더링 로직 수정

**이번 주 변경된 항목 id 집합 준비**:
```javascript
const statusChangedIds = new Set(changes.statusChanged.map((t) => t.id));
const capExemptIds = new Set([...changes.added, ...changes.statusChanged].map((t) => t.id));
```

- `statusChangedIds`: 색상 표시용 (statusChanged만)
- `capExemptIds`: cap 예외용 (added + statusChanged, 둘 다)

**상태 그룹 렌더링 시 적용**:
```javascript
const { displayed, hiddenCount } = selectGroupDisplayTasks(g.tasks, capExemptIds, MAX_TASKS_PER_GROUP);
```

**색상 클래스 조건부 적용**:
```jsx
<li className={statusChangedIds.has(t.id) ? 'backlog-status-task-row is-changed' : 'backlog-status-task-row'}>
  <span className="backlog-status-task-title">{t.title}</span>
  {t.owner && <span className="backlog-status-task-owner">{t.owner}</span>}
</li>
```

### 3. CSS 스타일 추가 (`src/index.css`)

새 색 토큰을 만들지 않고 기존 `--priority-mid-text`(주의/변경색) 재사용:

```css
.backlog-status-task-row.is-changed .backlog-status-task-title {
  color: var(--priority-mid-text);
}
```

**색 토큰 정보**:
- `--priority-mid-text`: oklch(80% 0.13 85) — 주의/변경을 뜻하는 주황 톤
- 이미 다른 곳(`.priority-chip.mid`)에서 쓰이는 기존 토큰이라 일관성 유지
