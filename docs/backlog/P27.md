# P27 — scripts/backlog: task별 선택적 목표일(due_date) 필드 추가

## 목적

Backlog 기반으로 개발 일정을 관리하려면, 각 task가 목표 마감일(due_date)을 담을 수 있어야 합니다. 현재 backlog task 스키마에는 날짜 관련 필드가 전혀 없어서, 같은 스키마를 쓰는 다른 프로젝트(예: TimeTable)에서 마감일을 기록하려다 보니 방법이 없는 상황입니다. 이 task는 이 프로젝트(TaskDock) 자신의 backlog 스키마에 선택적 목표일 필드 하나를 추가해, CLI에서 task 생성/수정 시 마감일을 지정할 수 있게 만듭니다.

## 쉬운 설명

지금까지 backlog의 각 task는 제목, 설명, 의존성, 우선순위, 카테고리 같은 정보를 가지고 있었지만, "언제까지 해야 하는가"라는 마감일(due date) 정보는 전혀 담을 수 없었습니다.

이 task에서는:
- task 스키마에 `due_date`라는 새로운 필드를 추가합니다(선택적이라 필수가 아님)
- 형식은 `2026-10-05` 같은 YYYY-MM-DD 문자열이거나 비어있을 수 있습니다(null)
- 기존 task들(이 필드가 없던 시대의 task들)은 자동으로 `due_date: null`로 채워집니다
- `add` 명령에서 `--due_date=2026-10-05`로 새 task를 만들 때 지정 가능합니다
- `set-field` 명령에서도 `--due_date=2026-10-05`로 기존 task의 마감일을 나중에 추가/수정할 수 있습니다
- 잘못된 날짜(예: `2026-13-45`, 존재하지 않는 달/일)는 CLI가 거부합니다

참고: 이 필드 추가는 이 프로젝트(TaskDock) 자신의 backlog에만 적용되며, TimeTable 같은 다른 저장소의 backlog는 이 변경과 무관합니다(그쪽은 그쪽이 자신의 저장소에서 같은 작업을 별도로 해야 함).

## 결과물

다음 파일들이 수정되거나 신규 생성됨:

1. **scripts/backlog/lib/schema.js** (수정)
   - `isValidDueDate(value)` 함수 추가
     - null 값: 유효(선택적 필드이므로)
     - 문자열: `YYYY-MM-DD` 정규식 형태 확인 + 실제 존재하는 날짜인지 검증(예: 2026-02-30은 형태는 맞지만 존재하지 않아 거부)
     - 그 외 타입: 거부
   - **critical-reviewer 지적 반영**: validateSchema 함수에도 due_date 형식 검증 추가
     - 기존에는 addTask/setField(쓰기 경로)에만 검증이 있어서, 손 편집이나 다른 도구로 잘못된 값이 들어와도 list/show 명령이나 validate-backlog 훅의 validateSchema는 조용히 통과시킬 수 있었음
     - 이제 validateSchema도 due_date가 있으면 isValidDueDate로 검증하므로, 파일에서 읽기만 해도 형식 검증이 보장됨
     - 회귀 테스트 2개 추가(validateSchema 직접 호출로 due_date 검증 확인)

2. **scripts/backlog/lib/store.js** (수정)
   - `readBacklogFile` 함수 수정
   - 파일에서 task를 읽을 때마다, `due_date` 키가 없는 기존 task(P1~P26)를 만나면 자동으로 `due_date: null`로 채움
   - 이미 값이 있는 task의 `due_date`는 절대 건드리지 않음
   - **critical-reviewer 지적 정정**: 정규화된 결과(메모리 상의 객체)는 다음 변경 명령(예: set-status, set-field 등 어떤 task를 고치든)을 실행할 때 전체 backlog.json으로 다시 저장되므로, 기존 task도 결국 디스크에 `due_date: null`이 실제로 기록됨(한 번의 변경 diff가 파일 전체 크기로 나타남). 동작 자체는 문제없음(해시는 원본 텍스트 기준이므로 동시성 검사에 영향 없음), 코드 주석만 명확하게 정정

3. **scripts/backlog/lib/mutations.js** (수정)
   - `addTask` 함수 수정
   - `--due_date=` 입력값 검증(isValidDueDate로 확인)
   - 형식이 잘못되면 CLI 오류 메시지로 거부
   - 정상이면 새 task의 `due_date` 필드에 저장

4. **scripts/backlog/lib/fieldMutations.js** (수정)

   - 같은 검증 규칙 적용(mutations.js와 동일한 isValidDueDate 사용)

5. **scripts/backlog/cli.js** (수정)
   - `add` 및 `set-field` 명령의 --help 출력에 `--due_date=YYYY-MM-DD` 옵션 문서화

6. **테스트 파일들** (신규/확장, 총 50개 테스트 케이스)
