# P28 — 백로그 유래 목표일을 일정 탭 캘린더에 읽기 전용으로 표시

## 목적

TaskDock의 일정 탭(Schedule)은 현재 이 위젯 자신의 데이터만 관리합니다. 하지만 사용자가 다른 프로젝트의 backlog.json(예: TimeTable)을 등록해 외부 작업 현황을 모니터링할 때, 그 외부 작업 중에 목표일(due_date, P27에서 추가됨)이 있는 것들을 일정 탭 캘린더에도 함께 표시할 수 있다면, 한 곳에서 모든 일정(자신의 일정 + 외부 작업 마감)을 한눈에 관리할 수 있게 됩니다. 이 task는 그 통합을 구현합니다.

## 쉬운 설명

현재까지:
- 일정 탭의 캘린더는 TaskDock의 자신의 일정(`Schedule` 데이터)만 보여줍니다.
- 백로그 탭에서는 등록된 외부 backlog(.json) 파일들(TimeTable 같은 다른 프로젝트)의 작업 현황을 별도로 봅니다.

이 task에서는:
- 외부 backlog(.json)에 있는 작업 중에서 `due_date`(목표일)를 가진 것들을 읽어옵니다.
- 그 작업들을 일정 탭의 캘린더에 "그 날짜의 항목"으로 함께 표시합니다(자신의 일정 옆에).
- 시각적으로 외부 작업임을 구분할 수 있게 표시합니다(각진 작은 사각형 모양 + 무채색으로 카테고리 점과 구분).
- **중요**: 이 항목은 읽기 전용입니다. TaskDock 화면에서 직접 수정, 삭제, 체크할 수 없습니다. 원본 파일을 다시 읽어야만 변경이 반영됩니다(B3.5의 "읽기 전용" 원칙).

예시:
- 외부 프로젝트 TimeTable의 backlog에 "2026-10-15 보고서 제출"이라는 작업이 있다면
- TaskDock의 일정 탭 캘린더에서 2026-10-15 셀에 그 작업이 외부 항목임을 알 수 있게 함께 표시됩니다.
- 하지만 TaskDock 화면에서 "완료" 체크나 수정은 할 수 없고, 원본 backlog.json을 다시 읽어야만 변경 상태가 반영됩니다.

## 필요한 입력

- **P27이 완료된 backlog 스키마** — backlog task에 `due_date` 필드가 있어야 합니다
- **등록된 backlog_sources** — 최소 1개 이상의 외부 backlog(.json) 경로가 TaskDock에 등록되어 있어야 합니다
- **electron/backlogSourceReader.js** — 외부 backlog 파일을 읽는 모듈(이미 존재)
- **src/lib/scheduleGrid.js** — 캘린더 표시 데이터를 만드는 순수 함수 모음(이미 존재)
- **src/components/Schedule*.jsx** — 일정 탭의 렌더러 컴포넌트들(ScheduleMonthView, ScheduleWeekView, ScheduleDateDetail 등, 이미 존재)
- **src/index.css** — 스타일시트(이미 존재, 외부 항목 표시용 새 클래스 추가 예정)

## 수행 순서에서의 위치

P28은 "백로그 기반으로 프로젝트 개발 일정 관리" 기능(P25~P28)의 마지막 조각입니다.

**이전 단계**:
- **P25**: 일주일간의 변화를 감지해 주간보고 텍스트를 생성하는 백엔드 모듈
- **P26**: 그 주간보고를 화면에 표시하는 UI
- **P27**: backlog task에 due_date 필드 추가(이 task의 선행작)

**이 task가 완료되면**:
- 사용자가 다른 프로젝트의 backlog를 등록하고, 그 작업들의 마감일을 일정 탭 캘린더에서 한눈에 볼 수 있게 됩니다
- 자신의 일정 + 외부 작업 마감을 한 화면에서 관리할 수 있어, "개발 일정 관리"의 원래 목표가 완성됩니다
- **P25/P26/P27/P28이 모두 완료됨에 따라**, 사용자가 원했던 "백로그 기반 개발 일정 관리"와 "주간보고 자동화"라는 두 가지 큰 목표의 뼈대가 이제 전부 갖춰졌습니다(향후 세부 개선은 별도의 task로 진행)
- **이 이후**: 더 이상 의존하는 task가 없으므로, 별도의 후속 기능은 없습니다(다른 feature는 별도의 PR/task로 진행)

## 확인 필요

   - 백로그 탭(`BacklogSourceCard`)과 달리, 일정 탭에서는 읽기 실패한 소스를 조용히 무시합니다(에러 표시 없음)

   - 필요시 외부 항목용 별도 필터/토글 추가 가능(현재는 범위 밖)

   - 이 기능은 이 TaskDock 프로젝트 자신의 backlog(.json)에서만 동작합니다
