# P29 — 트레이 메뉴에 완전 종료/자동 실행 토글 추가

## 목적

TaskDock은 원래 B5.1(창 닫기 = 트레이로 숨김)과 B5.2("별도 종료 메뉴 없음") 결정에 따라 설계되었으므로, 사용자가 앱을 마치려면 Windows 종료 시점까지 기다리거나 작업 관리자에서 직접 프로세스를 끝내야 했습니다. 그런데 2026-09-27 개발 과정에서 사용자 피드백이 들어왔습니다: 패키지를 자주 재빌드·재실행하는 과정에서 "매번 작업 관리자를 열어야 한다"는 번거로움 때문에 **이 결정을 사용자가 직접 번복**한 것입니다. 

이에 따라 트레이 메뉴에 다음 두 기능을 추가합니다:

1. **"완전히 종료"** — 트레이로 숨기지 않고 프로세스를 실제로 종료
2. **"Windows 시작 시 자동 실행" 체크박스** — 사용자가 작업 관리자/Windows 설정 없이 시작 프로그램 등록을 직접 제어(B5.4의 `openAtLogin` 설정을 트레이에서 바로 토글)

이로써 개발/실사용 과정에서 빠른 프로세스 관리와 시작 프로그램 제어를 한 메뉴에서 모두 할 수 있게 됩니다.

## 쉬운 설명

**지금까지 (B5.1/B5.2 당시)**:
- 창의 닫기(X) 버튼을 누르면 프로세스가 종료되지 않고 창만 숨겨져 트레이 아이콘만 남습니다.
- 앱을 완전히 끝내려면 Windows를 종료할 때까지 기다리거나 작업 관리자를 직접 열어서 프로세스를 강제 종료해야 합니다.
- 시작 프로그램 등록(Windows 자동 실행)을 켜거나 끄려면 Windows 설정 앱으로 가야 합니다.

**이 task에서 추가된 것**:
- 트레이 아이콘을 마우스 우클릭하면 메뉴가 나타나고, 다음 항목들이 있습니다:
  - "열기/숨기기" — 창을 표시하거나 숨김
  - **"완전히 종료"** — 클릭하면 프로세스가 정말로 끝남(프로세스 생존하지 않음)
  - **"Windows 시작 시 자동 실행"** — 체크박스로, Windows 부팅 시 이 앱이 자동으로 시작될지 여부를 직접 제어

**실제 개발 과정에서 발견되고 수정된 버그들**:
- 개발 모드(`npm run dev`)에서 실수로 자동 실행 체크박스를 누르면, "개발용 electron.exe 자체"가 Windows 시작 프로그램에 등록되는 부작용이 생길 수 있었습니다 (실제 패키지된 앱이 아니라 개발 환경의 임시 실행 파일 등록) — 이를 방지하기 위해 **개발 모드에서는 이 체크박스를 회색으로 비활성화**하도록 개선했습니다. 이미 이 프로젝트의 다른 부분(P7.2 configureAutoLaunch)에서 `app.isPackaged`로 이런 가드를 하고 있었는데, 새로 추가한 메뉴에서 그걸 빠뜨렸다가 리뷰에서 잡혔습니다.
- 앱이 처음 켜질 때 "트레이 메뉴부터 만들고 그 다음에 자동 실행을 등록"하는 순서였으므로, 초기 실행 시점에 메뉴 화면(체크 안 됨)과 실제 상태(자동 실행 켜져있음)가 어긋나는 버그가 있었습니다 — 사용자가 끄려고 체크박스를 눌러도 반영이 안 돼서 두 번 눌러야 실제로 꺼지는 혼란스러운 상황입니다. **두 함수의 실행 순서만 바꿔** (자동 실행 등록 먼저, 그 다음 메뉴 생성) 해결했습니다.

## 필요한 입력

- **B5.1이 완성된 트레이 구조** — `electron/main.js`에 이미 트레이 아이콘이 만들어져 있어야 하고, 트레이에서 창을 보이거나 숨기는 클릭 핸들러가 구현돼 있어야 합니다.
- **B5.1의 "창 닫기 = 트레이로 숨김" 동작** — `app.on('before-quit', ...)` 리스너와 `mainWindow.on('close', ...)` 핸들러가 이미 있어야 합니다. 특히 `if (!app.isQuitting) { event.preventDefault(); mainWindow.hide(); }` 패턴이 실장돼 있어야 합니다.
- **B5.4의 자동 실행 설정** — `app.setLoginItemSettings()`와 `app.getLoginItemSettings()`가 `electron/main.js`나 `electron/autoLaunch.js`에서 이미 호출 가능해야 합니다.
- **Electron의 Menu API** — `electron`에서 제공하는 `Menu.buildFromTemplate()` 등의 메뉴 생성 함수 사용 가능성.

## 결과물

다음 파일들이 수정되거나 신규 생성됩니다:

### 1. **electron/trayMenu.js (신규)**
   - 두 함수를 내보냅니다:
     - `buildTrayMenuTemplate({ openAtLogin, autoLaunchToggleEnabled, onToggleVisibility, onToggleAutoLaunch, onQuit })` —
       순수 함수(electron을 직접 부르지 않음). 어떤 상태(체크/활성화 여부)를 가질지와 클릭 시
       어떤 콜백을 부를지만 결정해 템플릿 배열을 돌려주므로 vitest로 단위 테스트 가능합니다.
     - `buildTrayMenu({ getMainWindow })` — 실제 Electron `app`/`Menu`를 불러 위 순수 함수에
       진짜 콜백(`app.quit()` 등)을 연결하고 `Menu.buildFromTemplate()`로 실제 메뉴를 만드는
       얇은 층(이 부분만 electron 의존이라 vitest 대상에서 뺌).
   - 메뉴 항목 5개:
     1. "열기/숨기기" — 창 표시/숨김 토글
     2. 구분선
     3. "Windows 시작 시 자동 실행" — 체크박스, `getLoginItemSettings().openAtLogin` 상태 반영, 클릭 시 `setLoginItemSettings()` 호출
     4. 구분선
     5. "완전히 종료" — `app.quit()` 호출

## done_when을 확인하는 방법

다음을 모두 만족해야 완료입니다:

1. **트레이 메뉴 구조 확인**
   - 트레이 아이콘 우클릭 시 컨텍스트 메뉴가 나타나고, 정확히 5개 항목 존재:
     - "열기/숨기기" (type: normal)
     - 구분선 (type: separator)
     - "Windows 시작 시 자동 실행" (type: checkbox)
     - 구분선 (type: separator)
     - "완전히 종료" (type: normal)

2. **"Windows 시작 시 자동 실행" 체크박스 상태 반영**
   - 초기 체크 상태가 `app.getLoginItemSettings().openAtLogin` 값과 일치

3. **"열기/숨기기" 동작**
   - 메뉴 항목 클릭 시 창이 표시 중이면 숨겨지고, 숨겨진 상태면 다시 표시됨
   - 토글이 실제로 동작함을 Playwright 또는 수동 확인

4. **"완전히 종료" 동작**
   - 메뉴 항목 클릭 시 프로세스가 실제로 종료됨 (exit code 0)
   - 트레이 아이콘과 창이 모두 사라짐

5. **자동 실행 체크박스 개발 모드 가드**
   - `npm run dev` (개발 모드)에서는 "Windows 시작 시 자동 실행" 체크박스가 회색으로 비활성화되어야 함
   - 클릭해도 아무 일도 일어나지 않음(상태 변경 없음)
   - 패키지 빌드(`npm run dist`)로 실행하면 체크박스가 활성화되어 정상 작동함

6. **Lint/Vitest/Build 통과**
   ```bash
   npm run lint      # ESLint 통과, exit code 0
   npm test          # vitest 전체 통과 (trayMenu.test.js 7개 신규 포함, vitest 388개 전체)
   npm run build     # vite build 성공, exit code 0
   ```

## 확인 필요

1. **"Windows 시작 시 자동 실행" 체크박스의 실시간 반영 한계**
   - 이 체크박스는 **메뉴가 처음 만들어질 때** (앱 시작 시점)의 `getLoginItemSettings().openAtLogin` 값을 한 번 읽습니다.
   - 이후 사용자가 Windows 설정 앱에서 직접 시작 프로그램 등록을 켜거나 끄면, 이 앱의 체크박스는 그 변경을 **실시간으로 반영하지 못합니다**.
   - 앱을 재시작해야 최신 상태를 반영합니다.
   - 이것이 의도된 설계인지(트레이 메뉴는 정적 갱신), 아니면 향후 메뉴를 동적으로 갱신해야 하는지는 명확하지 않습니다.

2. **Playwright 검증 범위**
   - 실제 프로세스 종료(exit code 확인), 창 표시/숨김 토글, 체크박스 상태·활성화 여부 반영은 Playwright(`_electron` + `app.evaluate`)로 자동화 검증했습니다.
   - 이때 사용한 스크립트는 검증 후 삭제한 스크래치 파일이라 저장소에 커밋돼 있지 않습니다 — 재현하려면 `global.__mainProcessTestHooks.buildTrayMenu`를 통해 동일한 방식으로 다시 작성해야 합니다.

3. **Critical-reviewer 리뷰 완료**
   - 이 task의 critical-reviewer 리뷰가 이미 완료되었으며, 모든 지적(High 1건+Medium 4건)이 반영되었습니다.
   - 더 이상 대기 중인 리뷰는 없습니다.
