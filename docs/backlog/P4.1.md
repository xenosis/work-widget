# P4.1 — 목록/편집 2단 레이아웃

## 목적

메모 화면의 레이아웃을 구현한다. 좌측에 메모 목록, 우측에 편집 창을 배치하고, 목록의 메모를 클릭하면 우측 편집창이 전환되도록 한다.

## 쉬운 설명

좌측-우측 2단 레이아웃 구성: 좌측은 메모 목록(비율 기반 폭), 우측은 나머지 영역을 차지하는 편집 창(제목 입력 + 본문 textarea). 좌측 목록에서 메모를 클릭하면 우측 편집창의 내용이 해당 메모로 전환된다. "+ 새 메모" 버튼으로 빈 메모를 추가하고 바로 선택할 수도 있다.

## 필요한 입력

- 메모 데이터 구조(B3.3): id, project_id, title, content, created_at, updated_at
- React state 관리(선택된 메모 id 추적)

## 결과물

`src/screens/Memos.jsx`의 2단 레이아웃(좌측 `.memo-list`, 우측 `.memo-editor`)과 `src/index.css`의 관련 클래스. P4.2(IPC 연동) 전까지는 컴포넌트 내부의 메모리 seed 데이터로만 동작하며, 실제 저장/불러오기는 없다 — 이건 의도된 범위 제한이다.

## 선행 작업

없음(deps 없음, UI 레이아웃만 구현).

## 수행 순서에서의 위치

P4 내에서 가장 먼저 구현. P4.2(영속화), P4.3(프로젝트 태그 표시)가 이 레이아웃 위에서 이어진다.

## done_when을 확인하는 방법

1. 메모 화면(사이드바 "메모" 클릭)에서 좌측에 메모 목록이 보이는가.
2. 우측에 제목 입력창 + 본문 textarea가 있는가.
3. 좌측 메모를 클릭하면 우측 편집창 내용이 그 메모로 전환되는가.
4. "+ 새 메모"를 누르면 빈 메모가 추가되고 바로 선택되는가.

실행 화면 확인 방법: `npm run dev`로 앱을 띄운 뒤 사이드바에서 "메모"를 클릭 — eslint/vite build 통과만으로는 위 4개 동작(특히 클릭 전환)을 증명하지 못하므로 반드시 실행해서 확인한다. 창 기본 크기(420×640, `electron/main.js`)에서는 좌측 목록 폭이 좁아지므로, 가로 스크롤 없이 우측 편집창(제목 입력 + textarea)이 온전히 보이는지도 함께 확인한다.

## 확인 필요

- 메모 목록의 프로젝트 태그는 현재 `project_id` 값을 그대로 문자열로 보여준다(예: "proj-1") — 프로젝트 **명**이 아니다. B2.3/P4.3은 프로젝트명 표시를 요구하므로, P4.3 착수 시 projects 목록에서 이름을 조회하는 로직을 추가해야 한다. 지금 태그가 보인다고 P4.3을 바로 done 처리하면 안 된다(P4.3 로그에 동일 내용 기록됨).
- 새 메모 id는 `crypto.randomUUID()`로 생성한다(과거 `Date.now()` 기반은 동시 생성 시 충돌 가능성이 있어 교체됨).
- 타이핑할 때마다 `updated_at`을 갱신하는데, 지금은 메모리 상태라 무해하지만 P4.2가 "수정 시 saveData 호출"을 그대로 붙이면 키 입력마다 파일 전체 쓰기가 발생한다 — P4.2에서 디바운스 또는 blur 시 저장 여부를 결정해야 한다.
- 메모 삭제 UI는 없다(범위 밖) — P4.2 done_when에 삭제 UI 여부를 명시할지 검토 필요.
