# P5.1 — 캘린더 라이브러리 선정

## 목적
월간/주간 일정 뷰 구현에 사용할 캘린더 라이브러리를 조사하고 선정한다. 최종적으로 외부 라이브러리 없이 순수 함수로 구현하기로 결정하고, 이를 위한 scheduleGrid.js 모듈을 미리 작성해둔다.

## 쉬운 설명
FullCalendar나 react-big-calendar 같은 무거운 라이브러리를 쓸지, 아니면 직접 구현할지 결정하는 작업이다. 이 프로젝트의 요구사항이 단순(종일 이벤트만, 반복 요일 지정만, 회차별 예외 없음)해서, 외부 라이브러리 없이 순수 Date 계산으로 구현하기로 결정했다.

## 필요한 입력
- 요구사항 B2.4: 일정 화면 요구사항 (종일만, 반복은 요일 지정까지, 회차별 예외 없음)
- package.json 현재 상태 (react/react-dom만 있고 UI 라이브러리 없음)
- dateRange.js 선례 (순수 Date 계산 패턴)

## 결과물
- src/lib/scheduleGrid.js:
  - getMonthGrid(): 월간 캘린더 그리드 생성
  - getWeekDates(): 주간 날짜 배열 생성
  - getDayLabel(): 요일 레이블 (월~일)
  - getSchedulesForDate(): 특정 날짜의 일정 필터링
  - 각 함수의 vitest 테스트 (npm test 대상)
- 결정: 외부 라이브러리 미설치, zero-dependency 유지

## 선행 작업
없음 (spike/조사 작업)

## 수행 순서에서의 위치
P5.1은 P5의 첫 번째 단계이다. P5.1에서 결정하고 scheduleGrid.js를 작성해두면, P5.2(월간 뷰), P5.3(주간 뷰), P5.4(반복 일정) 등이 이 모듈을 사용할 수 있다.

## done_when을 확인하는 방법
1. 캘린더 라이브러리 선정 여부 결정 (외부 라이브러리 미사용으로 확정)
2. src/lib/scheduleGrid.js 파일 작성 확인
3. getMonthGrid, getWeekDates, getDayLabel, getSchedulesForDate 함수 존재 확인
4. `npm test`로 scheduleGrid.test.js의 모든 테스트 통과 확인
5. package.json에 새로운 UI/날짜 라이브러리 미추가 (npm install 불필요)
