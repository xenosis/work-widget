# P5.5 — 반복 일정 수정 시 전체 회차 일괄 반영

## 목적

반복 일정의 규칙을 수정할 때, 특정 회차만 예외로 두지 않고 이후 모든 회차에 함께 반영된다. 회차별 레코드 없이 규칙 하나만 있으므로 이 동작이 설계 차원에서 자동으로 성립한다(P3.6과 같은 "유령 작업" 패턴).

## 쉬운 설명

"매주 월요일 회의"를 "매주 월, 수, 금"으로 규칙을 바꾸면, 앞으로의 모든 회차가 새 요일들에 표시된다. 특정 주만 빼거나 예외는 없다. 규칙 레코드 하나만 수정되므로, scheduleGrid.js의 getSchedulesForDate가 다음 렌더링부터 새 규칙으로 자동 전개한다.

## 필요한 입력

- P5.4 완료: ScheduleEditForm.jsx와 applyScheduleUpdate 함수가 반복/비반복 통합 구현
- 규칙 수정 로직: recurrence_days 필드 변경

## 결과물

별도 새로운 코드 없음. P5.4에서 이미 구현된 ScheduleEditForm.jsx와 applyScheduleUpdate 함수가 이 기능을 담당한다:
- ScheduleEditForm.jsx: 수정 폼 (기준일 명시, '모든 회차에 적용' 경고 문구)
- scheduleMutations.js의 applyScheduleUpdate: 규칙 레코드 수정 함수

## 선행 작업

- P5.4: 반복 일정 등록 및 CRUD 완료. applyScheduleUpdate 함수로 규칙 수정 시 일괄 반영 자동 성립

## 수행 순서에서의 위치

P5 내 CRUD의 Update 단계. P5.4에서 회차별 레코드 없이 규칙 하나로 설계했으므로, 이 작업은 별도 구현 없이 P5.4의 설계/구현으로 자동 충족된다. 2026-09-24 critical-reviewer가 P5.4 리뷰 중 다음 달 회차에서 제목을 수정해 Playwright로 즉시 반영됨을 직접 검증함으로써 이 task의 done_when 전체를 확인했다.

## done_when을 확인하는 방법

1. npm run dev로 Electron 앱 기동
2. Schedule 탭 → 반복 일정의 수정 버튼 클릭
3. recurrence_days 또는 title 변경(예: 제목을 '회의' → '중요 회의'로 변경)
4. 저장 후 현재 달과 다음 달 모두에서 새로운 내용이 표시되는지 확인
5. '모든 회차에 적용됩니다'라는 경고 문구 노출 확인
