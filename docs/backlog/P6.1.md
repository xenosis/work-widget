# P6.1 — Project.progress 계산 함수

## 목적

프로젝트에 소속된 할일들의 완료 비율을 계산하는 함수를 구현한다. 이 값은 저장하지 않고, 조회할 때마다 계산한다(B3.1).

## 쉬운 설명

프로젝트의 progress는 다음과 같이 계산된다: `progress = round((완료된 할일 개수 / 전체 할일 개수) * 100)`. 소속 할일이 하나도 없는 프로젝트는 "아직 시작 전"으로 보고 0%로 취급한다. 이 값은 data.json에 저장하지 않고, 화면이 데이터를 읽을 때마다 그때그때 계산한다.

## 필요한 입력

- projects와 todos 배열의 구조 (B3.1, B3.2)
- Todo.project_id와 Project.id의 매핑 관계, Todo.completed(boolean)

## 결과물

`src/lib/projectProgress.js`: `calculateProjectProgress(projectId, todos)` 순수 함수, named export.

(계획 단계에서는 `calculateProgress(project, todos)`처럼 프로젝트 **객체**를 받는 시그니처를 가정했지만, 실제 구현은 프로젝트 **id 문자열**을 받는 `calculateProjectProgress(projectId, todos)`다. 이 문서는 실제 구현 기준으로 갱신됐다 — 이 함수를 호출하는 쪽(P1.3/P2.1/P2.4)은 project 전체가 아니라 `project.id`를 넘겨야 한다.)

## 선행 작업

없음 (유틸 함수 구현, deps 없음).

## 수행 순서에서의 위치

P6 내에서 가장 먼저 구현되는 항목. P1.3, P2.1(→P6.2 경유), P2.4 등 화면 쪽 task들이 이 함수를 가져다 쓸 예정이지만, 이 문서 작성 시점까지는 어느 화면에서도 아직 import하지 않은 상태(그 연결은 각 화면 task의 몫).

## done_when을 확인하는 방법

1. 함수가 정의되고 export되었는가 — `src/lib/projectProgress.js`에서 `calculateProjectProgress` 확인.
2. 테스트 케이스로 검증(자동 테스트 러너가 없어 수동 실행 스크립트로 확인함, 재현 가능한 스크립트 파일은 저장소에 남기지 않았음 — 필요하면 재실행해서 검증):
   - 소속 todo 3개 중 2개 완료 → 67%
   - 소속 todo 1개 중 0개 완료 → 0%
   - 소속 todo 2개 중 2개 완료(경계값) → 100%
   - 소속 todo 없음 → 0%
   - `todos`가 빈 배열/undefined/null → 0%(에러 없이)
3. 다른 파일에서 import해서 쓸 수 있는가 — 함수 자체는 가능하지만, 이 문서 작성 시점엔 실제로 import하는 화면 코드는 아직 없다(위 "수행 순서" 참고).

## 확인 필요

- `calculateProjectProgress`로 계산된 값을 Project 레코드에 절대 저장하면 안 된다(B3.1 "저장하지 않고 조회 시 계산"). 이 함수 자체는 저장을 막지 않으므로, `electron/dataStore.js`의 저장 경로(P6.3/P6.4)에서 `progress` 같은 파생 필드가 실수로 들어와도 걸러내는지는 별도 확인이 필요 — 현재는 걸러내는 로직이 없다.
- 소수점 반올림 정책(`Math.round`, 99.5% 이상이면 100%로 표시됨)이 B4.3의 "전부 완료 시에만 자동 완료 전환"과 시각적으로 헷갈릴 수 있는지는 P6.2(자동 전환 로직) 구현 시 함께 검토 필요.
