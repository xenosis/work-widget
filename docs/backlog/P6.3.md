# P6.3 — data.json 스키마 검증/마이그레이션 유틸

## 목적

data.json이 손상되었거나 최상위 구조가 깨졌어도 앱이 죽지 않고 안정적으로 동작하도록 방어 로직을 구현한다.

## 쉬운 설명

실제 사용하다 보면 data.json이 손상될 수 있다: JSON 문법이 깨지거나, `projects`/`todos`/`memos`/`schedules` 중 일부 키가 없거나 배열이 아니거나, 배열 안에 이상한 값이 섞여 있을 수 있다. 이런 경우에도 앱이 예외를 던지며 죽지 않고, 가능하면 손상되기 전 원본도 잃지 않게 방어한다.

## 필요한 입력

- B3 섹션의 최상위 스키마(4개 배열 키)
- 어떤 경우를 "손상"으로 볼 것인지에 대한 판단 기준

## 결과물

`electron/dataStore.js`에 추가된 함수들:
- `normalizeData(data)` — 4개 배열 키가 없거나 배열이 아니면 빈 배열로 보정, 배열 안의 비객체 항목 제거. `loadData()`에서 파일을 읽은 뒤 항상 이 함수를 거친다(관용적 보정).
- `backupCorruptFile(filePath, rawText)` — JSON 파싱 실패나 최상위 구조가 완전히 다른 경우, 덮어쓰기 전에 원본을 `<path>.corrupt-<timestamp>`로 백업.
- `atomicWriteJson(filePath, obj)` — 임시 파일에 쓴 뒤 rename하는 원자적 쓰기. 쓰는 도중 강제 종료돼도 원본 파일이 반쯤 쓰인 채로 깨지지 않는다.
- `saveData(data)` — `loadData()`가 돌려준 것과 같은 **전체 객체**만 받는다는 계약. 4개 배열 키 중 하나라도 배열이 아니면(부분 객체 저장 시도) 조용히 채우지 않고 예외를 던진다.

## 선행 작업

**P0.3** — dataStore.js 작성 완료.

## 수행 순서에서의 위치

P6 내에서 독립적으로 구현 가능. 이 task는 **최상위 구조 손상 방어**만 다루고, 레코드(개별 project/todo/memo/schedule) 단위 필드 누락·구버전 마이그레이션은 범위에서 제외되어 **P6.4**로 분리됐다 — "구버전 data.json"이라는 done_when 문구 중 레코드 단위 해석은 P6.4가 마저 담당한다.

## done_when을 확인하는 방법

1. `loadData()`가 손상된 JSON(문법 오류)을 만나면: 원본이 `.corrupt-<timestamp>` 파일로 백업되고, 기본값(`{projects:[],todos:[],memos:[],schedules:[]}`)을 반환하며 예외를 던지지 않는가.
2. `loadData()`가 최상위 키 누락/타입 불일치(예: `projects`가 문자열)를 만나면 해당 키만 빈 배열로 보정되는가.
3. **`saveData(data)`에 부분 객체(예: `{memos:[...]}`만)를 넘기면 예외를 던지고 파일을 건드리지 않는가** — 이전에는 이 경우 나머지 키를 조용히 `[]`로 덮어써 데이터가 전량 삭제되는 Critical 버그가 있었고, 지금은 거부하도록 고쳐졌다. 이 검증이 가장 중요하다.
4. 두 번 연속 `loadData()`를 호출해 한쪽 결과를 mutate해도 다른 쪽이 오염되지 않는가(과거엔 `{...DEFAULT_DATA}` 얕은 복사로 배열 인스턴스를 공유하는 버그가 있었음).
5. `saveData()` 직후 임시 파일(`.tmp-<pid>`)이 남지 않는가(원자적 쓰기 확인).

위 5개 시나리오는 electron 의존성 없이 `normalizeData`/`loadData`/`saveData`를 분리 실행하는 방식으로 직접 재현 검증됨(모두 PASS).

## 확인 필요

- 레코드 단위 필드 기본값·버전 마이그레이션(예: 구버전 todo에 `tags`가 없어서 이후 `.map()`에서 죽는 경우)은 이 task 범위 밖이다 — **P6.4**에서 다룬다.
- 알 수 없는 최상위 키(예: 향후 추가될 `version`, `settings`)는 `saveData`가 `data`를 그대로 쓰므로 보존되지만, `loadData`의 `normalizeData`는 4개 키만 남기고 나머지는 버린다 — 앞으로 최상위 스키마가 늘어나면 `normalizeData`도 같이 확장해야 한다.
