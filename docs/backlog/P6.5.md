# P6.5 — 테스트 러너 도입(vitest)

## 목적

src/lib의 순수 함수들(projectProgress, projectStatus, dateRange 등)에 대한 자동 테스트 환경을 구축해서, 향후 작업들이 단위 테스트로 함수 계약을 검증할 수 있도록 한다. 현재는 gate=null이고 수동 node 실행에만 의존하고 있어, 회귀 버그가 조용히 쌓일 위험이 있다.

## 쉬운 설명

package.json에 vitest를 devDependency로 추가하고, npm test 스크립트를 연결한다. 그 다음 기존에 수동으로 검증해온 케이스들(projectProgress 7개 케이스, projectStatus 11개 케이스, dateRange 10개 케이스 등)을 .test.js 파일로 정식 테스트로 전환한다. 이제 npm test를 실행하면 이 모든 케이스들이 자동으로 검증된다.

## 필요한 입력

- P6.1(Project.progress 계산): 기존 수동 검증 케이스들(주석 또는 개발 로그에 기록된 7개)
- P6.2(프로젝트 상태 전환): 11개 검증 케이스
- P1.2 리뷰에서 추가된 src/lib/dateRange.js 및 검증 케이스
- vitest 문서 및 vite와의 통합 방식

## 결과물

- package.json에 vitest devDependency 및 "test": "vitest run" 스크립트
- src/lib/projectProgress.test.js (7개 케이스 + 추가 엣지 케이스들)
- src/lib/projectStatus.test.js (11개 케이스)
- src/lib/dateRange.test.js (10개 케이스)
- src/lib/priority.test.js 등 기타 유틸 테스트
- npm test 실행 시 모든 케이스 PASS

## 선행 작업

- P6.1: projectProgress 함수 및 검증 케이스 정의 완료
- P6.2: projectStatus 함수 및 검증 케이스 완료
- P1.2: dateRange 함수들 (getTodayDateString, getThisWeekRange 등) 완료

## 수행 순서에서의 위치

P6(데이터 계층) 내에서 P6.1, P6.2, P6.3 이후의 인프라 작업. 테스트 환경이 준비되면 P1~P5의 향후 화면 작업들에서 gate에 "npm test" 지정 가능해져서, 자동 검증 체계가 갖춰진다.

## done_when을 확인하는 방법

1. npm test 실행 시 "X tests PASSED" 출력 (전체 30+개 테스트)
2. npm run lint 통과
3. npm run build 통과 (테스트 파일이 번들에 포함되지 않음 확인)
4. vite.config.js에 test.include=['src/**/*.test.js'] 명시 확인
5. 의도적으로 하나의 테스트를 실패하게 수정 후 npm test 재실행 → 실패 보고 확인, 다시 원복 후 PASS 확인
