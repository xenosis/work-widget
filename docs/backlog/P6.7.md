# P6.7 — is_recurring이 truthy이지만 true가 아닌 값일 때 편집 저장이 recurrence_days를 지우는 문제 정책 결정

## 목적

P6.6에서 isScheduleRecurring을 엄격 비교(`=== true`)로 통일한 결과로 생겨난 새로운 데이터 손실 위험을 인식하고, 이에 대한 정책을 결정받고 확정한다.

## 쉬운 설명

손상된 데이터(is_recurring = "true" 문자열이나 1처럼 truthy이지만 boolean이 아닌 값)가 있을 때, P6.6의 isScheduleRecurring은 엄격 비교(`=== true`)로 이를 false로 판정한다. 그 결과 ScheduleEditForm을 열면 반복 체크박스가 꺼진 상태로 초기화되고, 사용자가 다른 필드만 수정해서 저장하면 recurrence_days가 null로 덮어써진다. 이는 원래 설정된 반복 요일 배열이 영구 삭제되는 일방통행 손실이다(P7.3 백업으로만 복구 가능). 이 트레이드오프를 어떻게 처리할지 사람이 결정해야 한다.

## 필요한 입력

- **P6.6 완료**: isScheduleRecurring 엄격 비교 통일
- **P6.4 완료**: FIELD_DEFAULTS에서 is_recurring의 기본값이 false로 설정됨 (신규 레코드는 올바른 타입)
- **요구사항 B3.4**: schedule.is_recurring 필드 정의 (타입 불일치 시 정책 미규정)

## 결과물

정책 결정 task이므로 코드 산출물 없음. 다만 **선택된 정책이 work-widget-requirements.md#B3.4에 문서화됨**. 

**확정된 정책**: 옵션 C — **현행 유지(문서화만)**
- 코드 변경 없음
- 위험을 인식하고 있으며, P7.3의 자동 백업(하루 1회)으로 복구 가능함을 명시
- is_recurring이 boolean이 아닌 손상 값인 경우가 생기는 유일한 경로는 수동 data.json 편집이므로, 대부분의 사용자는 이 문제를 만나지 않을 것으로 예상

## 선행 작업

**P6.6**: isScheduleRecurring 엄격 비교 통일 (완료)

## 수행 순서에서의 위치
