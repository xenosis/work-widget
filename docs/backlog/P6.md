# P6 — 데이터 계층 공통 로직 (B3/B4.3)

## 목적

프로젝트 진행률 계산, 프로젝트 상태 자동 전환(모든 할일 완료 시 자동 '완료', 이후 재개 시 자동 '진행중'), 데이터 검증/마이그레이션, 테스트 자동화 등 여러 화면이 공유하는 핵심 로직을 중앙화하여 중복 방지와 일관성을 보장한다. 이 작업이 완료되면 모든 화면이 동일한 데이터 규칙으로 동작하게 된다.

## 쉬운 설명

각 화면(대시보드, 프로젝트, 할일 등)이 각각 "이 프로젝트의 진행률은?", "이 프로젝트는 몇 % 완료?", "할일을 완료하면 프로젝트 상태를 자동으로 완료로 바꿀까?" 하는 로직을 중복으로 구현하는 대신, src/lib와 electron/dataStore.js에 하나의 정답 함수들을 모아둔다. 예를 들어 "프로젝트 진행률 = 완료된 할일 수 / 전체 할일 수"라는 규칙을 모두가 같은 함수(calculateProjectProgress)로 계산해서, 누군가 실수로 다르게 구현할 수 없게 만든다. 또한 data.json이 손상되거나 구버전 형식이어도 앱이 죽지 않도록 정규화하는 로직도 여기서 한다.

## 필요한 입력

- **B3 데이터 스키마**: projects/todos/memos/schedules의 필드 정의 (required/optional, type, 기본값)
- **B4.3 동작 규칙**: 프로젝트 상태 자동 전환 조건 (모든 할일 완료 ↔ 완료, 보류는 수동)
- **P0 완료**: 기본 저장/로드 체계 (electron/dataStore.js loadData/saveData)
- **요구사항 문서**: 일정 화면의 자정 경과 시 날짜 동기화 정책(P5.7), is_recurring boolean 타입 손상 시 정책(P6.7)

## 결과물

- **src/lib/projectProgress.js**: calculateProjectProgress(projectId, todos) — 진행률 백분율
- **src/lib/projectStatus.js**: deriveProjectStatus(currentStatus, projectId, todos) — 상태 자동 전환 로직
- **src/lib/dateRange.js**: 날짜 범위 계산 (getTodayDateString, getThisWeekRange 등)
- **src/lib/scheduleGrid.js**: 월간/주간 그리드, 반복 일정 노출 판정 (P5.1~P5.4에서 사용)
- **electron/dataStore.js**: normalizeData, applyFieldDefaults, backupIfNeeded 등 검증/마이그레이션 로직
- **electron/windowState.js**: 창 위치/크기 저장/복원 (P7.5에서 사용)
- **vitest 자동 테스트**: npm test로 src/lib/*.test.js 실행 (137+ 케이스)

## 선행 작업

- **P0**: 기초 인프라(스캐폴딩, 저장/로드 체계)

## 수행 순서에서의 위치

P6는 부모 작업(root)으로, P6.1~P6.7의 7개 하위 작업이 세부 기능을 담당한다. P6 완료 시점:
- P1(대시보드)은 이미 P6.1(진행률)을 사용 중
- P2, P3, P4도 P6의 공통 함수들 위에서 동작
- P7(백업, 창 상태)은 P6.4(필드 기본값)와 P6.5(테스트 자동화) 이후 안정화됨
- P8(패키징)은 모든 기능이 검증된 후 진행

## done_when을 확인하는 방법

P6의 done_when은 "하위 항목 전부 done"이므로, P6.1~P6.7 모두 done인지 확인:

```bash
node scripts/backlog/cli.js show P6.1 P6.2 P6.3 P6.4 P6.5 P6.6 P6.7
# 모두 status: done 확인

npm test
# 167개 테스트 모두 PASS
```

또는 각 기능별로 수동 확인:
1. **P6.1**: 프로젝트 진행률 계산 — 프로젝트 화면에서 "3개 중 2개 완료 → 67%"가 정확히 표시
2. **P6.2**: 상태 자동 전환 — 할일을 모두 완료하면 프로젝트 상태가 자동 "완료"로 바뀜 (코드 검증, 실제 저장 경로는 Todos.jsx에서 확인)
3. **P6.3/P6.4**: 손상된 data.json 방어 — 구버전 형식 레코드를 읽어도 앱이 죽지 않고 필드 기본값이 채워짐
4. **P6.5**: npm test 자동 실행 — npm test로 137개 테스트 모두 PASS
5. **P6.6**: is_recurring 일관성 — "true"/1처럼 손상된 boolean 값도 안전하게 처리
6. **P6.7**: 정책 결정 — is_recurring 손상 시 recurrence_days 유실 위험이 문서화됨
