# P7.1 — 실제 트레이 아이콘 리소스 적용

## 목적

nativeImage.createEmpty()의 빈 트레이 아이콘을 실제 PNG 이미지 파일로 교체하여, 사용자가 시스템 트레이에서 앱의 아이콘을 명확히 인식할 수 있도록 한다.

## 쉬운 설명

처음에는 트레이에 아무 아이콘도 보이지 않았다(임시 빈 아이콘 사용). 이제 외부 이미지 처리 라이브러리 없이 순수 Node(zlib + 수동 CRC32)로 PNG를 직접 생성해서 electron/assets/ 아래에 저장한다. 그 파일을 electron/main.js에서 nativeImage.createFromPath()로 로드하면, 시스템 트레이에 실제 아이콘(청록 원 + 흰 체크마크 모양)이 표시된다.

## 필요한 입력

- Electron의 nativeImage API (createFromPath, createEmpty)
- 트레이 아이콘 이미지 생성 능력
- 이 프로젝트에선 외부 라이브러리 없이 Node의 내장 zlib 모듈로 PNG 생성

## 결과물

- `scripts/gen-tray-icon.js`: 순수 Node(zlib + 수동 CRC32)로 PNG를 생성하는 스크립트
- `electron/assets/tray-icon.png` (16x16 픽셀)
- `electron/assets/tray-icon@2x.png` (32x32 픽셀, 고해상도 디스플레이 대응)
- `electron/main.js` createTray() 함수 개선:
  - nativeImage.createFromPath(경로)로 파일 로드
  - tray.isDestroyed() 검사 추가
  - 트레이 아이콘 클릭 리스너 등록

## 선행 작업

없음. P7 내에서 독립적으로 진행 가능함.

## 수행 순서에서의 위치

P7 내 가장 먼저 진행되는 하위 작업이다. P7.1이 완료되어야 P7.4(창 동작 검증)에서 트레이 클릭을 정확히 검증할 수 있다(빈 아이콘은 클릭 좌표 특정이 어려움). 순서: P7.1(아이콘) → P7.4(창 동작) → P7.2(시작프로그램).

## done_when을 확인하는 방법

1. `npm run dev`로 앱 실행
2. electron/assets/tray-icon.png와 tray-icon@2x.png 파일이 존재하는지 확인
3. 시스템 트레이에 실제 아이콘(청록 원 + 흰 체크마크)이 표시되는지 육안 확인
4. electron/main.js의 createTray() 함수가 nativeImage.createFromPath()로 로드했는지 코드 확인
5. 로드한 nativeImage 객체가 isEmpty()===false인지 확인
6. npm run lint, npm run build, npm test 모두 통과
7. Playwright+Electron으로 실제 트레이 아이콘 표시와 클릭 동작 검증(설정된 토글 리스너 실행)
