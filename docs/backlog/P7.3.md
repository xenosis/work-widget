# P7.3 — 데이터 자동 백업

## 목적

하루 1회 data.json을 자동으로 백업하여, 실수로 인한 삭제(P2.10의 cascade 삭제)나 손상에 대비한다.

## 쉬운 설명

프로젝트 삭제 시 소속 할일/메모도 함께 사라진다. 이를 복구할 유일한 방법은 백업이므로, 매일 자동으로 데이터를 백업해 둔다. 최근 7일치만 유지하여 디스크 공간을 절약한다. 데이터를 로드하거나 저장할 때마다 오늘 날짜의 백업이 없으면 생성하고, 형식이 맞는 파일만 세어서 7개 초과 분은 정리한다.

## 필요한 입력

- B5.3 요구사항: 주기적 자동 백업
- P0.3: loadData/saveData 함수
- electron userData 경로
- 파일 시스템 I/O 권한

## 결과물

electron/dataStore.js:
- backupIfNeeded(): loadData/saveData 호출 시 오늘 날짜 백업 생성 (중복 방지)
- pruneOldBackups(): 최근 7개 파일만 유지하고 오래된 것 삭제
- todayDateStamp(): YYYY-MM-DD 형식 오늘 날짜

electron/dataStore.test.js:
- pruneOldBackups/todayDateStamp 순수 함수 테스트 5건

userData/backups/ 폴더:
- data-YYYY-MM-DD.json 파일들 (최근 7일치)

## 선행 작업

- P0.3 (데이터 저장 계층): done
- P2.10 (프로젝트 cascade 삭제): 이 작업 착수 당시에 이미 done으로 우선순위 재검토 근거 제공함

## 수행 순서에서의 위치

P7(유틸리티) 내에서 최우선. P7.1(앱 아이콘)/P7.2(런처 등록)보다 먼저 실행되어야 함. 데이터 안전이 UI 개선보다 우선이기 때문.

## done_when을 확인하는 방법

1. electron/dataStore.js에 backupIfNeeded/pruneOldBackups/todayDateStamp 함수 구현 확인
2. npm run dev로 앱 실행:
   - userData/backups/data-YYYY-MM-DD.json 생성 확인
   - 같은 날 두 번째 실행 시 중복 생성 안됨
   - 오래된 가짜 백업 8개 + 오늘자 1개를 미리 만들고 실행 → 최근 7개만 남음 확인
3. electron/dataStore.test.js 테스트 5개 통과:
   - 보관 개수 이하일 때 무보존
   - 초과 시 정리
   - 형식 다른 파일 무시
   - 미래 날짜 파일 있어도 오늘자 보존
4. npm test 전체 통과(npm test는 scheduleGrid.js만 회귀했으나 dataStore.test.js 5개도 포함)
5. npm run build 성공
6. 콘솔 에러 없음

## 확인 필요

없음

(참고: 보관 기간 7일은 요구사항 B5.3에서 "정확한 주기·개수는 구현 시 조정 가능"이라 명시한 값. 파싱 성공 후에 백업하며, 복사 도중 실패하면 tmp 파일로만 남음. 미래 날짜 파일이 섞여도 오늘자는 항상 보존 — 날짜 정렬순 정리가 아니라 개수 기준 정리이므로 필요한 보호)
