# P7.4 — B1.1 위젯 창 동작(리사이즈/이동/always-on-top 아님) 실행 확인

## 목적

요구사항 B1.1은 위젯 창이 사용자의 자유로운 위치 이동, 드래그를 통한 크기 조절을 지원하고, 다른 창에 가려질 수 있음(항상 위 고정 아님)을 규정합니다. 이 작업은 현재 코드가 이 요구사항을 실제로 충족하는지 확인하고, 창이 너무 작아져 레이아웃이 깨지는 것을 방지하는 최소 크기 정책을 실행으로 검증합니다.

## 쉬운 설명

Electron 앱의 창을 사용자가 마우스로 드래그해서 크기를 조절하고 위치를 옮길 수 있어야 한다는 요구사항이 있습니다. 이 작업은:
- 창 크기 조절과 이동이 실제로 작동하는지 확인
- 창이 너무 작아지지 않도록 최소 크기(가로 420px, 세로 420px)를 설정
- 창이 항상 다른 창 위에 있지 않도록(alwaysOnTop 비활성) 확인

입니다. 이전 과제들(P1.7, P3.3, P4.3)에서 420px 너비가 텍스트 오버플로 문제를 일으키지 않는 최소 폭임을 확인했으므로, 그보다 좁으면 화면이 깨지지 않도록 막는 것입니다.

## 필요한 입력

- electron/main.js: BrowserWindow 생성 로직 (P0.4에서 이미 만들어짐)
- work-widget-requirements.md: B1.1 창 동작 요구사항
- 이전 텍스트 오버플로 수정 이력(P1.7, P3.3, P4.3): 420px 폭 검증 기준

## 결과물

- electron/main.js: minWidth=420, minHeight=420 옵션 추가
- work-widget-requirements.md: B1.1 섹션과 v1.9 버전 정보 갱신
  - 최소 크기 결정 및 근거 기록
  - "고정된 크기로"의 의미 해석 추가(상시 노출을 뜻함, 크기 고정이 아님)

## 선행 작업

P0.4 (Electron 메인 프로세스 작성) — BrowserWindow 생성 로직이 있어야 최소 크기 옵션을 추가할 수 있습니다.

## 수행 순서에서의 위치

P7(UI/UX 마무리)의 중요한 정책 수립 항목입니다. 기본 창 동작이 확인되어야 이후 창 위치/크기 영속화 정책(P7.5)을 결정할 수 있으며, 배포(P8) 전에 실행되어야 합니다. P7.1(트레이 아이콘), P7.2(시작 프로그램), P7.3(데이터 백업)과 유사하게 인프라 차원의 필수 항목입니다.

## done_when을 확인하는 방법

1. npm run build 실행 → exit 0 확인
2. npm test 실행 → 모든 테스트(168개 이상) 통과 확인
3. Playwright를 이용해 실제 Electron 앱 기동 후:
   - isResizable()와 isMovable()이 true 반환 확인
   - isAlwaysOnTop()이 false 반환 확인
   - setSize(200, 200) 호출 후 getSize()가 [420, 420]으로 클램프되는지 확인(최소 크기 강제)
   - setSize(800, 900) 호출 시 실제로 그 크기로 설정되는지 확인(최대 크기 제약 없음)
   - setPosition(150, 150) 호출 후 getPosition()이 반영되는지 확인
4. 콘솔/로그에 Electron 관련 에러 없음 확인
5. work-widget-requirements.md#B1.1에 최소 크기 결정 이력(2026-09-24, P7.4) 기록 확인

참고: 실제 마우스 드래그(WM_SIZING 신호) 시뮬레이션은 OS 입력 시뮬레이션 부재로 이 환경에서 불가능하며, 다른 창에 실제로 가려지는 것도 동일한 이유로 검증 불가합니다. 대신 프로그램 API(setSize, setPosition, isAlwaysOnTop 플래그)로 동등한 기능을 검증합니다.

## 확인 필요

없음. 최종 결정사항:
- minWidth=420, minHeight=420 고정
- minHeight=360(초기 설정)에서 420으로 상향: 사이드바 5개 메뉴 렌더링에 필요한 높이(327px)를 충분히 확보하기 위함
- "420px 미만에서 깨진다"는 설명은 정확히는 "420에서만 검증했으므로 보수적 하한으로 설정"
- API 검증 한계(실제 마우스 드래그 미검증)는 이 저장소 정책(DOM/UI 테스트 범위 밖, CLAUDE.md 명시)에 부합
