# P7.5 — 창 위치/크기를 재시작 사이에 기억할지 정책 결정

## 목적

요구사항 B1.1은 "사용자가 자유롭게 이동/배치 가능"을 규정하지만, 창 위치와 크기를 저장했다가 재부팅/재시작 후 복원할지는 명시하지 않는다. 이 작업은 그 정책을 결정하고, 필요하면 구현하는 것이다. 시작프로그램(P7.2)으로 등록되어 매번 자동 실행되는 위젯의 특성상, 사용자가 배치한 위치를 재부팅 후에도 유지할지 여부가 중요하다.

## 쉬운 설명

창을 화면 오른쪽에 옮기고 크기를 500x600으로 조절한 뒤, PC를 재부팅하거나 앱을 다시 실행했을 때:
- **옵션 1 (선택된 정책)**: 같은 위치와 크기(500x600)가 복원되어야 한다. 단, 외장 모니터를 분리했거나 해상도를 바꿔서 저장된 좌표가 화면 밖이 되면, 가장 가까운 모니터나 기본값으로 안전하게 폴백한다.
- **옵션 2**: 항상 기본 위치(화면 중앙)와 기본 크기(420x640)에서 시작한다.

**확정된 정책**: 옵션 1 — 창 위치/크기를 저장하고, 자동 복원하되 화면 밖 좌표에 대한 방어를 함께 구현.

## 필요한 입력

- **work-widget-requirements.md#B1.1**: "사용자가 자유롭게 이동/배치 가능" 요구사항
- **P7.2 완료 여부**: 시작프로그램 등록이 되는 경우, 부팅 후의 초기 좌표 설정이 중요
- **P7.4 완료**: 창 리사이즈/이동 기능 구현, minWidth/minHeight 설정
- **정책 결정(2026-09-25)**: 위치/크기 저장 및 복원하기로 확정

## 결과물

- **electron/windowState.js** (신규):
  - loadWindowState() — userData/window-state.json에서 저장된 bounds 로드
  - saveWindowState(mainWindow) — 현재 창 상태를 저장 (원자적 쓰기)
  - isValidBounds(bounds) — 저장된 좌표가 현재 디스플레이 작업영역 내에 있는지 검증
  - findContainingDisplay(x, y) — 좌상단 좌표가 어느 모니터에 속하는지 찾기
  - (vitest 3개 테스트)

- **electron/main.js** 수정:
  - createWindow()에서 loadWindowState() 호출, 저장된 bounds로 생성 (없으면 기본값 420x640)
  - window의 move/resize 이벤트에 500ms 디바운스 저장
  - close 핸들러에서 즉시(디바운스 없이) 저장
  - session-end 이벤트에서도 저장

- **work-widget-requirements.md#B1.1**: (2026-09-25 결정, P7.5) 정책 문단 추가

## 선행 작업

- **P7.4**: 창 리사이즈/이동 기능 및 minWidth/minHeight 확인 (완료)

## 수행 순서에서의 위치

P7의 최종 정책/구현 항목. P7.1(트레이 아이콘) → P7.3(백업, 우선) → P7.4(창 동작) → P7.2(시작프로그램) 진행 후, P7.5에서 창 상태 영속 구현. 배포(P8) 전에 완료되어 부팅 후 자동 실행 시 사용자 배치가 보존되도록 함.

## done_when을 확인하는 방법

1. **코드 확인**:
   ```bash
   test -f electron/windowState.js
   # 파일 존재 확인
   grep -n "loadWindowState\|saveWindowState" electron/main.js
   # 호출 확인
   ```

2. **자동 테스트**:
   ```bash
   npm test
   # 173개 테스트 포함 모두 PASS
   grep "windowState" <(npm test 2>&1)
   # windowState 테스트 3개 포함
   ```

3. **수동 검증** (npm run dev):
   - 앱 기동 후 창을 500x600으로 리사이즈
   - 화면 오른쪽으로 이동
   - 앱 종료 후 userData/window-state.json 확인 (bounds 저장됨)
   - 앱 재기동 → 같은 위치/크기로 복원
   - 다시 크기를 200x200으로 줄여본 후 최대화
   - 종료 후 userData/window-state.json 다시 확인 (최대화가 아닌 '일반 크기' 200x200이 저장됨)

4. **화면 밖 좌표 방어 검증** (Playwright):
   - userData/window-state.json을 수동 편집해 화면 밖 좌표(예: x=50000) 삽입
   - 앱 기동 → 기본값(420x640)으로 폴백
   - 폭/높이가 비정상적으로 크면(50000) → 디스플레이 크기로 클램프

5. **실제 부팅 검증** (P7.2 완료 후):
   - npm run dist로 배포 빌드
   - 설치본을 실제 PC에 설치하고 시작프로그램에 등록
   - PC 재부팅 → 위젯이 자동 실행되고 저장된 위치/크기로 복원되는지 확인
   - 외장 모니터 연결/분리 후 재부팅해 폴백 로직 동작 확인

## 확인 필요

- **P7.2 미완료**: 시작프로그램 자동 실행이 아직 todo 상태라서, 실제 부팅 후 초기 실행 시 디스플레이가 완전히 준비되지 않은 상황(외장 모니터 늦은 인식)에서 저장된 좌표가 잘못 판정될 가능성이 있다(추측, 미검증). **P7.2 착수 후 실제 로그인 자동 실행 환경에서 재검증 필요**.
- Windows 이외의 플랫폼(macOS, Linux): work-widget은 Windows 목표이므로 크로스 플랫폼 처리 불필요로 확인됨. 하지만 향후 포팅 시 주의 필요.
