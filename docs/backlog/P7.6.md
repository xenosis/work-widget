# P7.6 — 단일 인스턴스 락(중복 실행 방지)

## 목적

P7.2(Windows 시작프로그램 자동 실행)로 인해 로그인할 때마다 위젯이 자동으로 떠있는 것이 상시화되면, 사용자가 실수로 바탕화면 바로가기나 시작메뉴에서 앱을 또 실행할 가능성이 높아진다. 이때 같은 데이터 파일을 다루는 두 프로세스가 동시에 뜨면 저장 경합으로 인한 데이터 손실이 발생할 수 있다. 두 번째 인스턴스 실행을 Electron의 `requestSingleInstanceLock()`으로 방지하고, 기존 창으로 포커스를 옮기는 단일 인스턴스 락을 구현한다.

## 쉬운 설명

앱이 이미 실행 중인 상태에서 사용자가 실수로 또 실행하려고 하면, 두 번째 실행 시도는 "이미 떠있으니까 그쪽으로 집중해"라는 신호를 받고 자동으로 종료되고, 기존에 떠있던 창이 맨 앞으로 나타난다. 마치 윈도 탐색기에서 같은 파일을 두 개의 편집기로 동시에 열었을 때 두 번째 파일 열기가 기존 편집기를 활성화하는 것과 같은 원리다.

## 필요한 입력

- Electron 메인 프로세스 파일(`electron/main.js`)
- `app.requestSingleInstanceLock()` API를 지원하는 Electron 버전(이미 설치됨)
- 주요 윈도 인스턴스 참조(`mainWindow`)와 `second-instance` 이벤트 처리
- 렌더러 프로세스가 안정적으로 뜨는 상태 (P1.1~P1.6 완료)

## 결과물

`electron/main.js` 수정:
- `app.requestSingleInstanceLock()` 호출 (앱 모듈 최상위, `app.whenReady()` 이전)
- lock 획득 실패 시 `app.quit()` + 최상위 `return`으로 창/트레이 생성 전 종료
- `app.on('second-instance')` 리스너 등록:
  - 기존 창이 최소화 상태면 `restore()`로 복원
  - 기존 창을 `show()` 호출로 표시
  - `focus()`로 포커스 이동
  - `isDestroyed()` 가드로 종료 시퀀스 중 예외 방지

변경 사항: `data.json`/`window-state.json` 파일은 전혀 건드리지 않음 (두 번째 인스턴스가 lock을 얻지 못해 창 생성 코드 자체가 실행되지 않음).

## 선행 작업

없음. 

deps에 P7.2가 원래 명시돼 있었으나, critical-reviewer 지적으로 "이 task가 왜 생겼는지의 출처"(P7.2 리뷰에서 발견)일 뿐 실제 선행 조건이 아님이 확인됐다. 코드상 `requestSingleInstanceLock`은 `app.setLoginItemSettings` 호출과 무관하게, 어떤 방식으로든 두 번째 실행이 들어오면 막으므로 P7.2 완료 여부와 상관없이 독립적으로 구현·검증 가능하다. 따라서 deps는 비워졌다.

## 수행 순서에서의 위치

전체 위젯 인프라(P0)와 개별 화면 기능(P1~P6) 완료 후, 위젯 운영 기능(P7) 내에서 실행된 작업. 실제로는 P7.2(시작프로그램 자동 실행)의 리뷰 단계에서 critical-reviewer가 지적한 위험으로 급히 등록되었으나, 코드상 P7.2와 독립적이므로 리뷰 완료 후 바로 구현 가능했다.

이 작업 완료로 "사용자가 실수로 앱을 두 번 실행해도 데이터 파일 경합이 발생하지 않는" 상태가 보장된다. P8(패키징/배포)과 P8.2(설치본 테스트)는 이 작업이 이미 구현된 상태에서 진행된다.

## done_when을 확인하는 방법

백로그의 done_when:
> app.requestSingleInstanceLock()으로 두 번째 인스턴스 실행을 막고, second-instance 이벤트에서 기존 창을 show+focus한다. Playwright로 두 번째 _electron.launch()가 실패하거나 즉시 종료됨을 확인, 기존 창이 포커스되는지 확인.

**실제 확인 절차** (이미 수행됨):

1. **코드 구현 검증**:
   - `electron/main.js` 최상위에 `app.requestSingleInstanceLock()` 호출 확인
   - lock 획득 실패 시 `app.quit()` 및 `return` 분기 확인
   - `app.on('second-instance')` 리스너 등록 확인: `mainWindow.restore()` (최소화 상태 복원), `mainWindow.show()`, `mainWindow.focus()` 호출 확인
   - `isDestroyed()` 가드로 창 파괴 시 예외 방지

2. **Playwright 자동 검증** (완료):
   - `npm run dev`로 개발 서버 실행
   - 두 번째 `_electron.launch()` 시도: 즉시 실패 (락 미획득으로 앱 프로세스가 곧바로 종료)
   - 첫 번째 인스턴스를 숨김/최소화 상태로 두고 두 번째 시도: 
     - 두 번째 프로세스가 종료 코드 0으로 정상 종료됨을 확인 (`child_process.spawn`으로 직접 확인)
     - 첫 번째 인스턴스의 창이 visible/unminimized/focused 상태로 전환됨을 확인

3. **데이터 무결성 검증** (완료):
   - `data.json` 및 `window-state.json`의 수정 타임스탐프를 두 인스턴스 실행 전후로 비교
   - 두 번째 인스턴스 시도 후에도 파일 mtime이 전혀 변하지 않음을 확인 (두 번째 프로세스가 파일을 건드리지 않음)

4. **환경별 추가 검증** (P8.2 단계에서 수행 예정):
   - 패키징된 `.exe` 설치본에서 바탕화면 바로가기 또는 시작메뉴에서 2회 연속 실행
   - 두 번째 실행이 조용히 무시되고 기존 창이 활성화되는지 확인

## 확인 필요

없음. 

기존 문서의 "확인 필요" 항목 4개:

1. **P7.2의 상태** — 해결됨. P7.2는 "배포 검증 대기(blocked)" 상태지만, P7.6은 P7.2의 코드 구현(이미 완료)과 무관하게 독립적으로 검증 가능. critical-reviewer가 명확히 지적했고, deps에서 제거 완료.

2. **`second-instance` 이벤트 인자** — 해결됨. 이 위젯은 command-line 인자가 필요 없으므로 단순히 "기존 창을 보여주기"만 구현. 현재 요구사항에 충분.

3. **최소화 상태 복현** — 해결됨. 구현에 `mainWindow.restore()` 호출을 명시적으로 추가. Playwright 검증에서 최소화 상태에서 정상 복원됨을 확인.

4. **테스트 타이밍** — 해결됨. `requestSingleInstanceLock`은 모듈 최상위(app.whenReady() 이전)에 호출되므로 어떤 시점의 두 번째 실행이 들어와도 락을 먼저 확인. 테스트에서도 이를 검증 완료.
