# P7 — 위젯 운영 동작 (B5)

## 목적

애플리케이션이 트레이에서 상주하며 Windows 시작 시 자동으로 실행되고, 데이터의 안전을 위해 주기적으로 백업되도록 하는 운영 수준의 동작들을 구현한다. 이는 단순한 기능 개발이 아닌, 사용자가 실제로 위젯을 매일 사용할 때 안정성 있게 동작하는지를 검증하는 단계다.

## 쉬운 설명

Windows 작업 표시줄 아래 시스템 트레이에 아이콘이 늘 떠 있고, 컴퓨터를 켜면 자동으로 앱이 실행되게 하며, 혹시 데이터가 손상되거나 사용자가 실수로 삭제했을 때를 대비해 매일 자동으로 데이터를 백업해두도록 한다. 또한 윈도우 창을 드래그로 리사이즈하거나 이동할 수 있게 하고, 닫았을 때의 위치를 기억했다가 다시 열 때 그 위치에 나타나도록 한다.

## 필요한 입력

- P0: 기본 Electron 앱 구조
- work-widget-requirements.md의 B5 섹션: 트레이 아이콘, 시작프로그램 자동 등록, 자동 백업, 창 상태 저장에 대한 상세 요구사항

## 결과물

- `electron/main.js` — 트레이 아이콘 로드, 시작프로그램 등록 함수 호출, 창 상태 복원
- `electron/autoLaunch.js` — 시작프로그램 등록 로직 (최초 1회만, 플래그 파일 기반)
- `electron/windowState.js` — 창 위치/크기 저장 및 복원
- `electron/dataStore.js` — 데이터 백업 로직 (매일 자동)
- `electron/assets/tray-icon.png`, `tray-icon@2x.png` — 트레이용 실제 아이콘 파일
- `scripts/gen-tray-icon.js` — Pure Node(zlib+수동 CRC32)로 PNG 생성하는 스크립트

## 선행 작업

P0 (기본 Electron 앱 뼈대)

## 수행 순서에서의 위치

전체 기능 개발(P1~P10)이 완료된 후 배포 직전에 P8(배포 설정)과 함께 최종 점검되는 단계다. P7의 하위 항목들(P7.1~P7.6)은 다음 순서로 진행되었다:
1. P7.1 — 실제 트레이 아이콘 파일 생성 및 로드
2. P7.3 — 데이터 백업 로직 (안전장치가 필요한 단계)
3. P7.4 — 창 리사이즈/이동 검증 (최소 폭 정책 확정)
4. P7.5 — 창 위치/크기 저장 및 복원
5. P7.2 — 시작프로그램 자동 등록 (실제 설치본 환경에서 검증)
6. P7.6 — 단일 인스턴스 락 (중복 실행 방지)

이제 모든 하위 항목이 완료되었으므로 P7 전체도 done이다.

## done_when을 확인하는 방법

모든 하위 항목(P7.1, P7.2, P7.3, P7.4, P7.5, P7.6)이 done 상태임을 확인한다:

1. `node scripts/backlog/cli.js list --parent=P7` 실행 후 모든 자식 task의 status="done" 확인
2. npm run dev로 앱을 실행했을 때:
   - 트레이에 실제 아이콘(청록색 원+체크마크)이 보이는가?
   - 트레이 아이콘 클릭으로 창이 토글되는가?
   - 창을 드래그로 리사이즈/이동할 수 있는가?
   - 창을 닫고 다시 열 때 이전 위치에 표시되는가?
3. npm run dist로 설치본을 생성하고 실제 설치한 후:
   - Windows 로그아웃 → 재로그인 시 앱이 자동으로 실행되는가?
   - 설치본의 exe 아이콘이 올바르게 표시되는가?
   - 제거 목록에 올바른 앱 이름과 아이콘이 보이는가?

최종 검증 완료: 2026-09-25 사용자가 Windows 개발자 모드를 활성화한 후, 실제 설치본 환경에서 위의 모든 항목을 확인했다.
