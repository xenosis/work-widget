# P8.1 — electron-builder 설정 다듬기

## 목적

Windows 설치 파일의 메타데이터(앱 이름, 게시자, 아이콘)를 정확히 설정하고, 외부 라이브러리 없이 순수 Node.js로 다중 해상도 앱 아이콘을 생성하여, 사용자가 설치 후 윈도우 프로그램 목록, 시작 메뉴, 바로가기 등에서 올바른 앱 정보와 아이콘을 볼 수 있도록 한다.

## 쉬운 설명

Windows에서 앱을 설치하면 "프로그램 추가/제거" 목록, 시작 메뉴, 바탕화면 바로가기에 앱의 아이콘과 이름이 표시된다. P8.1은 이 모든 곳에 나타나는 앱 정보를 정확하게 설정하는 작업이다. 트레이 아이콘과 같은 디자인(청록 원 + 흰 체크마크)을 electron-builder가 읽을 수 있는 Windows 아이콘 파일(.ico)로 변환해서 저장한다.

## 필요한 입력

- `scripts/lib/pngIcon.js` (P7.1에서 만든 순수 Node 로직으로 PNG를 생성)
- `package.json`의 `build` 섹션 수정 권한
- Git 저장소의 author 정보 (`sewoong`)
- electron-builder 설정 지식
- Windows 개발자 모드 또는 관리자 권한 (심볼릭 링크 생성 가능 환경)

## 결과물

- `electron/assets/app-icon.ico`: 16x16, 32x32, 48x48, 256x256 네 해상도를 PNG-in-ICO 방식으로 묶은 아이콘 파일 (트레이 아이콘과 동일한 청록 원 + 흰 체크마크 디자인)
- `scripts/gen-app-icon.js`: 위 .ico 파일을 생성하는 Node 스크립트 (`node scripts/gen-app-icon.js` 실행으로 파일 생성)
- `package.json` 업데이트:
  - `build.appId`: `app.workwidget.desktop` (이전의 플레이스홀더 `com.example.workwidget`에서 확정)
  - `build.author`: `sewoong` (NSIS 설치 파일과 "프로그램 추가/제거"에 표시되는 게시자 정보)
  - `build.executableName`: `work-widget` (exe 파일명과 표시 이름 분리, P7.2 검증 중 발견된 레지스트리 등록 버그 해결)
  - `build.win.icon`: `electron/assets/app-icon.ico`
  - `build.files`: 제외 항목에 `!electron/**/*.test.js`, `!electron/assets/app-icon.ico` 추가

## 수행 순서에서의 위치

P8(패키징/배포)의 첫 번째 하위 작업이다. P8.1이 완료되어야 P8.2(로컬 배포 빌드 테스트)에서 실제 설치본의 아이콘과 메타데이터를 검증할 수 있다. P7.2(시작프로그램 자동 등록)가 동시에 진행되었으며, P7.2 검증 중 exe 파일명 문제(productName 공백)가 발견되어 이 작업에서 executableName 설정으로 해결했다.

## done_when을 확인하는 방법

**최종 검증 완료 (2026-09-25)**

사용자가 Windows 개발자 모드를 활성화한 후, 다음과 같이 검증했다:

1. **electron-builder 빌드 성공**:
   - `electron-builder --dir --win` 오류 없이 실행 완료
   - 생성된 `work-widget.exe` 파일 확인

2. **아이콘 반영 확인**:
   - PowerShell의 `System.Drawing.Icon.ExtractAssociatedIcon` 명령으로 exe에서 직접 아이콘 추출
   - 추출된 이미지가 우리가 만든 청록 원 + 흰 체크마크 아이콘으로 정확히 바뀌었음을 확인
   - 이전의 Electron 기본 아이콘(파란색 사각형)이 아닌 올바른 아이콘임을 시각적으로 검증

3. **메타데이터 검증**:
   - PowerShell의 `[System.Diagnostics.FileVersionInfo]::GetVersionInfo()`로 exe의 파일 정보 조회
   - `ProductName='업무 위젯'` 확인
   - `CompanyName='sewoong'` 확인
   - `FileVersion='0.1.0'` 확인
   - 모두 의도한 값과 정확히 일치

4. **버그 발견 및 해결**:
   - **발견된 버그**: 원래 `productName='업무 위젯'`(공백 포함)이 exe 파일명으로도 그대로 사용되어 Windows 레지스트리 Run 키에 경로가 잘려 등록되는 문제 (P7.2 검증 과정에서 발견)
   - **해결**: `package.json`의 `build.executableName='work-widget'`을 추가해 exe 파일명과 표시 이름(productName)을 분리
   - **재검증**: 수정 후 다시 빌드한 exe에서 아이콘과 메타데이터가 그대로 정상임을 재확인

5. **빌드 산출물 정리**:
   - 검증 후 생성된 `release/` 디렉토리 삭제 (다음 세션에서 stale 산출물로 오판될 위험 방지)
