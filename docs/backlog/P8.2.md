# P8.2 — 로컬 배포 빌드 테스트

## 목적

`npm run dist`로 생성한 실제 배포 설치본(.exe 인스톨러)을 설치하고 실행해서, P8.1(메타데이터와 아이콘), P7.1(트레이 아이콘), P7.2(자동 실행), P7.5(창 위치/크기 복원), 그리고 기본 CRUD 동작이 실제 설치 환경에서 모두 정상 작동하는지 최종 검증한다.

## 쉬운 설명

개발 중에는 `npm run dev`로 테스트하지만, 실제 사용자에게 전달할 설치본은 다르다. 설치본이 진정으로 설치되는 환경(진짜 Windows 로그인, 시작메뉴, 제거 목록 등)에서 제대로 작동하는지 마지막으로 확인한다. P7과 P8.1의 여러 기능이 "설치 후 실제로" 작동하는지도 한 번에 확인한다.

## 필요한 입력

- P8.1(electron-builder 설정 다듬기) 완료 또는 blocked 상태 — 앱 아이콘, 메타데이터(appId, author, productName)가 `package.json`에 설정되어 있고, `electron/assets/app-icon.ico`가 존재
- `npm run dist`가 성공적으로 실행될 수 있는 환경 (또는 P8.1의 Windows 심볼릭 링크 권한 문제가 해결된 환경)
- 실제 로그아웃/재로그인을 할 수 있는 Windows 환경 (가상 머신이면 재로그인이 어려울 수 있음)
- P7.1, P7.2, P7.5의 코드 구현 완료

## 결과물

이 작업은 "검증"이므로 새로 만들어지는 코드/파일은 없다. 다만:

- `npm run dist` 실행 후 생성되는 설치 파일(`.exe`)과 설치 후 생성되는 파일들:
  - `Program Files/업무 위젯/` (또는 사용자 지정 경로): 실제 설치된 앱 파일들
  - `AppData/Local/work-widget/` (userData 폴더):
    - `data.json` (첫 실행 시 초기화)
    - `window-state.json` (P7.5에서 창 위치/크기 저장)
    - `auto-launch-registered.flag` (P7.2에서 자동 실행 등록 확인용)
    - `backups/data-YYYY-MM-DD.json` (자동 백업본)
- 검증 결과를 backlog.json의 P8.2 log 항목에 기록

## 선행 작업

- P8.1(electron-builder 설정 다듬기): deps에 명시됨. 메타데이터와 아이콘이 설정되어야 `npm run dist`가 올바르게 진행됨.

## 수행 순서에서의 위치

P8(패키징/배포)의 마지막 단계이자, 전체 위젯 개발의 최종 검증 단계다. P8.2가 완료되면 "개발 완료" 판정이 가능해진다. 또한 이 작업은 다음 세 작업의 "설치본 환경에서의 최종 검증"을 일괄 담당한다:
- P7.1(트레이 아이콘): 설치본의 트레이에 아이콘이 표시되는지 확인
- P7.2(자동 실행): 로그인 시 자동 실행되는지, API 설정이 올바른지 확인
- P7.5(창 위치/크기 복원): 종료 후 재실행 시 이전 상태가 복원되는지 확인

P7.1과 P7.5는 이미 `done` 상태이지만, P7.2는 현재 `blocked`(재로그인 환경 대기)이므로, P8.2 완료 후 세 작업 모두 진정한 "설치 환경 검증 완료" 상태가 된다.

## done_when을 확인하는 방법

**조건**: Developer Mode 또는 관리자 권한이 있는 환경에서 electron-builder가 오류 없이 .exe를 생성할 수 있어야 한다 (P8.1의 Windows 심볼릭 링크 권한 문제 해결).

### 필수 검증 항목 (5가지):

#### (1) 설치된 exe/바로가기/시작메뉴/제거 목록의 아이콘과 메타데이터 (P8.1 관련)

```
설치 후 확인:
- exe 파일의 아이콘: 트레이 아이콘과 동일한 청록 원 + 흰 체크마크인가?
- 바탕화면 바로가기: 아이콘이 올바르게 표시되는가?
- 시작메뉴: 아이콘이 올바르게 표시되는가?
- 프로그램 추가/제거 목록: 
  - 표시 이름이 "업무 위젯"인가?
  - 게시자가 "sewoong"인가?
  - 아이콘이 올바르게 표시되는가?
```

#### (2) 트레이 아이콘 표시 (P7.1 관련)

```
앱 실행 직후 Windows 시스템 트레이(우측 하단 알림 영역) 확인:
- 청록색 원 + 체크마크 아이콘이 보이는가?
- 아이콘 클릭했을 때 창이 보여지거나 숨겨지는가? (토글 동작)
- 우클릭 메뉴가 정상 작동하는가?
```

#### (3) 자동 실행 및 설정 (P7.2 관련)

```
로그아웃 후 같은 사용자로 재로그인:
- 위젯이 바탕화면/시작메뉴 수동 실행 없이 자동으로 떠있는가?

Windows 작업관리자에서 확인:
- "시작" 탭에서 "업무 위젯"이 "활성" 상태인가?

Windows 설정에서 확인:
- 설정 > 앱 > 시작 > "업무 위젯"의 토글이 ON인가?

Electron DevTools(개발 빌드인 경우) 또는 로그로 확인:
- app.getLoginItemSettings().openAtLogin === true 인가?
- 등록된 path가 실제 설치 exe 경로(%ProgramFiles%/업무 위젯/...)와 일치하는가?

수동 해제 후 유지 확인:
- Windows 설정에서 토글을 OFF
- 앱 재실행
- 설정에서 여전히 OFF인가? (앱이 다시 켜지 않았는가?)
```

#### (4) 창 위치/크기 복원 (P7.5 관련)

```
첫 설치 후 첫 실행:
- 기본 크기(420x640)로 표시되는가?
- 위치가 화면 안에 있는가?

창 상태 변경 후 복원:
- 창을 다른 위치로 옮기고 다른 크기로 조정
- X로 닫음 (트레이로 숨김)
- 트레이 아이콘 클릭해서 다시 띄움
- 이전 위치/크기가 정확히 복원되는가?

외장 모니터 분리/연결 후 (선택):
- 창 위치가 화면 밖으로 나갔으면 기본값으로 폴백하는가?
```

#### (5) 기본 CRUD 동작 (기본 기능 검증)

```
프로젝트 화면:
- 새 프로젝트 추가/수정/삭제 가능한가?
- 프로젝트 상태(진행중/완료/보류) 변경 가능한가?

할일 화면:
- 새 할일 추가 가능한가?
- 할일 완료 체크/체크 해제 가능한가?
- 마감일, 우선순위, 태그 설정 가능한가?
- 할일 삭제 가능한가?

메모 화면:
- 새 메모 추가 가능한가?
- 메모 제목/내용 편집 가능한가?
- 메모 삭제 가능한가?

일정 화면:
- 새 일정(일회성/반복) 추가 가능한가?
- 일정 수정/삭제 가능한가?
- 월간/주간 뷰 전환 가능한가?

대시보드:
- 오늘/이번주/나중 할일이 올바르게 그룹핑되는가?
- 프로젝트 진행률이 표시되는가?
```

### 최종 확인

```
데이터 저장:
- AppData 폴더의 data.json에 위의 변경사항들이 저장되어 있는가?

백업:
- AppData/Local/work-widget/backups/ 에 오늘 날짜 백업 파일이 생성되어 있는가?

에러 없음:
- Windows 이벤트 뷰어에 에러가 없는가?
- 앱 실행 중 예기치 않은 종료나 오류 메시지가 없는가?
```

## 확인 필요

1. **로그아웃/재로그인의 현실성**: 실제 테스트 환경에서 "로그아웃 후 재로그인"을 완전히 재현할 수 있는가? 가상 머신 환경이라면 재로그인이 불가능할 수 있으므로, 이 경우 대안 검증 방법이 필요한가? (예: `setLoginItemSettings` API만 확인하고 실제 재로그인은 생략)

2. **외장 모니터 지연**: P7.5의 알려진 제약인 "로그인 직후 외장 모니터가 아직 인식되지 않은 상태에서 창 위치가 폴백될 수 있다"는 사항이 실제로 발생하는가? Windows가 모니터를 인식하는 데 걸리는 시간이 예측 가능한가?

3. **기존 데이터와의 충돌**: 개발 중 생성한 `data.json`과 백업이 `%APPDATA%/work-widget/` 에 이미 남아있을 수 있다. 깨끗한 설치 검증을 위해 이전 데이터를 먼저 지울 것인가?

4. **DevTools 접근**: 실제 배포 설치본에서 DevTools(F12)를 열어서 console을 확인하기 위해 필요한 조치가 있는가? (배포 모드에서는 기본적으로 disabled)

5. **P8.1 환경 제약**: P8.1이 현재 환경의 Windows 심볼릭 링크 권한 부족으로 blocked인데, P8.2를 시작하기 전에 이 권한 문제를 먼저 해결해야 하는가? 아니면 P8.2는 "권한이 있는 환경에서 재시도할 때의 검증 절차"로 별도 기록할 것인가?
