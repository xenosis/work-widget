# P9 — 비주얼 디자인 적용 (다크 글래스)

## 목적

승인된 Claude Design 캔버스의 다크 글래스 디자인 목업을 실제 5개 화면(대시보드/프로젝트/할일전체/메모/일정)과 사이드바에 적용한다. 기존 기능 로직은 그대로 유지하고 시각 레이어(색상, 카드 스타일, 아이콘)만 교체한다.

## 쉬운 설명

지금까지 만든 앱의 화면들이 기본 스타일(흰색 배경, 단순한 버튼)로 되어 있다. 이 작업에서는 UI/UX 디자이너가 만든 목업(다크 배경, 글래스 효과 카드, 시안 포인트 컬러)을 CSS와 컴포넌트 코드로 실제 구현해서, 모든 화면이 목업처럼 보이도록 만든다.

## 필요한 입력

- Claude Design 승인 목업: https://claude.ai/artifact/QcYrpj1rKyj947SLgAj9tx (다크 글래스 디자인 토큰, 컬러 팔레트, 각 화면별 UI)
- 현재 src/index.css (기존 기본 스타일)
- 5개 화면의 JSX 파일들 (src/screens/*.jsx) 및 컴포넌트들
- 사이드바 컴포넌트 (Sidebar.jsx)

## 결과물

- src/index.css 전체 재작성 (다크 글래스 디자인 토큰: oklch 색상, box-shadow, backdrop-filter 등)
- src/components/Sidebar.jsx 업데이트 (아이콘 렌더링, 활성 상태 pill 스타일)
- src/components/icons.jsx 신규 (5개 화면용 stroke 아이콘)
- Dashboard.jsx, Projects.jsx, Todos.jsx, Memos.jsx, Schedule.jsx 클래스명 적용
- 모든 화면이 목업과 시각적으로 일치

## 선행 작업

없음 (UI/UX 계층이므로 기능과 독립적)

## 수행 순서에서의 위치

P1~P8의 핵심 기능이 구현된 후에 진행하는 시각 개선 작업. 현재 P1.1, P1.3, P2.1, P4.1 등 여러 화면과 기능이 완료되어 있어서 이 시점에 디자인 적용이 가능. P9 완료 후 P10(공통 훅 추출)과 병렬 진행 가능하며, 모든 화면의 디자인이 통일되면 P0~P8 기능 개발과의 조화로운 완성도를 갖춘다.

## done_when을 확인하는 방법

1. npm run dev 실행 시 Electron 앱 기동
2. 5개 화면(대시보드/프로젝트/할일전체/메모/일정)과 사이드바를 PrintWindow API로 스크린샷 캡처
3. 각 스크린샷을 Claude Design 목록 원본(https://claude.ai/artifact/QcYrpj1rKyj947SLgAj9tx)과 시각적 비교:
   - 배경색이 다크(검은색 또는 매우 어두운 회색)인가
   - 카드/항목들이 글래스 효과(반투명 흰색 배경 + 가려짐 효과)를 가지는가
   - 사이드바에 아이콘이 보이고, 활성 메뉴가 pill 모양의 배경을 가지는가
   - 전체적으로 일치하는가
4. npm run lint 통과
5. npm run build 통과
6. npm test 통과 (기존 35개 테스트)
7. 콘솔에 에러 없음

## 확인 필요

- 목록 아이템(todos, memos 등)의 완료 표시(취소선) 스타일이 다크 배경에서 잘 보이는지 확인 필요
- 다크 모드에서 텍스트 대비도(contrast ratio) 접근성 기준(WCAG AA) 충족 여부 — 요구사항에 명시 없음
- 프로젝트/할일/메모/일정 "나중에" 그룹의 라벨 텍스트가 목업에서 어떻게 스타일링되어 있는지 확인 필요
- 반복 일정 표시, priority chip 등 세부 컴포넌트의 디자인 톤이 목록에 명시되어 있는지 확인
